# 提交代码

在主会话中处理 `$ARGUMENTS`。`/commit` 与中文“提交／提交代码”使用同一流程；用户直接下达这些口令，默认表示检查当前仓库改动、执行必要验证、提交并推送到当前工作分支的对应远端，无需另问是否 push。用户明确限定文件范围或说“只提交、不推送”时，以本次限定为准。

讨论、引用、示例、历史档案、到期提醒正文，以及创建或测试本 Skill，都不是新的提交授权；定时任务不自动继承本入口的提交与 push 授权。参数只表达范围和限制，不作为任意 shell 命令执行。

## 流程

1. 核对当前仓库、分支、工作区、已有暂存区、upstream 和远端目标；读取适用的根及模块 CLAUDE.md，保留用户已有改动。不要用默认分支名或固定远端名猜测目标；有实质歧义才询问。
2. 默认纳入当前仓库已跟踪修改及经检查的非忽略新文件；先检查实际差异、暂存差异和新文件内容。不盲目添加整个目录、不强制加入忽略文件、不发布密钥、本地凭证或会话日志。显式范围与已有暂存区冲突时，先说明并确认如何处理，不擅自重置或夹带范围外内容。
3. 根据改动执行必要验证，区分运行测试、静态检查和未验证项。验证失败、发现敏感内容或权限拒绝时，停止相关提交／推送步骤并说明，不换工具绕过。
4. 默认分支上先建工作分支；不自动合并到默认分支。只暂存已审查且属于授权范围的具体文件，提交前再次核对暂存差异，发现期间出现的未知改动先检查。
5. 创建新提交，不重写已有提交。遵守当前适用的提交消息署名要求；不强制推送、不绕过 Git hooks 或签名。hook 失败先分析原因，不使用跳过参数。
6. 推送前再次核对分支和远端：已有 upstream 时使用对应远端分支，无 upstream 时仅在目标明确后建立跟踪。远端冲突时停止，不强推、不擅自解决冲突或改写历史。
7. 无新改动但有待推送提交时，检查提交范围和内容后仅推送；无改动也无待推送提交时说明无需操作。明确“只提交、不推送”时不得执行上述推送。
8. 报告提交 ID、实际推送目标和结果、剩余改动、验证成功／失败／未运行项；不把提交成功当作推送成功。按根规则维护实施记忆；提交后的收尾若产生新记忆改动须如实报告，不为清空工作区自动循环提交。
