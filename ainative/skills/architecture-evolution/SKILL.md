# 架构演进与共性沉淀

帮助维护者判断工程该怎样随需求成长。以真实代码、调用链和变更原因解释边界，交付能逐步验证的调整；不以增加层数、目录或设计模式作为进步。只要求评估时不修改业务代码；明确要求实施时在既有授权范围内完成，不增加逐步骤批准。

## 必读规范

执行本工作流前，**必须读取并遵守**以下两份规范：

- [05《代码阅读设计及编码规范》](../../docs/05-代码阅读设计及编码规范.md)
- [06《架构设计原则和工程结构规范》](../../docs/06-架构设计原则和工程结构规范.md)

两份文档是对应规范的唯一正文。本 Skill 及配套资料只维护工作步骤和项目特有执行约定，不复制、改写或另设代码、注释、工程结构及架构原则。已读取且确认未变化的内容可复用；文档不可读取时先核实当前入口，不依据旧摘要声称合规。

项目协作、资料归属、验证命令与工具接入要求见 [统一入口](../../AGENTS.md)。

## 架构治理执行流程

本 Skill 负责执行流程，设计判断统一引用上述规范。按当前任务复用已核实事实，逐步交付可审阅的结果：

| 阶段 | 操作与结果 |
| --- | --- |
| S1 目标与基线 | 核实任务来源、版本、工作区差异、授权范围和保留行为。 |
| S2 调查事实 | 沿真实调用链定位问题，核对消费者与现有实现，记录未知项。 |
| S3 分析影响 | 记录契约和行为差异、实际消费者、验证范围及交付深度。 |
| S4 形成方案 | 比较保留现状与调整方案，拆成可独立 review 的切片，说明兼容和回退安排。 |
| S5 范围内实施 | 迁移真实消费者，核实动态注册、配置、历史数据和外部兼容需求后清理旧入口。 |
| S6 验证与同步 | 按实际影响执行检查，失败后修正相关范围，并调用 architecture-maintenance 同步资料。 |
| S7 交付与归档 | 交付 diff、证据、阅读入口及剩余限制，在已授权的 Issue／PR 记录结果。 |

检查分档按任务选择：C1 为本次变更检查，C2 为只读专题调查，C3 为已授权专项整改。认知交付采用 L0（无行为变化）、L1（局部行为）、L2（跨模块契约或状态变化）、L3（全局或关键边界变化）；只影响说明深度，不自动扩大测试或授权。

交付回答四问：保护了什么、变化落在哪里、验证如何选择、下次从哪里修改；第五问记录值得沉淀的规则候选或明确“无”。候选须经明确确认后才成为生效规则。抽象退出记录 active → deprecated → migrating → retired，退役前核实所有受支持消费者及兼容承诺。

只读任务执行 S1–S4 和 S7 的报告部分，S6 仅检查实际产出的资料；已有实施授权则继续完成 S5–S7。失败回到相关步骤，超出范围时单独处理新的决策，不逐步重复批准。

## 先建立全局位置，再判断局部变化

- 阅读统一协作入口、当前架构说明和本次目标，核对实际源码及工作区差异。区分文档目标、代码现状和已经验证的行为。
- 画清理解本次问题所需的系统边界：用户入口、业务编排、领域规则、平台适配、外部系统。列出各自的职责、输入输出、状态所有者及允许依赖；沿至少一条相关真实调用链读到最终副作用和结果返回。
- 对照全仓维护代码清单寻找同类职责和受影响消费者，再深入相关模块。报告实际阅读范围和未覆盖项；只读了局部不能称完成全仓评估。生成目录、第三方依赖和运行数据不作为自有架构扫描对象。
- 用搜索定位相似职责、业务规则和调用方式，阅读真实消费者及相关测试；必要时核对变更历史，区分重复业务知识、重复技术机制和偶然相似的代码外形。为复用候选记录共同不变量、变化部分，以及权限、幂等、错误、重试、取消、并发和资源所有权差异。
- 检查接口、类型、事件、注入和持久化涉及的调用方与被调用方，对照 06 记录实际耦合证据。
- 对照 06 核实依赖来源、类型引用和间接协作，输出与本次问题有关的证据及影响位置。

## 判断值得调整的边界

按 [06 的架构原则](../../docs/06-架构设计原则和工程结构规范.md#2-十二条架构原则) 调查候选问题，记录变化原因、实际影响、消费者及继续保留现状的成本。缺少证据时标为未知，不仅凭目录名、代码外形或提交数量下结论。

区分职责问题、接口问题与文件组织问题，比较“不调整”和调整方案。没有治理收益时记录依据并结束调查；有收益时说明最小切片、前置和重新评估的触发条件。

## 选择可沉淀的抽象

Core、Logic、Bridge、View 四层源码迁移已完成，见 [四层设计](https://github.com/nan023062/cbim/blob/7dcff4142e09fdac1a670438bd3081d6c0341f23/design/four-layer-architecture.md)。src/core 仅持有独立技术机制；任务、知识、预算、运行和存储归 Logic，通信与可信宿主归 Bridge，页面及交互归 View。旧目录已退出，但原共享事务与依赖密集模块仍需按真实变化点渐进治理，不能把目录迁移等同于全部语义解耦。

前后端使用相同契约的机制可共享 Core；语言相同不证明语义相同，必须核对排序、空值、错误和生命周期后再统一。业务/视图策略保持原归属；当前视图共享控件归 framework-ui，不引用业务实现。Core 不依赖 Logic/Bridge/View 或旧 backend/frontend；平台专用实现有独立入口。Bridge 只负责通信，Logic 不依赖 Bridge；View-new 仅依赖自身模块、framework-ui 与 Bridge 契约。每项能力有自己的公开入口、实例状态和资源所有者，不建立万能容器。

本项目的算法入口为 `core/utility`，现有类别包括 JSON、字符串、字节和异步协调；先核对对应源码契约，再按 05、06 决定本次组织调整。迁入序列化／摘要算法时固定现有字节与错误语义，分别验证各调用方使用的 canonical 排序；通用入口和 Node 入口的实际许可由项目依赖检查器核对。

传入流的消费机制与建立连接分开：utility 可持有 reader 的字节上限、取消和释放，URL、凭据、时长与物理退出屏障留在消费者。不得把不合作的底层 cancel 当作必须无限等待的清理。严格 JSON 只报告语法/重复键事实，业务错误、危险字段与资源限制由适配层解释；不能把普通协议自动升级为更严格解析。

已有机制入口包括 `orderJsonValue`、`InFlightOperations`、`LineFramer`。排序迁移先固定比较器、undefined/数字键/数组规则与历史字节，不能用“确定性”掩盖 locale 差异；在途集合只等待调用时快照，不能取代停止接单、动态排空或物理退出；分帧保留字符/字节、CR、空白及 EOF 差异，协议和限额通过原适配组合，不预建通用 RPC 框架。

验证边界引用 [06 的独立验证原则](../../docs/06-架构设计原则和工程结构规范.md#p09模块边界必须支持独立验证)。迁移时同步 `tests/modules.json` 及依赖登记，运行 `pnpm check:test-modules`，并记录人工 review 与实际执行分别核实的范围。

前端订阅机制已有 events.ts 的 SubscriptionSet，只抽取实例监听集合；业务状态、首末订阅副作用、轮询、代次和资源销毁不并入公共类。相似 subscribe 方法不证明完整生命周期相同，迁移须保留去重、实时遍历、异常和退订身份语义，不扩成全局事件总线或统一状态管理器。

前端异步代次已有 async.ts 的 AsyncGeneration，只复用实例标记的捕获、推进和判断。先区分每请求推进与生命周期推进；保留各消费者的响应校验及清理时机，不把迟到隔离扩成请求管理器。按键代次、持久或业务序号、Hook 生命周期须另核实语义，不能机械迁移。

共性与抽象的设计判断引用 [06 的共性抽象原则](../../docs/06-架构设计原则和工程结构规范.md#p06共性抽象必须有业务语义依据)。针对候选记录真实消费者、合法差异、兼容影响和比较结论；使用真实扩展场景验证方案，不在工作流中另列设计模式规则。

## 选择最小有效的演进并验证

对关键候选比较保留现状与有依据的调整，写清收益、代价和暂不解决的事项，不凑满方案数量。

- 依据 06 比较候选方案，记录适用条款、源码证据、预期影响及尚未解决的差异。
- 将方案拆成能保持系统工作的切片：建立行为基线、引入边界、迁移一个真实消费者、验证其余受影响入口、清除不再使用的旧路径。每片写明可观察结果和回退条件；避免边改边重写全项目。
- 为本次受影响的消费者列出具体验证场景、输入、预期结果与执行入口，将结果关联到方案中的变化。
- 分别说明重构与新增业务行为。旧调用、注册和动态入口均核实迁移后再删除旧实现，同步导入和构建入口；不把行为变化藏进抽象整理。

## 实施与维护者交接

实施源码调整时遵循 [architecture-maintenance](../architecture-maintenance/SKILL.md)，同步注释、依赖规则、架构文档和受影响测试。日常只运行当前切片及实际受影响消费者的单元／契约测试，静态检查按边界变化选择；不因抽取公共能力或广泛重构自动跑全量回归、打包及全套桌面验证，全量留给后续自动化阶段。通过后收尾，仅在新变化或失败暴露相关影响时扩展验证；静态无环不等于运行时已解耦。

交付以维护者能判断的内容为主：

1. 当前问题、源码或调用证据，以及继续维持现状的成本。
2. 调整前后的职责、依赖和状态归属；哪部分成为受保护的稳定能力，业务变化被限制到哪里，对应 06 的哪些原则；明确保持不变的外部行为和已授权改变的行为。
3. 本次最小切片、实际验证结果、未覆盖边界及后续重新评估的具体触发条件。
4. 一个真实需求例子：调整后该改哪里、为什么只需要改这些位置，以及维护者应先读哪些入口。

按 06 的模块设计标准更新相关契约或架构说明，交付时链接本次差异；记录尚待验证的假设与下一次复核条件。

重要取舍写入项目现有的架构或决策文档，并链接源码；没有现成位置时按需要建立简短记录。由 [architecture-maintenance](../architecture-maintenance/SKILL.md) 同步代码资料并完成认知交接，复用已经核实的材料，不重复生成平行说明。对真实业务歧义集中提问，不把例行技术选择变成审批门槛，也不声称维护者已经理解或接受。

前端图布局通过 utility/graphs.ts 的 rankDirectedGraph 组合；只沉淀 ID/边与层级，业务边筛选、错误文案、坐标和路径保留原适配。分层与无环判断是不同契约，暂保留各自实现；共享须核实语义，不开放业务互引；拓扑单元与任务布局消费者分别验证。

前端本地记录存储已有 utility/storage.ts 的 JsonRecordStorage；仅复用注入式有界 JSON 读写。迁移核对空串/缺失规则、UTF-8 上限、序列化字节、写失败前后的内存状态；schema、条数、坏数据禁写、回执及原请求恢复保留业务控制器，不能扩成统一命令状态机。

后端 JSON 补齐优先复用 orderJsonValue，迁移显式固定比较器与 undefined 策略，业务身份与哈希字段留在原模块。调度器仅可导入 core/utility 的通用公开入口，禁止私有实现及 Node/files/web；手工拼接字符串、排序后读取属性的协议须单独核对，不直接统一。

后端字符串精确脱敏统一组合 strings.ts 的 redactLiteral；凭据来源、认证模式、事件序列化和错误屏障留在引擎。保留空凭据、大小写、非重叠及编码语义，不以字符串函数宣称覆盖所有泄露途径；独立算法与真实引擎适配分别测试。

Pi/Codex 的请求关联使用 utility/async.ts 的 PendingRequests；register/take/rejectAll 仅管理 ID、回调与计时器。协议决定超时处置：Pi 单项未知、Codex 整体失败及杀进程必须保留；发送异常、重试与物理退出不下沉，分别验证乱序/重复回包、超时及关闭。

后端无环判断组合 utility/graphs.ts 的 isDirectedAcyclic，前端分层独立实现；领域入口先核验节点/端点，再选择启用依赖与等待边并保留原错误码。公共图算法不认识任务或授权；独立拓扑测试与领域防环/重放契约分别验证，新增私有类别同步依赖清单。

模型位于 src/logic/models：纯目录/连接/选型入口与 service/index.ts 分开，纯入口不得加载服务。Bridge 仅具名转接公开纯契约。Fault 和锁实现只有 Core 一份；主 Agent 设置位于 logic/team/settings，请求预算归 logic/budget。单元、消费者契约与 SDK 容量验证分别登记。

Web 已迁入 src/logic/web：纯工具契约 index.ts 与 service/index.ts 分开；Core 网页拆为 core/web/portable、core/web/node、core/web/electron.ts。Logic 不依赖旧后端或 Electron，浏览器只由桌面宿主注入；仅 bridge/contracts/web.ts 具名导出原设置 Schema/摘要，不能扩散为服务权限。SecretCipher 归 core/io/electron.ts，平台实现不迁入业务。正文转换、HTTP、页面策略、业务适配、设置单元及真实协作契约分别登记；保留匿名兜底、默认 allow、缓存策略隔离、取消、未知失败与密钥语义。

反馈已迁入 src/logic/feedback：index.ts 拥有输入、正文和可信范围；service/index.ts 提供授权与提交，不能反向导入旧后端或模型业务。旧工具范围仅组合并兼容重导出本域 Schema，Bridge 仅具名公开配置 Schema/状态。Core Node locking.ts 持有唯一原生锁实现，旧锁出口已移除，消费者直接使用同一 Core 构造器；保留锁身份、发送前持久化、未知结果不重发、凭据和退出语义。授权单元、HTTP 单元、提交协作契约与平台/真实 Pi 集成分别登记。

资源仓库已迁入 logic/resources：纯分类/状态与 service 分开，ResourceRepositoryPaths 只注入目录边界，不依赖具体工作区 Paths 实现或 Bridge。保留仓库 CAS、只读授权、共享退役取消及未知写结果；知识包位于 logic/resources/packages，授权连接位于 resource/connections/service。

四层迁移现状：具体引擎与编排已归 Logic；execution/assembly 是具体引擎选择点，规则不能依赖 runtime 服务。继续使用已登记的细粒度公开入口，不能用聚合导出引入类型环。

有状态服务与启动迁移已落地：Logic/Application 持有唯一业务生命周期，Bridge/server 只做通信与可信宿主适配；业务不得反向依赖 IPC/Electron。附件、工作区、资源包和更新类型由 Logic 拥有。构建入口改动须核固定输出名，不能改变用户数据或原恢复语义。

## 模块单元与增量执行

测试设施的结构与归属引用 [06](../../docs/06-架构设计原则和工程结构规范.md#34-测试设施与运行资产的归属)，本节只维护增量执行操作。

日常先用 `pnpm test:incremental --list` 查看变化原因，再运行受影响模块；`pnpm test:module --module <模块>` 也复用有效回执，`--force` 强制执行。实现、契约、测试和夹具、配置或环境变化使相关记录失效；失败、中断、零用例、全跳过和执行期间变化不得记成功。结果保存在忽略的 `test-results/module-tests/`，不提交，也不替代 CI 完整回归和发布验收。

独立契约通过 `tests/modules.json` 的 `contract: {files, revision}` 明确登记；行为语义变化同步正文或版本。无独立契约时按实现闭包保守传播。动态读取的本地资源通过 `inputs` 登记，不可固定的外部状态设 `cache: false`；真实契约验证追踪实现，集成不复用缓存。执行范围以实际影响为准，不能只看源码是否修改。

生产构建保留既有的加载模块、chunk 依赖和制品暂存检查；设计依据引用 06，执行方式沿既有构建入口维护。
