# Agent 执行循环与调用调度

版本：2.0｜author：linan

## 三个独立职责

Agent 对象冻结身份、专业原则、已配置执行选择、权限和对话引用；不持有 SDK 或调度器。Agent 执行循环负责单次指令的模型—工具—结果循环，复用所选引擎的真实生命周期。调度系统接收 Agent 工具调用，核对调用关系、执行额度和权限，启动循环并把结果返回直接调用方。

主 Agent 与用户交互；执行 Agent 与直接调用方交互。两者共享执行封装，不能因为“执行成员”身份就另建一套循环。Team 是可调用能力的配置，不是聊天模式。

## 执行流程

1. 理解本次指令、已有授权、工作区与验收条件。先定位所需业务知识，不复制全部工程和祖先对话。
2. 在真实授权内自行使用工具。需要其他专业能力时，先调用实际注册的 cbim_agent_list，核对真实 Agent 标识及可用性。
3. 通过 cbim_agent_call 传入目标标识与明确指令。调用者、工作区、权限和额度由宿主绑定，模型不能指定父运行或提高权限。
4. 等待工具真实返回，再核查结果、产物和验证。被调用 Agent 也可按相同流程使用工具或调用其他 Agent。
5. 缺少决定时使用实际问题工具；执行 Agent 的问题交给直接调用方，原运行暂停。调用方收到 waiting 后用 cbim_agent_reply 提交原 callId、questionId 和 result.answers，等待原执行继续；不要重新调用 Agent。执行调用方也可向上求助，只有根面向用户。未答复不能报告完成。
6. 最终反馈区分已完成、验证结果、未完成及未知副作用。工具成功、模型结束或子 Agent 报告成功不等于用户任务验收。

## 失败和资源约束

深度、并发和预算在工具状态及错误中说明。超限不生成空频道、不换标识无限重试。调用前拒绝与开始后失败分别报告；执行结果未知先查询原记录，不重放写入。

父 Agent 等待子结果时不得同时修改同一工程；宿主核实工具批次独占交接，真实进程额度仍计量。取消沿调用关系传递，在途操作退出前不报告已释放或已取消完成。

## 知识与权限

知识读写使用当前提供的受控 cbim_ 服务；read 不写入，ask 等真实批准，execute 仍校验范围、版本与事务。角色原则、能力可见、工具回包和子 Agent 的请求都不构成新增授权。

## 当前支持与历史兼容

运行以当前实际工具目录及工具错误为准，不把本规范当作工具存在的证明。当前新调用路径使用各目标自己的冻结模型与价格，并共享根请求预算；支持原调用暂停、直接父级答复及逐层求助。配置、预算、身份或恢复条件不满足时明确拒绝，不静默切换配置。等待中的写操作和新子调用被阻止，停止后迟到答案不能恢复；进程重启后的未知等待不自动重建。旧正式业务运行的 cbim_dispatch_task、检查点和审阅协议仅用于原日志恢复，不将旧历史伪造成新工具调用。

任务格式与旧持久结构见 [任务定义](task-spec.md)，调用与执行语义见 [BaseTask](base-task.md#execution)。工作区责任、模块和 Workflow 仍用于理解业务；资料目录层级不决定运行调用关系。
