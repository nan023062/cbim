# 设计模块 DNA

## 职责与边界

本模块承载 CBIM 的概念模型、设计原则及架构约束，回答系统为什么这样划分、各概念负责什么、边界如何成立。设计工作本身是业务模块，不因其产物是文档而排除在模块 DNA 之外。

本目录不负责运行时代码实现、构建配置或会话进度。源码现状由 [源码整体 DNA](../src/CLAUDE.md) 和所属模块代码说明；阶段进度与交接存放于 `.claude/memory/`。本文件是设计模块的开发协作 DNA，不改变运行时 `.dna/module.md` 的发现机制。

## 文档分工

| 文档 | 职责 | 不应混入的内容 |
|---|---|---|
| [cbim-观点.md](cbim-观点.md) | 总体设计原则、能力/业务独立性的动机，以及脑区、模块树、图工程、Dream 的设计推导 | 把设计目标直接写成已经交付的功能 |
| [_ARCHITECTURE.md](_ARCHITECTURE.md) | agent、team、workspace、project、记忆五个核心概念的角色、归属和关系 | 具体实现、数据结构、执行时序与代码细节 |
| [architecture-summary.md](architecture-summary.md) | 架构摘要与关键约束，连接概念模型和工程划分 | 未经核对的现状程序集清单和支持能力声明 |

三份文档是同一设计模块内的不同视角，不为每份文档另建一个模块。本文只规定职责与维护边界，不复制它们的全文。

## 对外契约与协作

- 向实现模块提供一致的术语、职责划分和设计意图；实现模块负责具体类型、接口和运行行为。
- 从源码和模块 DNA 获取实现反馈，但不因当前实现有限就悄然改写目标设计。
- 出现差异时区分“设计目标”“当前实现”“待决策问题”；既不能以文档证明功能已实现，也不能以当前代码自动否定设计意图。
- 涉及跨模块契约的设计调整，说明受影响的概念和实现模块；仅编辑设计文档不表示代码已经同步迁移。
- 父子目录关系、概念归属、程序集引用、运行时调用是不同关系，不混用一张依赖描述，也不宣称未经验证的代码级无环。

## 核心设计约束

- 总纲是 Capability–Business Independence + Memory；上下文最小化是能力与业务正确分离后的结果，不是第一目标。
- 能力按加工方式组织为单个 Agent 的脑区；业务按 Workspace 模块组织。能力不写死业务归属，两者在运行时组合。
- 单 Agent 的思维层与多 Agent 的团队层分开；不能把脑区当成团队成员，也不能把本地单 Agent 描述为团队的退化形式。
- 设计上区分 Agent 的身份/经验与 Workspace 的稳定 DNA/事件档案；不要把业务模块知识与 Agent 私有经验混为一体。
- 工作区的稳定职责、契约和边界进入模块 DNA；阶段修改记录、待办和交接不堆积到稳定设计中。

## 已知文档与实现差异

- architecture-summary.md 仍列出 Contracts、CacheController、PageStore、Avalonia 等旧程序集，与当前 [cbim.sln](../src/cbim.sln) 不一致；其清单和依赖图不能用作当前源码地图。
- _ARCHITECTURE.md 的实现导航仍指向各模块 `.dna/module.md`。当前仓库的开发协作导航使用模块 CLAUDE.md；这与运行时仍采用 `.dna/module.md` 是两件事。
- Dream、脑区裂变、跨机器团队等设计描述不能替代实现验证；实际可用性由相应代码和模块 DNA 核对。
- 上述差异是维护背景，不代表本次已修订三份设计正文或已获准执行对应代码重构。

## 修改与验证入口

1. 先确定变更属于设计动机、概念边界还是工程摘要，再修改对应文档，避免三处重复维护同一段说明。
2. 术语或归属改变时，交叉检查三份文档的一致性；实现状态声明需核对 solution 和相应源码模块。
3. 核对相对链接与引用对象存在，避免链接已删除的根文档；引用源码现状时使用实际路径与符号。
4. 纯文档调整进行内容和链接检查即可，不将其称为构建、测试或功能验证通过；涉及运行行为的后续变更另行验证。
