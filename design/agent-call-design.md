# Agent 调用的核心设计

目标是让 Agent 调用像普通工具一样组合，同时保持身份、权限、资源占用与结果归属真实。需求与 UX 分别见 [产品需求](agent-tool-product-requirements.md)、[统一对话交互](agent-tool-ux-design.md)。

## 身份、循环与调度分开

Agent 对象持有身份、冻结配置与对话引用；执行循环负责一次模型／工具运行；调度负责调用关系、准入、结果路由和取消。三者通过明确契约组合，避免将配置、资源排队和引擎循环塞进一个对象。

独立职责不要求增加重复包装。已有 LoopRuntime 承担循环时继续复用；递归协调组合既有全局准入和预算服务，不再为每个根调用建立另一套资源计数。当前结构见 [执行模块](../src/logic/execution/ARCHITECTURE.md) 和 [执行装配](../src/logic/execution/assembly/ARCHITECTURE.md)。

## 一次调用的可信边界

调用者、父调用、深度、权限和额度来自宿主，模型只提供目标、指令和所需上下文引用。调用、任务、运行实例和原生会话有不同身份；用持久关联连接，不按名字、时间或最新记录猜测。

准入先核实身份、授权、引擎兼容及历史，再预留额度并记录受理，最后启动。受理前拒绝不创建空执行记录；受理后失败保留事实。未知写入先查询，显式重试是关联的新尝试。

进度、提问、答复和终态绑定同一调用。结果只返回直接调用方；工具完成不代表业务验收，主 Agent 仍负责整合。重复结果幂等，迟到答复不得覆盖已取消或终结的调用。

## 资源交接与停止

父 Agent 等待子结果时暂停模型推进。必须先核实工具与原生操作排空，才能交接冲突的工作区执行权；等待 Promise 不自动证明租约已经释放。无法可靠暂停的引擎应明确拒绝相应交互。

活动执行名额、模型请求并发与存活进程资源分别计量。共享任务预算复用根账本，每个模型请求仍走原票据；子调用不能重置预算，也不能靠忽略父进程突破物理容量。

停止立即阻止新派发并传播到所属后代。请求取消、真实退出、释放额度和费用结算是不同事实；不能提前释放占用，也不能取消无归属的兄弟调用。

## 兼容与演进

在途调用固定配置、权限、引擎和工作区；Team 的修改只影响后续获准调用。旧记录保留原事实，缺少可靠父子关系时只读展示，不伪造嵌套。

新交互必须由真实工具、宿主和引擎能力共同支持，不能只删禁用提示或改卡片文案。运行指令的唯一来源在 [assets](../assets/)，随能力接通同步维护。旧迁移切片和接入快照已转入 Git 历史，不再作为当前待办；待实施范围与进度以 [Issues](https://github.com/nan023062/cbim/issues) 为准。
