## 2. 目标边界与契约（S4）

用户追加确认三项独立封装：Agent 对象、Agent 执行循环、调度系统。Agent 对象持有冻结身份、能力配置、权限与对话引用，不重复保存日志正文；执行循环封装单次模型／工具运行和终态，不重写 SDK 已有循环；调度系统持有调用关系、准入、结果路由与取消，通过注入工厂创建循环。Agent 不导入调度实现，循环不反向加载 Application，调度不依赖旧 AutoCollaboration 实现。独立封装不等于创建无人使用的空层，须由产品真实入口消费。

保留 Core / Logic / Bridge / View。Logic 拥有调用身份、生命周期、权限与账本；Bridge 只传递契约；View 投影持久事件，不自行调度或判定完成。具体引擎通过装配注入，不能使 rules 反向依赖 engine implementation 或 Application。

Agent 工具输入至少表达目标 Agent 引用、指令、所需上下文／附件引用。调用者身份、父调用、根运行、深度、权限与额度从宿主上下文取得，模型不可伪造。使用现有 toolCallId/runId 语义建立明确关联，不造另一套全局任务 ID。旧数据缺关系时只读展示，不按时间猜测。

工具输出包含状态、摘要、产物引用、验证事实或结构化错误；成功不自动变成业务验收。进度／提问作为同调用事件传递，终态只结算一次；重复回包幂等，迟到回包不得覆盖终态。工具的记录查询与执行入口分离。

准入顺序：参数与身份核验 → 授权／引擎兼容／历史预检 → 原子额度预留 → 记录受理与调用关系 → 启动子运行。启动失败释放额度并保留准确错误；持久化结果未知先查询，不能重发。原子预留与停止竞态须在拥有额度的模块内处理。

父 Agent 等待子 Agent 时暂停模型推进；不制造自动无限轮询。执行名额与仍存活进程资源分别核实，不能通过不计父进程绕过物理容量。运行中到达预算上限停止新增动作，待在途动作排空后结算；无可靠取消能力的工具明确报告仍在执行。

权限取交集，附件与文件访问沿用既有可信边界。子 Agent 不得绕过父级审批；需要用户的审批沿调用链回到主对话，答复必须绑定原请求，不扩大其他调用授权。

### 3.2 首个可安全实施的切片

E1 先做**启动预检与失败事实的正确归属**，再让调用契约被真实入口消费，避免先提交无人使用的新框架：

1. 将引擎历史可转交性等不依赖已登记 scope 的检查移到 `beforeRun` 之前。当前 `createEngine` 依赖 `mainToolContext`，不能直接把整段引擎创建前移；需要把引擎身份／准备检查与依赖 scope 的能力装配分开，保持原冻结配置。
2. 历史超限等预检失败保留原输入与明确错误，不调用 openScope，不创建子运行日志。受理后的真实失败仍保留记录，不能通过删除日志伪装未开始。
3. 在现有真实派发受理入口记录可追溯的调用关系，并由查询入口消费；关系中包含原 toolCallId、调用者 runId、被调用运行引用和版本。先保证一层身份和重复回执，随后在 E2 扩展递归。运行实例、任务、调用尝试不得混为同一标识。

此切片解决真实已知失败、建立可靠关系基础，但不交付“成员已能递归调用”。深度／共享并发／预算的最终原子准入必须在 E2 的真实端口闭环中验证；孤立纯函数测试不是执行约束已经接通的证据。

### 3.3 E2 必须固定的技术决策

这些属于工程设计约束，不要求新增用户界面，也不逐条请求用户批准。

- **执行权交接：** 父等待子结果前停止模型推进并核实在途工具排空；有未决工具、原生操作仍可能继续或引擎无法可靠暂停时，返回工具错误，不能释放工作区独占权后放行冲突写入。需先在各引擎适配器核实可支持的暂停／恢复形态，不能假设 SDK 的等待 Promise 自动释放资源。
- **额度单位：** 活动执行名额、模型请求并发及存活进程资源分别由原所有者计量；共享任务预算绑定根调用。数值映射及默认配置应通过现有设置／迁移实现，不能把三个计数混成一个“并发”。UI 只在当前工具详情显示相应约束。
- **父子答复：** 提问事件绑定调用身份与 questionId；答复仅接受直接调用者，审批还须核对原授权范围。同一答复重复投递幂等，已取消或已终结的请求拒绝迟到答复。
- **终态与取消：** 调用者等待结果、被调用者退出、费用结算是不同事实；终态提交与结果投递需要可查询回执。取消只停止后代，不能取消同根下无归属的兄弟调用；取消尚未排空时不能提前释放占用。
- **迁移：** 不将历史 scope 名称或时间排序映射成父子关系；新协议启用前仍按旧入口读取旧记录。原生 session、用户工作区和既有结果未知记录保持不动。

### 3.5 实际加载的运行规范随实现迁移

- 完成条件分别写明：代码、专项测试、桌面、CI、人工 review、合并、发布。未执行项不宣称通过。

保护的稳定能力：原生引擎适配、文件权限、记录与恢复、预算计量。主要变化局限于调用关系和协调入口、工具投影视图。为何不沿用频道模型：频道与调用身份不一致，失败恢复会产生空任务；为何不全量重写：既有宿主约束与引擎生命周期仍需保留。下次新增执行 Agent 应改配置／能力登记，而非新增聊天模式。规则候选：无，本轮不新增通用治理规定。
