# Agent 工具调用产品需求

日期：2026-11-15。状态：用户已确认核心模型；本文定义目标行为，不代表已实施。

## 1. 产品模型

CBIM 是本地／多端 AI Native 工作流工具，不建设多人协作服务。真实工程团队协作未来通过 Git、P4、飞书等插件和连接器实现。

所有 Agent 使用同一种对话与工具执行模型：接收外部指令、调用工具、观察结果、继续判断、向调用方反馈。直接与用户交互的 Agent 称为主 Agent；被另一个 Agent 调用的 Agent 称为执行 Agent。这是调用关系，不是两种互不兼容的执行类型。

主 Agent 的输入和反馈对象是用户；执行 Agent 的输入和反馈对象是直接调用它的 Agent。执行 Agent 也可以调用其他 Agent 或普通工具。Agent 调用在调用方界面中就是普通工具调用和结果，可逐层展开执行对话，不增加频道、层级、调度中心或专用聊天模式。

Team 是可调用 Agent 的职责、能力和权限配置集合，不拥有第二套消息流，不要求用户发送前选择“团队聊天”。没有可用执行 Agent 时，主 Agent 仍能使用已授权普通工具工作。

## 2. 功能需求

| 编号 | 需求与可观察行为 |
| --- | --- |
| P01 | 用户发送消息进入主 Agent 连续对话；任务卡不取代消息、工具过程和结果。普通补充不隐式创建频道或重置目标。 |
| P02 | 调用 Agent 与调用命令、文件工具共用工具状态、展开和结果语义；主 Agent 委派后仍负责整合与验收。 |
| P03 | 任意已授权 Agent 可调用允许范围内的 Agent；输入、反馈和提问只交给直接调用方，不越级广播。 |
| P04 | 每次调用有稳定身份；从调用条目展开对应执行对话，不能用名称、时间或“最新运行”猜测关系。 |
| P05 | 执行 Agent 对话默认只读，不提供用户直发输入框。用户在主对话调整要求，由主 Agent 分发。 |
| P06 | 执行 Agent 的补充请求属于同一次工具交互。调用方可答复并继续原执行对话；需要用户决定时，由主 Agent 正常提问。支持情况必须真实，不支持续接的引擎须明确返回错误，不能伪装已继续。 |
| P07 | 递归深度、并发、预算只作为工具调用约束和详情展示；超限返回工具错误，不建立专用页面、排队频道或新的用户状态体系。 |
| P08 | 调用前失败不得建立空执行对话。已经受理的调用保留原身份与失败记录；显式重试是关联的新尝试，未知结果先查询，不自动重放。 |
| P09 | 停止向当前调用及其后代传播；立即停止新派发，真实执行未退出时显示停止中，不提前报告取消成功。 |
| P10 | 工具完成不等于任务完成。父 Agent 处理子结果，主 Agent 汇总实际改动、验证和未完成项后回复用户。 |
| P11 | Agent 历史独立保存，调用只传所需指令和授权上下文引用，不复制完整祖先工具历史；原生上下文与调用链分别管理。 |
| P12 | Team 配置变化只影响后续获准调用；在途调用固定配置与权限，不静默换账号、引擎、模型或工作区。 |
| P13 | 系统独立封装 Agent 对象、Agent 执行循环和调度系统。对象持有身份与配置及对话引用；循环处理单次执行；调度受理调用、安排执行并路由反馈，三者通过明确契约组合。 |

## 3. 约束语义

- 深度：根 Agent 深度为 0，每次调用 Agent 加 1；普通工具不增加 Agent 深度。允许深度等于上限，下一次调用拒绝。
- 并发：按配置的共享执行额度原子预留；超限立即返回错误。等待子结果的父 Agent 不应占住子 Agent 必需的活动执行额度造成死锁；资源仍未释放的进程须继续计入其真实资源额度。
- 预算：全链共享任务账本，子调用不能重置预算。调用前预留、结束后结算；未知费用标记待核实，不当作零。不能可靠计价且预算为硬限制时，拒绝开始并说明原因。
- 限额由可信宿主判定，模型参数不能提权或覆盖；子权限不大于调用方可委派权限与目标 Agent 配置的交集。
- 上限数值沿用经核实的配置或迁移规则，本文不臆造产品默认值。缺配置、零值、非法值及计量单位须由实现契约明确，不能静默解释成无限制。
- 错误包含稳定代码、限制类型、当前值、请求值、上限、计量单位、是否启动及已发生的副作用。收到工具错误后由调用方 Agent 决定后续行动，系统不隐式无限重试。

## 4. 关键用户场景与验收

| 场景 | 验收 |
| --- | --- |
| 仅主 Agent 完成工作 | 用户输入、普通工具、最终回复连续可读；无 Team 配置也可工作。 |
| A 调用 B，B 调用 C | A 展示 B 工具调用；展开 B 后展示 C 工具调用；C 结果只交给 B，B 汇总回 A；只有 A 对用户发言。 |
| B 需要补充 | 请求进入 A 的工具交互；A 可以答复，或询问用户后转交；保留 B 的原对话和关联。 |
| 并行调用 | 每个结果精确返回对应调用；完成顺序变化不串线，兄弟调用不能互取私有上下文。 |
| 深度／并发／预算超限 | 产生可读工具错误，超限调用没有执行副作用，没有空频道；共享预算不重复计费。 |
| 用户停止 A | B、C 停止接收新操作；尚未退出和已发生改动可见；无孤儿运行和伪成功。 |
| 刷新或重启 | 恢复真实调用关系；结果未知先核实，不能重新执行写入。 |
| 长对话切换引擎 | 预检失败留在原对话，输入不丢失；不生成空话题或把全部祖先历史反复转交。 |
| 老版本记录 | 可读且不改写原事实；无可靠调用关系的记录不伪造嵌套。 |

## 5. 范围边界

本需求不新增多人邀请、在线状态、组织架构或协作服务器；不授权公开发布、改写用户数据或删除旧日志。办公室视图不作为本次必需入口，也不新增另一套任务状态源。
