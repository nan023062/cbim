# Agent 统一对话与工具展开 UX

日期：2026-11-15。状态：目标设计，非已实现说明。需求基线：[产品需求](agent-tool-product-requirements.md)。

## 1. 页面与信息结构

主界面保留任务／对话导航、中间连续对话和底部唯一用户输入框。主对话按时间显示用户输入、Agent 回复、工具调用及结果。移除以频道卡列表代替主对话的默认布局，移除“Agent／Team”聊天模式切换；可调用 Agent 在既有配置入口管理。

工具调用统一包含：展开按钮、工具图标、名称与简短目的、真实状态。折叠时只显示必要摘要；展开显示输入、过程、结果、错误和可用操作。Agent 工具展开后的正文就是该 Agent 对话流，内部普通工具和 Agent 工具继续使用同一组件。

桌面允许在同一条目内展开，内容较长时可打开现有详情容器。手机不不断缩窄嵌套宽度，深层内容在同一全宽详情页替换正文，“返回调用方”恢复原条目的滚动和展开位置。导航仅表达回到原调用，不引入第几层、组织树等新用户概念。

## 2. 消息来源与输入

| 所在位置 | 内容来源 | 输入行为 |
| --- | --- | --- |
| 主 Agent 对话 | 用户指令、主 Agent 回复、工具事实 | 用户可发送、附文件、停止；发送目标始终明确为主 Agent。 |
| 执行 Agent 对话 | 调用方指令、执行 Agent 回复、工具事实 | 默认只读；显示“指令来自调用方 Agent”，没有用户直发输入框。 |
| Agent 工具结果 | 被调用 Agent 返回的结构化结果和摘要 | 父 Agent 接收；用户查看不会再次投递或创建新任务。 |

不展示私有推理、凭据或未经授权的上下文。执行过程仅显示允许公开的回复、工具事实和进度。

## 3. 工具状态与操作

以下是现有工具状态的统一展示语义，工程须映射真实事件，不另建 UI 权威状态机。

| 状态 | 显示 | 可用操作 |
| --- | --- | --- |
| 正在执行 | 当前工具和实际进展；缺进度时不编造百分比 | 展开详情；在已有控制能力下停止 |
| 等待答复／授权 | 谁需要回复、缺少什么；属于原工具条目 | 用户只在主对话回答需要用户处理的问题 |
| 停止中 | 已发停止请求、仍未退出的操作 | 查看已发生改动；不显示“已取消” |
| 已完成 | 结果摘要、产物与验证引用 | 展开结果、打开真实成果 |
| 失败／拒绝 | 原因、是否开始执行、已发生改动 | 查看详情；仅在后端允许时显示重试 |
| 已取消 | 实际终止事实和已保留改动 | 查看详情 |
| 结果待核实 | 连接中断或结果未知的事实 | 查询原调用；禁用会重放副作用的重试 |

递归深度、并发、预算显示在工具详情的普通字段中，例如“深度 2 / 4”“活动执行 3 / 3”“预算 ¥8.20 / ¥10.00”。数字均为示例，不能硬编码为默认配置。跨币种不直接相加；缺实际计量时显示未知。

超限错误示例：“未开始执行：并发已达上限（3 / 3），本次请求需要 1 个执行名额。” 深度／预算错误同样使用现有失败样式和结构化详情，不弹出专门管理界面。

## 4. 统一视觉、图标、动效与提示

复用 [既有图标、动效与提示规范](cbim-icon-motion-system.md) 和现有主题变量。Agent 工具仅更换工具图标与名称，不使用特殊大卡片、团队颜色或独立组件体系。

- 状态同时有文字和图标；执行用活动指示，完成用勾，失败用错误，停止用停止图标。不能只靠颜色区分。
- 图标按钮提供可访问名称；桌面悬停和键盘聚焦显示 Tooltip，触屏可通过可见标签理解，不依赖悬停。
- 展开／收起使用短过渡（建议 120–180ms）；减少动效偏好下关闭位移与循环动画，仍保留文字状态。
- 异步加载只在被展开区域展示加载提示；失败就地重试读取，不重新运行工具。
- 流式更新不抢夺焦点；用户上翻后不强制滚到底部，提供回到最新位置入口。
- 展开按钮使用 aria-expanded、aria-controls；状态变化用非打断式播报，错误保持可定位；触屏操作目标至少 44px，320px 宽不横向滚动。

## 5. 同一任务的演示脚本

1. 用户发送“修复断线重连”；主 Agent 回复并调用联机 Agent。
2. 展开该工具，显示调用方指令和联机 Agent 的工具执行。
3. 联机 Agent 调用测试 Agent；再展开看到测试对话。
4. 测试 Agent 返回失败用例；联机 Agent 修改并验证，向主 Agent 返回结果。
5. 主 Agent检查结果后回复用户；不把子 Agent 完成直接显示为用户任务完成。
6. 替代路径分别演示深度、并发、预算拒绝、等待答复、取消、结果未知；都在原工具条目呈现。

## 6. UX 验收

- 主对话可连续读完，不必进入频道才能找到回复或错误。
- A→B→C 的输入、反馈、展开和返回准确，主窗口不混入 B/C 面向父级的发言。
- 桌面、320px 手机、键盘、减少动效均可操作；返回恢复滚动和输入草稿。
- 在工具条目能明确区分“查看记录失败”和“工具执行失败”，前者重试不触发后者。
- 用户看到的状态、操作可用性全部来自真实调用契约；原型通过不等于产品验收通过。

旧 [UX 提案](cbim-ux-system-proposal.md) 与 [全界面设计](cbim-complete-ux-design.md) 的视觉基础可复用；其频道中心、群聊及模式切换在本范围内由本设计取代。未涉及设置和成果页面继续按原设计维护。
