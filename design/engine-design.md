# 领域引擎与模型的核心取舍

Agent Loop 引擎封装一类任务的执行循环，可以适配厂商 SDK，也可以实现专业循环。模型提供推理、生成或向量能力；工具提供被授权的操作。三者不因同属 AI 能力而合成一个生命周期。

## 三个独立边界

- 引擎领域管理身份、声明、选型和本机安装事实；执行装配选择具体引擎。
- 模型领域管理供应商连接、模型目录和能力，按操作与角色解析配置，不用引擎名称决定模型协议。
- 宿主持有授权、预算、正式知识事务与验收。引擎通过版本化端口访问，不能用自报结果授予权限或反向导入宿主实现。

专业循环与通用宿主分开，使新增领域主要扩展引擎实现及声明。代价是必须维护真实能力声明、版本兼容及共享契约测试；不支持的输入、恢复或暂停必须明确拒绝，不能用空实现凑齐接口。

## 静态支持与独立发布

支持哪些引擎由经过 review 的代码静态登记，并随 R 资源发布；远端版本索引与本机下载清单不能注册任意新 ID。支持表只表达描述与策略，不加载 SDK 或具体实现。

引擎包包含适配器／自研循环、声明、固定依赖和资源。包版本、上游 SDK 版本与 Host API 分别表达；制品不可变，入口受信，按平台和宿主能力核验。新增引擎通常需要登记代码和新 E 包；已登记引擎的兼容更新可独立发布 E。超出现有宿主能力或信任根时才调整相应 R/C，不能承诺所有扩展都免冷更。

这换取更小的变化传播范围，同时承担独立包的供应链校验和版本组合成本。具体发布步骤沿 [现有发布流程](../ainative/skills/cbim-release/SKILL.md) 与 [引擎工具入口](../scripts/engine-release.ts) 核实。

## 冻结运行与资源所有权

支持声明、发布清单、本机安装状态、Agent 选择与实际运行绑定是不同事实。安装成功不代表配置匹配，更不代表任务验收通过。

启动固定准确包摘要、模型角色、权限和配置版本；在途运行不追踪 latest。下载与校验放在短事务之外，启动前重新核实身份和取消。停用阻止新使用，清理前核对运行与恢复引用；包回退不能被解释为原生历史或知识数据也可降级。

## 多模型与知识一致性

记忆引擎使用生成和 embedding 两类模型，是当前代码中检验领域扩展的一种实现，不再列为尚未实现的计划。每种请求保留自己的计量单位与预算票据；未知费用不是零，向量请求不伪造生成 token。

正式知识由知识服务维护，向量索引是可重建派生数据。索引失败不能触发已提交知识的自动重写；索引代次关联来源版本、模型身份、维度和分块规则，切换模型时不能混用向量空间。
