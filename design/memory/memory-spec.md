# 个人短期记忆生成与使用

`design/memory/` 定义记忆机制与规范；实际生成的个人记录存放于 `<用户主目录>/.cbim/<项目标识>/memory/` 或宿主指定的记忆存储，不写入本设计目录。

Memory 保存尚未进入正式知识、后续可能复用的个人短期线索。它可缺失，不是执行任务或恢复工作的前提；不承担审批、进度、验收和正式架构规则。记录命名与本地存储边界遵循 [任务知识基线与恢复](../task/task-baseline.md)。

Memory 由入口独立装配，仅允许依赖 Task 的共用记录规范（`memory → task`）。Task、Skill 及其他抽象不反向加载 Memory；需要记忆处理时由入口协调。

## 触发条件与职责

触发只表示检查候选内容，不表示一定生成文件。默认在当前工作中按需执行，不运行后台扫描或定时生成。

| 事件 | 何时判断 | 候选范围 |
| --- | --- | --- |
| 用户明确要求记住 | 收到指令时 | 用户指定的线索；仍检查归属、依据和重复内容 |
| 调查产生新发现 | 一个调查步骤得到可定位证据后 | 难以直接检索到的入口、环境条件、排除结果和待验证假设 |
| 尝试失败或发现绕行方式 | 原因或适用条件有所明确时 | 可避免重复试错的条件、尝试和实际结果，不保存无信息量的报错 |
| AI 成员返回结果 | CBIM AI 助理核对返回内容时 | 成员提交的候选线索，完成状态本身不是记忆 |
| 用户纠正已有线索或依据发生变化 | 本次工作接触到相关记录时 | 受影响的旧记录及新的依据，决定更新或标记失效 |
| 阶段完成、交付或准备交接 | 当前阶段收尾时 | 本阶段尚未处理的候选内容；仅有进度变化时只更新任务记录 |

AI 成员返回候选主题、线索、来源、适用范围、复用理由和未验证项，由 CBIM AI 助理统一分流与去重。当前流程内只安排一个写入者，不让多个成员直接竞争同一记录。

自动写入由下述开关控制。只读任务且未授权写入时只返回候选，不落盘；读取规则仍须执行。不能写入时，对存在冲突或已失效的线索本轮停止采用，并说明状态未持久化。

## 自动生成开关

### 生效范围与恢复

- 持久设置限定于当前项目、当前用户、当前设备，默认开启按需自动生成；未限定范围的开启或关闭指令按此范围持久化，不跨项目、用户或设备传播。
- “本轮／本次请求”只覆盖当前用户请求及为完成该请求而执行的步骤；请求交付或取消后失效。工具调用、AI 成员返回或中断恢复不自动结束该请求；其他独立请求不继承此覆盖。
- “当前会话／这次对话”覆盖当前宿主会话，直至用户撤销或会话结束；不改持久配置。同一会话的上下文压缩不算结束，新会话不继承。
- 有效值按宿主权限限制、当前请求覆盖、当前会话覆盖、身份匹配的持久设置、默认值依次确定。用户在同一范围内再次设置时替换该范围的旧值；较大范围的新设置不静默清除较小范围覆盖，应说明当前仍生效的覆盖。用户明确要求取消所有临时覆盖时再清除。
- 临时覆盖结束后，重新计算有效值，采用届时仍有效的会话或持久设置，不恢复缓存的旧布尔值。临时关闭正常到期不需要再次授权开启；持久关闭则须用户明确重新开启或明确授权更小范围的临时开启。

### 持久配置与身份匹配

- 通用文件模式在 `<用户主目录>/.cbim/<项目标识>/memory-settings.json` 保存配置，结构为 `{"version": 1, "entries": [{"project_id": "项目身份", "user_id": "用户身份", "device_id": "设备身份", "auto_generate": false, "updated_at": "带时区的实际时间", "reason": "用户明确关闭"}]}`。这是固定位置的控制配置，不是记忆记录，不使用记录时间前缀。
- 身份使用宿主可核实的稳定标识；文件模式没有项目标识时可使用规范化项目根绝对路径，没有用户或设备标识时可使用可核实的系统身份。不得凭显示名称猜测身份；标识方案改变或目录迁移后，旧条目不得自动套用。
- 只有三个身份均匹配的唯一条目才能生效。配置有效但无匹配条目时，视为当前身份未设置，采用默认值，不继承其他条目；写入只新增或更新本身份条目，保留其他身份设置。旧布尔格式、身份字段缺失、同身份多条、类型错误、文件损坏或身份无法确认时暂停自动写入并说明，不能当作不存在配置而开启。迁移旧格式须由用户确认归属后进行。
- 宿主要求专用存储时，以相同身份组合为键持久化同等控制信息，不维护文件副本。控制信息不参与普通线索召回，也不受新增线索的六项标准限制；宿主自身的禁用设置优先。
- 每次会话首次准备自动写入前读取并校验配置；收到变更指令、身份变化、临时覆盖结束或发现配置版本变化时重新核对。确认文件不存在或有效配置无匹配条目才采用默认值；读取失败或无法确认当前值时暂停自动写入。无法确认请求或会话覆盖是否仍有效时也先暂停，不猜测恢复。

### 写入权限与失败处理

- 有效值为关闭时，停止所有自动写入，包括新增、补写、状态变更和沉淀标记；仍可按需检索、核实并在当前工作中排除不可靠内容。用户明确要求保存或纠正某条记录时，仅授权该条操作，不改变开关。
- 只有持久配置写入并核实成功后，才能报告跨会话生效。写入失败时，在当前会话内遵守用户最后确认的选择，并明确未持久化；不承诺后续会话能够知道这次失败。宿主无法保存控制状态时，不提供跨会话保证；下次无法确认设置则暂停自动写入。
- 自动开启不覆盖只读任务限制、宿主权限或内容判断标准。设置开启或关闭不启动后台扫描，也不删除已有记录。

## 新增内容的保存判断标准

以下六项仅用于新建线索及给已有记录补充新的事实或假设。既有记录的状态纠正、范围收窄、来源失效说明和沉淀指向按维护分支处理，不要求重新满足新增标准；不得借维护补入未经筛选的新结论。

按以下顺序判断，不凭对话长度、任务耗时或固定条数生成记忆：

1. **属于短期线索**：仍处于调查或待整理阶段。任务状态、授权与验收分流到 task-records；正式规则与设计决定进入权威知识；已能说明适用范围和观察依据的可复用规律进入模块观察模式。单次、局部且归纳不足的假设才暂留 memory。分流不扩大本次修改授权。
2. **未来有明确用途**：能说明下一次什么问题会用到，以及能节省哪一步调查或避免哪种已发生的失败。“可能有用”不足以通过。
3. **具有新增信息**：已有文档或记忆不能直接提供相同结论与条件。能从注册表或源文件直接读到的目录清单、接口签名和代码副本不另存；已经有权威正文时只引用，不复制。
4. **依据可追溯**：提供可定位的来源与观察时间，适用时绑定版本或哈希。事实有证据，假设有支持它的观察与验证方法。只有猜测、无观察依据的内容不保存；用户明确要求保存的推测也须有可追溯的观察依据与验证方法，否则说明未保存原因。“待验证”表示有观察依据但结论未验证，不表示可以缺少依据。
5. **范围和失效条件明确**：至少说明适用问题、模块或环境，以及需要重新核实的条件。缺少信息先补充，不把一次成功或失败推广为通用规律。
6. **可压缩为独立主题**：用简短线索与下一步验证描述清楚，不需要复制完整日志、聊天或大量源码才能成立。原始证据保留在其权威位置，通过引用定位。

新增内容六项均满足才进入去重与保存步骤。没有合格新增候选是正常结果，不创建空记录或“本轮无记忆”的文件；这不阻止对本次涉及的旧记录进行必要维护。凭据、令牌及无关个人信息不得写入。

## 去重与处理结果

去重覆盖有效和待验证记录，并定向检查同主题的已失效、已沉淀记录及其替代关系或权威知识位置，不能只按标题或文件时间判断重复。普通任务召回只采用有效或待验证线索；去重读取历史状态不代表重新启用它们。

| 判断结果 | 动作 |
| --- | --- |
| 合格且没有等价记录 | 新建；未完成验证标为待验证，已核实的局部事实标为有效 |
| 等价记录已有同样证据 | 不写入，不刷新更新时间制造新内容 |
| 同主题新增证据或范围收窄 | 更新原记录，保留创建时间，注明变更依据 |
| 结论冲突且新证据不足 | 不覆盖旧结论；整条记录转为待验证，在正文区分冲突与来源，冲突部分停止作为事实使用 |
| 已证实旧结论错误或适用条件不再成立 | 标记旧内容已失效并注明原因；有合格新结论时记录替代关系 |
| 已进入模块或能力权威知识 | 标为已沉淀，保留来源与权威位置，不继续维护重复正文 |
| 新增内容不符合六项标准 | 放弃新增内容，或分流到正确记录类型；既有记录仍可按维护规则纠正 |

“有效”仅表示在记录的条件下已核实，不代表正式规范。依据版本变化且影响未明时先回到待验证，不能仅凭版本变化断定结论错误；确认失效后才标为已失效。已失效内容重新获得证据时，明确重新验证依据及替代关系，不静默恢复。

## 生成与维护步骤

1. 分类：事件触发后，区分新增内容与既有记录维护。新增线索或补入新结论先通过六项标准；来源丢失、冲突、条件变化或已沉淀等维护直接核实变化依据，不因缺乏新增价值而跳过。混合情况分别判断，只执行通过条件的部分。
2. 分流：任务进度、授权、快照和验收证据归任务记录；已确认的模块规则归模块知识；可复用的待验证规律归模块观察模式。Memory 只保留尚未整理的短期线索，不复制上述正文。
3. 核实：区分事实与推断，保留来源路径、对应版本或内容哈希、适用条件和待验证问题。有可追溯观察但结论未验证时标为待验证；完全没有依据或来源无法定位时不新建、不补写候选内容，说明缺口。已有记录的来源丢失时停止采用并转为待验证，确认失效后再标为已失效；所有状态写入仍受开关与授权限制。
4. 决定动作：新增内容执行完整状态范围的去重；等价内容且状态、条件均未变化时不写入。维护按已核实的变化更新原记录，保留创建时间并说明理由；来源丢失可据实际读取失败或路径核实结果转为待验证，无需取得已经丢失的原始证据。结论变化按冲突核实与替代规则处理。
5. 落盘：先核对开关、授权和选定动作；需要新建时默认在 `<用户主目录>/.cbim/<项目标识>/memory/` 新建 `YYYY-MM-DD_HH-mm-ss_主题.md`，文件名取实际本地时间并在正文注明时区。一个主题一份记录，更新不改创建前缀；多附件主题可使用同名目录。格式见下文。
6. 复核：确认写入成功、状态与实际证据一致。新增内容的来源必须可定位；维护记录中的失效旧引用须明确标记其不可用原因及本次核实依据，不伪造引用恢复。写入失败时如实报告未保存，不影响已有任务成果的交付，也不声称已记住。

宿主若规定专用记忆接口或唯一存储渠道，应通过该接口读写，不绕过宿主限制直接创建另一份记忆。上述目录是通用文件存储约定，不要求镜像宿主记忆；回执需说明实际存储位置。没有可用持久化能力时，返回候选内容与未保存状态。

## 单条记录格式

```markdown
# 主题

- 创建：YYYY-MM-DD HH:mm:ss +08:00
- 更新：YYYY-MM-DD HH:mm:ss +08:00
- 状态：待验证 / 有效 / 已失效 / 已沉淀
- 范围：适用模块、环境或问题；未确定时明确说明
- 来源：可定位的文件、任务证据或用户说明，附版本依据
- 复用理由：下次什么问题可复用，能节省哪一步调查
- 失效条件：哪些前提变化后必须重新核实
- 变更依据：更新或替代的原因及关联记录；首次生成可省略

## 线索
简短描述事实、尝试或假设，并区分未验证部分。

## 后续使用
如何核实、仍待解决的问题；已沉淀时只记录权威知识位置。
```

## 读取、沉淀与清理

- 收到相关需求时先按主题和模块检索，仅读取命中的有效或待验证记录，不把整个 memory 目录注入上下文。不存在记忆或未命中时正常继续。
- 使用前核对当前文件与证据版本；待验证内容只能作为调查线索，不能当作规范、授权或验收依据。与用户当前指令及权威知识冲突时，先停止采用并转为待验证；确认旧结论错误或适用条件已不成立后，才标为已失效。持久化状态遵循开关与授权规则。
- 线索经核实适合进入正式知识时，由助理按入口选择已有知识维护流程；本文件不直接调用 Skill。确认权威知识实际写入且通过核验后，在允许写入 memory 时记录其位置并标为已沉淀，避免保留重复正文；未获授权或写入失败时，不提前宣称沉淀完成。
- 阶段结束时整理本次涉及的记录，不无故扫描全部历史。失效项停止默认召回；删除按用户清理范围执行，不因固定天数自动删除，也不删除其引用的任务证据。
- Memory 丢失不意味着工作无法继续。需要恢复进度、授权或版本时读取任务记录，不从个人记忆推测任务已经完成。

## 判断示例与完成条件

| 候选内容 | 判断 |
| --- | --- |
| “任务完成，测试通过” | 属于任务结果，写入任务记录，不生成 memory |
| “某模块位于某目录”且注册表已有记录 | 可直接查询，缺少新增信息，不保存 |
| 某环境下失败，记录了具体前提、实际尝试和定位证据，原因待验证 | 有复用场景和验证方法时保存为待验证；只保留必要线索 |
| 同一线索再次出现，内容、状态和条件均无变化 | 不新增、不改写 |
| 已有记录来源丢失，无法满足新增标准 | 进入维护分支；允许写入时注明核实结果并转为待验证，不补入无依据的新结论 |
| “本轮关闭”，会话设置为开启 | 仅当前请求关闭，交付或取消后重新计算有效值 |
| 配置有效但属于另一用户或设备 | 不采用该条目，当前身份无设置时使用默认值 |
| 已确认的模块排障方法 | 进入模块知识；已有短期线索标为已沉淀 |
| 用户只纠正一次输出措辞 | 本轮直接遵守；不能自行推断为长期偏好或通用知识 |
| 旧线索依赖的配置改变，影响未查明 | 转为待验证并重新核实，不能继续作为事实采用 |

完成本次生成处理须满足：候选均已分流，无需保存时可正常结束；需要写入时通过开关、授权及对应分支复核：新增内容满足六项标准且无等价重复；维护有可核实的变更原因、状态与失效引用说明。两者均须命名合规且写入渠道返回成功。用户明确要求保存时回复实际保存位置或未保存原因；自动处理时仅在影响后续使用或存在失败时说明，不每轮堆积记忆汇报。

这些规则由当前助理流程执行，文档存在不代表宿主已经提供后台触发器、自动检索索引或持久化服务。
