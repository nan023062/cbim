# 产品模型与知识分工

CBIM 面向本地／多端 AI Native 工作流。用户通过连续对话表达目标，Agent 使用有明确授权的工具完成工作并交付可核实的结果。产品不自建多人邀请、在线状态和协作服务器；外部工程协作通过 Git、P4、飞书等连接器承接。这是产品目标，不代表所有多端能力已经实现。

## Agent 与 Team

Agent 表达专业能力、工作原则和可用方法；主 Agent 与执行 Agent 的区别来自当前调用关系。主 Agent 面向用户，被调用 Agent 面向直接调用方，两者使用统一执行模型。Team 配置可调用 Agent 的职责、能力与权限，不引入第二套聊天模式。具体行为与验收集中在 [产品需求](agent-tool-product-requirements.md)。

能力目录与 Skill 分组解决资料组织和检索，不决定运行层级或授权。专业方法在所属 Agent 的 Skill 中维护，共享方法以引用复用；不能因为目录可见就认为可执行。

## 能力与工作对象

Module 表达工作对象的职责、边界、知识和流程，与“谁有能力工作”的 Agent 分开。一个模块可以关联分散的实际源码；目录包含、业务依赖、任务前置和运行调用分别建模，不能相互推导。

模块索引供检索，知识正文解释结构与设计依据，Workflow 保存可重复操作步骤。共享知识只有一个所属位置，其他对象引用；父模块只理解直接子模块的边界，不复制子模块内部细节。尚未确认的观察不能自动升级为正式设计约束，源码扫描也不能替代人工确认的架构决定。

工作区提供实际工程和知识的作用范围；Task 表达本次目标、责任和验收。引用模块、文件或外部资源不等于获得其写入权限，工具完成也不等于业务验收完成。

## 取舍与深入阅读

分开能力、工作对象和执行任务，使新增专业角色不要求复制项目知识，调整模块知识也不要求重写所有 Agent。代价是需要保持引用准确，并在执行时明确身份、权限及资料版本。
