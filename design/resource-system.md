# CBIM 资源体系设计

普通客户端无需注册、登录或配置发布凭据，即可浏览商城、下载免费资源、安装和更新兼容的签名引擎及连接器。发布资源单独鉴权；付费资源下载取决于权益，不能借匿名访问绕过。


**设计基线。** 贡献者在本地客户端设计、实现和验证资源，通过客户端上传选定版本；云端市场负责接收、管理和分发，本机客户端也负责缓存和运行，项目负责决定采用什么、如何组织工作。这是目标设计与验收依据，不代表存量数据已迁移或云端服务已经上线。Office 如何派发和交付见[核心系统设计](core-system-design.md)，业务节点如何组成工作区见[工作区编译设计](workspace-compilation.md)。

桌面端通过侧栏「资源商城」访问资源服务器。引擎、连接器、人力和业务按分类浏览，同一入口处理上传、下载与更新；Office 只选择本机已安装可用的资源。商城不可用时提示连接失败，不切换到其他分发源。

## 三层归属

| 位置 | 保存什么 | 谁决定变更 |
| --- | --- | --- |
| 资源市场（规划中的云端资源服务器） | 面向各客户端的贡献资源：引擎、连接器、人才市场的能力资产、业务模板。每个发布版本有资源标识、类型、发布者、版本、依赖和完整性标识 | 贡献者显式提交、市场发布；本机试用和项目内编辑不会自动上传 |
| 用户目录 `~/.cbim/` | 四类资产的本机缓存；已安装版本、启停及本机运行记录。账号凭据由本机安全存储管理 | 客户端下载、校验、安装或清理缓存。多个项目可复用同一资产版本 |
| 项目目录 `<项目>/.cbim/` | 项目知识库与项目配置，包括两棵树、已复制的资产、引擎和连接器的引用、项目级工作约定与定时任务定义 | 用户通过页面或助理编辑；Office 从此处恢复项目定义。移动目录、换机器或清理用户缓存不能改变这份定义 |

区别两个同名目录的办法：**新机器打开同一个项目必须看到的定义，写在项目里；换机器就需要重新安装、授权或确认的状态，留在用户侧。** 构建产物、聊天日志和模型密钥不属于项目架构树。

## 从本地创作到云端发布

1. **本地设计与实现。** 贡献者在自己的开发项目中制作引擎或连接器，构建并试运行插件；也可以将已验证的团队、岗位、Skill 或业务工作区、Workflow 整理成模板。草稿可离线迭代。
2. **客户端打包与上传。** 贡献者在客户端选择要贡献的资源，核对包内文件、依赖、版本和共享范围，再发起上传。客户端只上传这次选定的版本包和清单，不扫描上传整个项目、用户缓存、凭据或运行日志。
3. **云端接收与发布。** 服务器校验发布身份、内容摘要和版本冲突，保存资源包并返回上传结果。市场发布成功后，其他客户端才能按共享范围发现和下载该版本。上传失败可从本地重试；已上传但未发布的版本不出现在可下载目录中。
4. **其他客户端采用。** 下载到本机缓存后，引擎和连接器由项目引用，能力和业务模板复制进项目。作者后续在本地修订并上传新版本，不覆盖已发布版本或使用方的项目内容。

## 四类资源怎样进入项目

**引擎和连接器由同一客户端的所有本地项目共享安装；人才和业务资产导入后归项目独享。** 两个项目引用同版本的引擎或连接器，只需安装一次；各项目独立选择是否引用，连接器的账号授权不会随引用自动继承。人才和业务模板的下载包可缓存在用户目录，但运行时读取各自项目的副本。在 A 项目修改或删除岗位、技能或工作区，不会改变 B 项目或模板原件。

| 市场分类 | 本机缓存 | 项目采用方式 | 更新时的行为 |
| --- | --- | --- | --- |
| 执行引擎 | 可验证的适配器、运行包与依赖 | **引用**资源标识和选定版本；不写本机绝对路径、不复制可执行包 | 新版本可与原版本共存；项目升级引用才切换，进行中的任务保持原版本 |
| 连接器 | 插件、协议与依赖 | **引用**资源标识和选定版本；账号、凭据和授权独立绑定 | 更换版本不扩大权限；新机器必须重新确认可用账号与授权 |
| 人才市场（能力资产） | 团队模板、岗位、Skill 等发布内容 | **复制**采用的内容到项目能力树，分配项目节点 ID，保留来源标识和版本 | 项目可以独立改名、改职责、改技能；上游更新只提供可审阅的差异 |
| 业务模板（业务资产） | 业务树、工作区模板、Workflow 与验收要求 | **复制**到项目业务树，再绑定项目内的目录、资料和验收规则 | 同一模板可导入多次；更新某一实例不得覆盖其他实例或本地修改 |

市场发布版本、用户缓存版本、项目节点是三个不同身份。例如，同一个“游戏策划”模板可在 FPS 中生成“战斗策划”和“关卡策划”两个岗位；删除本机模板缓存，不应删除任何一个岗位。本机版本保留与清理遵循下列规则。

## 本机共享包的版本与清理策略

引擎和连接器均按精确版本并存：同一资源、平台和制品摘要只存一份；项目 A 锁定 v1，项目 B 可同时使用 v2。市场标记的最新版仅用于提示更新。安装 v2 不覆盖 v1、不中断已有会话，也不修改 A 的项目引用。

| 本机版本状态 | 清理规则 |
| --- | --- |
| 本机已登记项目锁定，包括未打开的项目；或被保留版本间接依赖 | 必须保留。管理页列出占用项目或依赖方，先升级或解除引用才能清理。项目目录暂不可访问时，沿用上次确认的引用；引用情况未知时跳过自动清理。 |
| 正在运行、安装或校验；已排队任务固定使用；或作为本机默认、被用户标记保留 | 必须保留。关闭一个窗口不等于释放全部引用；回收前重新核对任务和跨进程占用。 |
| 已无上述引用，且未处于保护期 | 可手动清理。自动回收建议默认保留最近使用的 30 天，超过缓存容量预算时按最久未使用优先回收，空间足够即停止。30 天和容量预算属于客户端可调参数。 |
| 下载中断留下的临时文件 | 与已验证安装包分开管理；只有确认无下载或恢复任务占用后，才按临时文件策略清理。 |

清理预览显示资源、版本、预计释放空间和保留原因。若全部版本均受保护，即使空间不足也提示用户处理，不强删。清理只作用于用户目录中的缓存，不改项目文件、授权或市场资源；外部导入的项目若引用了已回收版本，提示按原版本和摘要重新获取，不能静默切到最新版。

## 项目知识库与首次打开

| 项目内位置 | 权威内容 | 消费者 |
| --- | --- | --- |
| `.cbim/` | 项目身份、格式版本、资源引用、项目配置和任务定义 | 初始化、迁移、资源解析、Office |
| `.cbim/cability/` | **能力维度的组织树**：团队、岗位、职责、技能与岗位资源需求 | 组织架构页与助理经同一项目接口增删改查；运行时从这里装配组织 |
| `.cbim/bussinss/` | **业务维度的工作区树**：节点、父子关系、职责范围、Workflow、资料位置和验收要求 | 业务架构页与助理经同一项目接口增删改查；运行时从这里装配工作区 |

以上两处目录名按项目约定固定拼写。项目身份和树节点 ID 不依赖机器绝对路径。业务工作区可以关联多个项目相对目录；移动或重命名岗位、工作区不应改变其 ID。运行时快照可以缓存，但不能演变成与项目文件各自接受写入的第二份定义。

1. 首次打开空项目时，在项目根目录初始化知识库、项目身份和两棵空树。此步骤不等待云端或引擎更新。
2. 已有有效知识库时直接加载，不重复初始化。检测到旧布局时，校验并迁移原定义，保留节点身份和项目修改；遇到格式冲突或未知版本，保留原件并报告原因。目录不可写时明确提示，不在用户目录悄悄另建一份。
3. 打开后先呈现两棵树，再解析本机依赖。缺包、离线或未授权应指出受影响的资源和操作；不影响查看、编辑与该依赖无关的项目知识。
4. 结构变更先校验节点关系和版本，再写回项目；写入成功后刷新页面与运行时。删除仍被任务或子节点引用的对象，应说明依赖并先处理引用，不能留下无主任务。

## Office 如何使用资源

助理可以在当前项目权限内管理组织、业务、定时任务和项目配置。页面与对话调用同一套项目操作；只读模式不写入，需确认的变更仍走确认流程。写一份团队说明文档不等于登记岗位，项目声明需要连接器也不等于账号已经授权。

派发一次任务时，记录**项目 ID、岗位 ID、工作区 ID**，并固定本次执行使用的引擎版本。岗位说明“谁负责”，工作区说明“交付什么、在哪里验收”。交付件可以在项目正文目录，任务回执应指向真实产物。定时任务的规则和目标属于项目；哪台客户端启用调度、上次触发记录属于运行状态。复制项目到另一台机器不能默认产生第二个执行者。

## 验收场景

| 场景 | 可观察结果 |
| --- | --- |
| 两个客户端验证贡献流程 | A 在本地制作并验证一个策划岗位模板；上传并发布前 B 搜不到，发布后 B 可按版本下载并导入自己的项目。A 继续编辑草稿不影响 B。 |
| A 锁定连接器 v1，B 锁定 v2，A 升级时仍有任务使用 v1 | 两版共存；关闭 A 或修改项目引用都不能中断旧任务。任务结束且无其他引用后，v1 才能按清理策略回收。 |
| 空 FPS 项目首次打开、关闭后再开 | 第一次离线也能初始化；第二次项目及节点身份不变，不重置树 |
| 用户要求创建策划、美术、UX、程序、测试团队，再让策划设计 | 五个岗位出现在组织页并可重新读取；设计任务同时指向真实策划岗位和业务工作区，有独立交付回执 |
| 项目修改导入的岗位或业务模板后，市场发布新版 | 本地修改保留；可以查看来源、版本和更新差异，确认后才合并 |
| 将整个 FPS 目录复制到没有缓存的新机器 | 两棵树、项目配置和资源引用完整可读；执行前明确提示缺少的引擎或连接器，不自动继承原机账号或调度权 |
| 已安装可用引擎，市场不可达 | 本地执行不等待市场检查；依赖外部模型或服务的调用仍遵从其自身连接条件 |
