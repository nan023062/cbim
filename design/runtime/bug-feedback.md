# BUG 反馈

适用于用户点击对话窗“+ → BUG 反馈”，或明确要求调用 BUG 反馈 Skill。遵循[通用规范](builtin:common-rules)。这是产品反馈收集，不是当前工作区的业务开发任务。

## 首次调用

先核对本轮实际活动工具，`cbim_knowledge_tool_catalog` 只列知识族，不能据此判定反馈工具缺失。提交和核实工具应同时存在；任一缺失时先调用本轮提供的 `cbim_feedback_status`，按真实错误码提示，保留已经填写的上下文，不让用户反复重填。连接诊断不证明原提交结果；只有尚未发起过的反馈才能称“尚未提交”，已有未知提交始终保持待核实。

- `GITHUB_NOT_CONNECTED` 或 `GITHUB_EXPIRED`：说明尚未提交，按诊断提示连接或重新连接账号，之后发送新消息继续。
- `GITHUB_AUTH_PENDING`：本机还在等待授权结果，请回到 GitHub 反馈设置页并保持打开直到显示已连接；网页授权完成后不要求再授权一次。
- `FEEDBACK_NEW_TURN_REQUIRED` 或 `GITHUB_CONNECTION_CHANGED`：账号已连接或连接已变化，请发送新消息开启新一轮，沿用原上下文；不要要求再次授权，不自动重发未知提交。
- `FEEDBACK_TOOL_NOT_LOADED`、`GITHUB_SETTINGS`、`GITHUB_SECRET_STORAGE`：按返回事实说明组件、设置或安全存储问题，不解释为账号未连接。
- 状态工具也不存在，或状态称就绪但实际仍缺工具：说明“尚未提交，本轮反馈工具不可用，连接状态尚未核实；请检查 CBIM 版本或重启应用并查看运行日志”，不声称重新连接一定能解决。

用户已明确给出愿意反馈的问题简述时，直接进入“收到上下文”，不要先发模板或追问补充项。只有点击菜单而没有描述问题时，简短提示：“用一句话描述遇到的问题即可，其他信息都可不填。内容会提交到已连接的 GitHub 仓库，请勿填写凭据或不愿分享的信息”，然后等待用户描述。菜单名称本身不是问题正文，不能凭空创建 Issue。

仅当用户需要格式时提供以下自愿参考；只填写第一项就可以提交：

```text
问题简述：
复现步骤（可选）：
实际结果／报错（可选）：
期望结果（可选）：
CBIM 版本、操作系统（可选）：
出现频率（可选）：
截图或相关日志（可选）：
```

只使用用户愿意提供的内容，不因缺少复现步骤、实际/预期结果、环境、频率或附件而阻塞或追问。缺项省略或写“用户未提供”；用户明确写“不清楚”等则保留原意。不猜版本、复现过程、影响范围或根因，不自动读取环境补齐模板。截图与日志由用户自行选择；不读取、上传完整工程、会话或凭据。

## 收到上下文

有一句非空问题简述即可整理标题并提交，不要求证明可复现。其它内容仅在用户已给出时归位，不能将推断写成用户事实。反馈授权不等于修复授权，不创建业务目标、不派工、不更改文件。

直接调用 `cbim_feedback_submit`，不增加草稿确认或逐条审批。仅 `kind:"bug"` 和 `summary` 必填；`steps/actual/expected/environment/extra` 均可省略或留空，后端将缺失主栏目统一写为“用户未提供”。例如用户只说“安装后的桌面图标与启动后窗口图标不一致”，即可提交 `{"kind":"bug","summary":"安装后的桌面图标与启动后窗口图标不一致"}`。不要为填满字段反复追问，不把推测、完整会话或工程资料加入。附件仅在用户明确提供可分享链接或说明时加入 `extra`，本工具不自动上传本地截图或文件。

只有实际工具返回 `status:"submitted"` 才表示创建成功。此时用一句话反馈已提交并结束，明确提交不代表开发完成；可引用真实回执中的 Issue 链接，不承诺处理结果或排期。不查询开发进度。

如果本轮没有提交工具，按上面的可用性检查区分原因；如果只读权限拒绝提交，说明需切换允许写入的会话权限。连接授权只允许这个固定仓库，不可用浏览器填单、命令、任意网络工具或模型参数改变目标。GitHub 明确拒绝时保留原上下文并简短说明错误，不循环重试。超时、取消、未知或坏回包后仅在 `cbim_feedback_receipt` 实际可用时核实原提交一次；核实成功后简短反馈真实提交结果并结束，仍未知或核实工具不可用则说明“提交结果待核实，未自动重发”，不要换正文、调用 ID 或会话重发。原提交核实不是开发结果回访。

后续处理结果统一进入软件版本更新日志；本 Skill 不建立“我的反馈”、进度订阅或逐条结果回访。

`GITHUB_PENDING_OTHER` 表示当前工作区另有不同内容的待核实提交：停止本条提交并保留用户正文，不把其它原提交的回执当成本条成功。硬中断后可在新会话明确要求核实原提交；同一工作区相同账号／仓库／内容跨会话也只创建一次。核实有界，原 Issue 被改写或未找到时保持未知，不承诺自动恢复。
