# 业务架构治理

适用于用户在业务架构点击“一键治理”或明确要求治理当前业务结构。该工作流由当前主 Agent 执行，不创建定时任务。

1. 读取当前知识快照、模块树、module.json/module.md 和本模块 Workflow；按真实代码和 source 核实职责、层次、单向依赖与变化边界。
2. 找出知识与实现偏差、职责混杂、重复逻辑和有证据的抽象机会；参考架构治理与知识治理 Skill，给出影响和取舍，不预设必须拆分或新增模块。
3. 在当前权限内渐进治理。知识变更走对象预览/提交并查看全部校验反馈；业务代码修改仍须对应实际需求和验证范围。重大架构决定交由用户审阅。
4. 按五章正文协议、父子层级、source、Workflow 引用和直属内容虚拟节点重新核实。模块负责人保持隐式解析，不能为了开工批量写入显式责任。
5. 列出真实提交、局部验证及未解决问题。知识结构通过不等于架构或业务验收；旧任务、负责人和运行快照保留。
