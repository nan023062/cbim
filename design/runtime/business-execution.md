# 需求实现

遵循[通用规范](builtin:common-rules)、[Task 定义](builtin:task-spec)与[任务基线](builtin:task-baseline)。本工具只返回流程，业务执行使用宿主实际能力。

1. 明确用户目标、已有进展、范围、负责人、授权与验收方式。仅分析请求不默认授权实现。
2. cbim_module_registry → cbim_module_get 定位业务模块和自己的 Workflow；cbim_agent_registry、cbim_people_list → cbim_agent_get 匹配能力。作者仅提供候选线索，专业适配与权限仍需核实。缺少模块边界时先提出定义方案，不虚构已登记模块。
3. 整理必要的模块知识、专业原则、可用 Skill、Workflow、工具与产物基线。Skill 从自身到祖先继承，Workflow 只使用本模块的。以服务返回的冲突与缺失信息为准。
4. 按明确模块、责任、依赖和读写冲突拆分任务，列出执行步骤和验证证据。跨模块任务分别核实边界。不为形式化创建无意义任务。
5. 在有效授权内实现；宿主具备且获授权使用委派能力才可派发，否则顺序执行。记录真实工具结果，不伪造并行、隔离或完成回执。
6. 依据结果继续、修正或报告阻塞；外部副作用结果未知先核实，不盲重试。无关步骤可继续，不让流程空转。
7. 进行必要的业务验证与回归，核对实际运行版本。知识变化使用 cbim_object_preview/cbim_object_commit 或受控知识事务接口；结构通过不能代替功能验收。发现架构问题交由治理判断，不默默扩大重构。
8. 交付实际成果、验证结果、未验证项、剩余问题和接续位置。需记录基线时使用宿主任务记录并说明 CBIM 当前没有完整业务任务持久化接口。
