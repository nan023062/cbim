# 业务执行

本规范供当前 Agent 完成已授权的项目工作，不增加权限，不把工作区知识或角色配置当作用户授权。

1. 明确目标、允许修改范围和验收条件，读取真实工作区身份与所需模块知识。
2. 使用本轮实际提供的工具完成工作；没有 Team 配置也可由主 Agent 在原对话直接执行。
3. 需要委派时先用 cbim_agent_list 查询可调用标识、配置及限制，再用 cbim_agent_call 给出清楚指令和必要上下文。静态 Agent 路径与岗位标识不同，不猜测 UUID。
4. 执行 Agent 使用同样的工具循环，也可调用其他 Agent；返回结果、错误和具体缺口给直接调用方。主 Agent 整合结果并向用户汇报。
5. 按真实改动及消费者选择验证，记录命令、环境和结果。未验证、失败和未知不能说成通过。
6. 需要返工时基于明确证据继续；未知工具副作用先核实原调用，不换身份重放。
7. 汇总实际产物、验证和剩余问题。模型回合结束与工具成功不自动表示业务目标完成。

递归深度、并发和预算由调度系统及原请求账本控制，限制返回普通工具错误；不得绕过、无限重试或创建替代频道。子 Agent 不得自行提高权限或静默替换模型。当前装配不支持的异模型或暂停答复须明确返回限制，用户信息经主 Agent 获取。

所有 .cbim/ 知识查询与修改经过受控服务，不能用原生文件工具绕过。read/ask/execute 及审批、版本、Schema、来源核验仍生效。模块负责人、业务 Workflow 和 Skill 是专业上下文，不因递归调用取得更大的文件或操作权限。

旧日志恢复若只提供 cbim_dispatch_task 等旧协议，则按该工具已注册的参数、候选和恢复契约处理，不能把旧入队回执当成新调用已执行。不为普通问答强制创建目标计划。
