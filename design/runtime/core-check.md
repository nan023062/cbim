# Core 检查

遵循[通用规范](builtin:common-rules)。本流程不自动在每个任务结束后运行，调用工具只返回检查指引。

1. 核实用户明确要求和检查范围，建立覆盖清单；通过内置资料与知识查询取得当前依据，无法取得的内容列为未覆盖。
2. 检查抽象层依赖方向，能力侧与业务侧是否不当互依，通用规范是否绑定某个项目实例或宿主实现。不把文件目录形状直接当作架构结论。
3. 检查 README/docs 与执行指引职责：人类导航不能被当作启动权威；执行 Skill 不应依赖人类说明中隐藏的操作规则。检查旧部署、Python 入口和宿主直读旧路径是否残留。
4. 查询团队与 Agent 详情，核对根 Team、中间小组、叶子 Agent、自身及所有祖先 Skill 的继承与冲突；Module 只使用自身 Workflow。
5. 检查原则、方法、知识与规则的权威来源是否唯一，运行约束与设计说明是否混淆；程序结构验证不能代替专业判断。
6. 默认只读返回位置、证据、影响与建议。发现问题不自动授权修正 CBIM 安装资源或业务架构；内置资料问题应进入 CBIM 工程维护，不在工作区复制覆盖。
7. 若用户授权修正工作区知识，通过 MCP 预览、提交后复核；内置程序问题报告缺口与未完成范围。交付已覆盖、未覆盖、确认问题和待判断项。
