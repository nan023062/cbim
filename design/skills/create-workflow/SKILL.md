# 新建模块 Workflow

输入：所属模块目录、流程目标、触发条件、已确认的操作依据与维护授权。产出：`workflows/<小写_snake_case>/workflow.md`、模块清单及验证结果。

1. 按[任务基线](../../task/task-baseline.md)记录实际使用的定义与依据。通过[任务上下文](../../task/task-spec.md)接收调用方提供的模块规范及其版本，缺少时返回输入缺口；依据该规范核对目标 `module.json` 和 `module.md`，核实模块职责与已有 workflows；已有等价流程时向调用方返回复用或更新建议，不自动建立重复入口。
2. 依据实际工具和用户确认内容编写一个独立流程，写明触发条件、输入、授权范围、步骤、出口校验、失败与恢复、完成条件。流程引用模块知识，不复制设计；未知按钮、命令和输出不能凭空补齐。创建文档的授权不等于执行流程的授权。
3. 将完整正文写入本次任务记录的输入文件。优先复用已有确定性工具；确需新脚本时放在此 Workflow 的 `scripts/`，验证参数、失败和正常路径，不每次临时生成重复实现。运行报告留在任务记录。
4. 使用下面的固定入口预览，再带 `--write` 创建并登记。脚本拒绝覆盖、越界、重复、无效所属定义和空正文；不会代写语义内容或执行流程。`--owner` 相对项目根，`--content` 为已编写的 UTF-8 文件，`--slug` 为流程目录名。

```powershell
python -B design/skills/create-workflow/scripts/create_workflow.py --root "<工程根>" --owner <模块目录> --slug <流程目录名> --name "<流程名称>" --content <正文文件>
# 已有新增授权时，同一命令加 --write 落盘。
```

5. 核对生成入口与模块 `workflows` 清单，正文中相对链接按最终目录解析；按需在 module.md 现有章节加入导航，不增加章节。运行 `python -B design/scripts/maintain_registries.py --root "<工程根>" --check`，索引确有变化才使用 `--write` 后重新检查。通过正常、前置条件缺失、操作失败三个场景走读，并实际测试新增脚本。
6. 返回创建路径、登记变化、验证证据和未验证项。脚本退出 0 表示预览或写入完成，1 表示失败；失败时查看具体错误并核对文件现状再重试，不覆盖现有入口。只有文档走读时明确未执行实际业务流程。需其他治理时把证据返回调用方，由入口路由，不直接调用其他 Skill。
