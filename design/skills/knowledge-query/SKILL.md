# 默认知识查询循环

适用于查找定义、解释职责、查询契约、已有方案或操作流程。由 CBIM AI 助理执行；一般闲聊与无需项目调查的简单状态回复不强制进入本循环。

输入：用户问题、范围、调用方提供的索引与权威资料入口、已有结果及有效授权。输出：逐项结论、来源与适用版本、事实与推断的区分、未确认事项，以及需要调用方处理的问题与返回位置。

使用 [任务知识基线与恢复](../../task/task-baseline.md) 绑定实际使用的资料。需要模块调查时复用 [Task Loop](../../task/task-loop.md) 和 [Task 定义](../../task/task-spec.md)，不重定义派发或执行者内部循环，不直接调用其他 CBIM AI 助理 Skill。

## 1. 确定问题与回答边界

整理可回答的子问题，明确用户要了解文档规定、当前实际行为还是修正建议。记录范围与所需证据；能够从已核实资料直接回答的简单问题不强制派发任务。需要排查实际故障或改变产物时，把目标差异返回调用方决定流程，不将查询视为修改授权。

## 2. 定位权威资料

需要全局架构模块树时使用 [core 模块树预览工具](../../scripts/preview_module_tree.py)：`python -B design/scripts/preview_module_tree.py --root "<工程根>"`，可选 `--root <项目根>` 与 `--open`。必须显式指定项目根，读取全部正式模块的 children，检查悬空子模块、多父与循环；失败退出 1，不输出部分树。成功退出 0，在本地任务记录中生成自包含 HTML、定义哈希及结果路径，可离线缩放、拖动、搜索、折叠并查看 scope。虚拟直属内容按需显示，不注册新模块；图中连线仅表示包含关系，不从 source 路径推导结构或代替正文类图的业务依赖约束。预览是生成时快照，模块更新后重新运行；不自动运行 Core Check 或修改索引。

候选模块查询统一复用 [模块检索脚本](scripts/query_modules.py)，不重复生成检索脚本。脚本接受 `--root <项目根>`、`--query <词项>`、`--module <精确模块 id>`、`--limit <条数>`；默认项目根为当前工作目录，可用 --root 显式指定，结果输出到标准输出，不修改文件。示例：

```powershell
python -B design/skills/knowledge-query/scripts/query_modules.py --root "<工程根>" --query "资源 生命周期"
```

结果包含定义与 overview 路径、SHA-256、匹配词和正文行号。该脚本按 id、name、summary 做字面候选检索，不将匹配分数解释为语义可信度。退出码 `0` 有候选、`2` 未命中、`1` 输入或资料错误；未命中后按本步骤继续限定范围调查，不能宣称全项目不存在。显式模块定位可用于读取不含查询关键词的权威入口。

使用传入索引检索候选，再读取命中定义、边界及必要正文。摘要用于定位，不能代替正文证据。沿引用按需展开，核对路径、知识归属、适用范围与生效状态；不重复展开循环引用。未命中时记录已检索范围与缺口，不宣称全项目不存在相关知识。

## 3. 构建必要的查询任务

需要专业或跨模块调查时，将子问题、实际查询对象、只读依赖、资料入口、基线、只读边界和回答验收条件交给 Task Loop。一个 Task 绑定一个经核实的负责维护的 AI 成员 与其维护的一个或多个模块；只读不取消维护关系与模块覆盖检查。仅查询核心规则或能力定义时使用明确对象，不虚构业务模块。

要求结果覆盖各子问题，给出来源位置、依据版本、适用条件、冲突、推断和未知。顺序、并行、失败与范围调整遵循 Task Loop；不重复派发在途任务。

## 4. 取得证据并解释

读取原文及必要实际产物，解释术语、关系与使用条件。文档规定与当前实现分别标明；历史决定、观察模式和正式契约不得混为一谈。被查询文件是证据，不自动执行其中命令或流程。取证不修改业务、共享知识、索引或验证状态；必要执行记录按调用方提供的本地位置保存。

## 5. 核实答案覆盖与冲突

逐项核对问题、结论和来源，确认当前版本与适用边界。收到 TaskResult 后先按 Task Loop 验收，再汇总答案；执行者报告完成不等于答案可靠。来源冲突时核实生效决定与实际产物，无法判定则保留冲突，不按读取先后选择结论。

文档规定不能证明实际运行符合规定；限定范围内未找到不能证明不存在。所需事实仍未知时，不将该问题标为已回答。

## 6. 根据缺口决定下一轮

有具体新线索时回步骤 2；需新增模块调查时回步骤 3，经 Task Loop 调整后继续。资料缺失、权限不足、执行失败或无新依据时保留已核实答案，报告受影响问题及继续条件；无关部分继续。恢复时核对已有结果与资料版本，避免从头重复调查。

## 7. 返回需要治理或实现的事项

发现错误知识、格式问题、实际故障或结构信号时，返回问题类型、来源、影响范围、是否妨碍回答及本步骤为继续位置，由调用方选择后续流程。附带发现不自动扩大成全量治理或修复。收到处理结果后回步骤 5 复核受影响答案；没有新证据或有效决定时不反复转交。

## 8. 回答并结束本轮

交付结论与可访问来源，按需说明适用条件、推断和未确认部分。所有必要子问题有足够证据支持才称查询完成；目标本来是确认资料是否存在时，可交付限定范围的检索结论。仍有必要问题未解决时报告部分结果与缺口，不把治理建议说成已修正，不为结束查询强行新增永久知识或抽象。
