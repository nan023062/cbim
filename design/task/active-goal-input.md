# 运行中补充的可信目标输入与版本门禁

状态：2026-11-07，Step27 已完成，承接 `ea680de`。上一片已验证队列插入的原运行身份、停止和确认边界；本片接通结构化目标的输入版本，不重复实现插入界面或原生消息队列。

## 已核实的缺口

当前成功 steer 只保存 Runtime 的 requested/accepted 日志，不提升 ScopeGoal 的输入版本或清除审阅。保存 complete/awaiting_user 审阅后插入新要求、随后模型仅结束时，现有最终门禁仍可能沿原审阅完成或停泊。普通问答与业务验收不能混为一谈，不能只依赖模型自行发现新增约束。

## 本片设计

- 独立保存 `scope.activeInputs`，与安全 waiting 的 `continuations` 分开。尝试绑定原 scope/run/queue、稳定插入身份、正文指纹及字节/附件身份；模型不能指定可信来源或确认结果。原始 `goal.input` 不改写。
- 发送前同一调度事务登记 pending，预留正文、输入与决策额度；准备失败不发送。真实 queued 且接受日志落盘后转 accepted，保存匹配正文及日志依据，目标版本和输入版本各加1，保留旧计划和人工约束并清除 review。
- 明确未发送才可 rejected，不升版。发送、日志或保存结果未知保持 pending/unknown，不能冒充未发生、沿旧审阅完成或安全 waiting。只读查询保留，不能通过新的 plan 洗掉未知输入。
- 完整准备、发送和确认作为周期在途操作，由 Auto 在等待前登记。停止立即作用原引擎，关闭周期前等待该操作收口；不重入 Manager.serial 造成自锁，迟到 queued 仍保存接收事实后再取消。
- 重复先查原 scope/run/queue 身份及指纹；accepted 不重发、不重复升版，unknown 不自动重试。重启只读历史，不继续 pending 或恢复原生发送。
- active accepted 与文本/人工 waiting continuations 按输入版本合并验证连续序列，总输入版最多32；真实主轮上限仍独立为32，steer 不新增轮次。目标决策仍累计最多64次，发送前预留接受及必要重规划/审阅额度；尝试历史和正文总量均有界，不截断后冒充原输入。
- 无 plan 的普通对话允许输入版增加而不造计划；有 plan 必须重新规划。pending/unknown 检查必须早于“普通问答无需业务审阅”的完成例外。旧人工决定不跨新输入自动授权。
- 公开严格输出、目标摘要/详情与前端历史同步这些事实；界面区分接收中、待核实和已接收后待重规划，不把 accepted 显示为业务目标达成。旧缺省字段不补写、不改旧日志。
