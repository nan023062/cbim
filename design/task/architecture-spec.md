# 架构评估与认知交付规范

模块类图是经人工 review 并确认的设计规范与约束，包含模块结构及依赖关系，是 Agent 核查实现的架构依据，不是从代码自动生成的现状图。正文用于解释图中的契约与设计理由，不另建重复的依赖索引。代码与类图不一致时记录实现偏差；只有取得人工确认的架构变更决定后，才能修改相应类图与约束。尚未确认的建议或观察不得混入正式类图。

用于架构分析、渐进演进和高影响变更的任务上下文。任务范围、授权、执行与恢复分别遵循 [Task 规范](task-spec.md) 和 [任务基线](task-baseline.md)。本文件定义评估与交付约束，流程选择和调度由调用方安排，不要求读取设计报告。

## 判断与证据

- 先确认职责边界、现有契约与必要约束，再判断具体抽象。允许有理由的独立实现和短期重复，不为减少代码行数强行统一。
- 重复次数、相似度、复杂度与依赖数量只触发调查；须比较共同语义、不变量、变化方向、反例、适用与不适用条件，并比较保持现状、局部修正、复用或重组的成本。
- 评估使用方、性能或专业效果、学习与维护成本、迁移和回归成本。没有新证据时复用仍有效的观察或处置决定，不重复提案。
- 观察、暂缓和驳回均可作为本轮结论，写明理由与复查条件；它们不表示结构问题已经消除。正式抽象不适用时说明依据，不强行复用。
- 代码、测试体系、资源和配置模型按专业语义判断，不要求所有对象都形成基类、接口或通过编译测试。专业能力不足或必要证据缺失时明确缺口。

## 方案、决定与实施边界

- 方案说明目标契约、关键关系、不变量、影响范围、使用方、迁移顺序、验证及回退条件。分析建议不等于实施授权。
- 正式公共契约、稳定层或全局边界变化使用相应负责人的有效决定，绑定具体方案版本和范围；作者身份、岗位名称及 AI 自评不代替批准。已有授权继续有效时不重复索取。
- 稳定层保护仅作用于项目已经明确登记的对象和审批安排，不从复用次数或业务名称自行创建保护清单。涉及已登记对象时核对模块技术审查与架构影响决定；未知影响不当作不涉及。紧急处理须有明确授权、回退及补审约定，不能自行假定存在紧急通道。
- 只使用现有契约不等于修改稳定层。契约不足时向调用方返回缺口，由其组织前置任务；前置结果验收并更新基线后再继续，仅阻塞实际依赖部分。
- 重构前建立行为或效果基线，隔离未授权的新功能变化。替换或废弃时核对全部使用方、兼容要求和迁移状态，满足退出条件后才移除旧入口。
- 实现、适用回归、必要人工审查和知识核验均完成后，才能宣称抽象正式生效；批准但未实施、验证缺失和迁移未完分别报告。

## 认知交付与复查

- 交付包括实际产物、设计意图、已知风险和未知范围。局部修改可用结果段落承载，不强制生成多份文档；高影响变更明确理解与接管负责人。
- 用简图、代表性场景或故障推演说明输入来源、状态或资源归属、关键不变量、失败影响、排查入口及恢复方法。专业任务按 QA 覆盖盲区、美术引用与导入限制、策划规则及玩家效果说明。
- 必要理解确认以负责人实际反馈为依据，不以发送文档、已读标记或 AI 自评代替。关键代码阅读与实际验证不能由风险说明替代，也不承诺风险已穷尽。
- 对需深度复盘的高影响变更，记录负责人、核心实现阅读、代表性故障推演、经验补充、时间或触发条件，以及安排是否得到确认；不擅自承诺一周等固定期限或建立定时任务。
- 业务验收与后续复盘状态分别报告。评估演进效果关注行为保持、变更与维护成本、知识一致性及实际接管表现，不以抽象数量、扫描次数或去重率单独证明改善。
