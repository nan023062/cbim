# 显式业务文件基线与按需复核

状态：2026-11-07 Step14a 已完成并验证，承接 `ca12a79`。本步是原成员检查点恢复的前置能力，不恢复现有已结束的成员。见[验证报告](../verification/artifact-baseline-20261107.md)。

## 可见行为

执行成员通过 `cbim_task_artifact_capture` 提供当前任务进度版本和 1～16 个真实成功工具调用 ID，程序从本轮已核实的 read/write/edit 单文件参数推导文件集。模型不能填写路径、哈希或覆盖率。采集绑定当前角色实例、task/run/plan、知识版本、源回执及副作用代次，保存到原 canonical 日志。

成员详情新增独立的文件基线核实面板。先手动加载该轮基线列表，再明确选定一份复核，显示每个文件“内容一致、已变化、缺失、不可核实”。切换任务/轮次隔离迟到响应，不轮询业务文件，不修改任务状态、原日志或原有执行报告的分页/恢复基线。

## 实现边界

- Core 保存纯 Schema、工具包装及证据规则；Runtime 负责可信身份、并发工具屏障和事件落盘。平台固定工作区根读取文件，Scheduler 独立生成只读报告，Frontend 经 Bridge 展示。
- 同时最多 16 个普通文件，单文件 8 MiB、合计 32 MiB，每轮最多 8 份成功基线。超限、路径越界、`.cbim`、设备路径、ADS、符号链接/目录联接和读取中变化明确拒绝；不以截断数据生成有效哈希。
- 采集期间不能有其他在途/待审批调用，也不放行新工具；采集前后核对进度、副作用代次、停止及知识基线。显式停止取消采集。平台检查打开前后文件身份，外部并发修改只做尽力检测，不声称操作系统隔离。
- `artifact.baseline_captured` 是暂存事实，必须与本次真实成功工具回执匹配才能被报告引用。损坏、缺失或身份不符的记录保持未知；旧日志不补造基线。
- 文件哈希仅证明采集时字节，不证明较早测试针对这些字节，也不证明整个工作区未变。命令影响范围、未覆盖写入、未知副作用及采集后的操作须单独保留。采集工具自身不能作为步骤完成或业务验收证据。
- 核实入口只读、按需，核对日志和图状态前后屏障；不启动模型、不签署人工验收、不据哈希相同恢复旧运行。

## 验收

单元/集成覆盖来源伪造与跨运行、坏授权链、大小/路径边界、并发写入与停止、日志损坏、知识变化、未知命令影响、外部改动/删除、重复读取和跨节点响应。真实 Pi 在临时工作区执行读取与采集；同一打包 Windows EXE 真实点击基线列表与复核，验证外部修改后显示变化、重启无重放以及报告查询没有新模型调用。同步注释、CONTRACT、类图、roadmap 和开发记录后单独提交。
