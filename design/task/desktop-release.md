## 交付与发布通道

- 首个平台为当前工程已验证的 Windows x64。现有 Forge/Vite 和 Pi 打包继续使用，新增 NSIS 每用户安装包，安装目录与 `~/.cbim` 用户数据分离。
- GitHub `nan023062/cbim` 已有旧 Python 内核 `v1.0.0`、`v1.0.2`。桌面应用独立使用 `desktop-v<版本>` 标签，首版为 `desktop-v0.1.0`；不改写旧版本、不让桌面更新器消费内核压缩包，也不抢占旧通道的 latest 标记。
- GitHub Releases 保存安装包、SHA-256、electron-updater 校验清单和公开更新日志；不建设自有更新或反馈服务器。
- 发布仅包含实际通过验证的功能和限制。代码签名情况如实标明，不把未签名安装包描述为可信发布者签名。发布前锁定源码、版本、构建及校验值，附件上传完成后才公开 Release。

## 产品行为

更新程序独立放在 `src/backend/updater/`：发布读取、版本筛选、状态机和 NSIS 适配不得混入运行时资源服务。依赖检查拒绝 updater 引用 main、scheduler-engine 或 core；主程序仅保留装配、IPC 和正常关闭回调。安装产物与下载缓存也独立保存。

1. 正式安装版启动 10 秒后、随后每 30 分钟读取桌面通道的稳定版本，也可手动检查。离线期间不即时推送；开发模式／普通便携包不自动检查安装更新。
2. 软件内提示可用版本；左下角账号菜单展示当前版本，提供“检查／查看更新”和“最近一次更新”。更新弹窗展示日志与手动更新，关闭后回到原页面。检查不需要登录或 GitHub 反馈授权。
3. 用户点击才下载，显示进度；校验完成后用户再次点击重启安装。退出和下次启动不自动安装下载缓存，不强制更新。
4. 安装前按产品正常关闭路径停止任务、排空文件／网络操作；关闭失败时保留当前程序并报告，不越过已有退出门禁。安装不清空用户目录、工程文件或反馈凭据。
5. 正式 APP 预置公开 OAuth Client ID `Ov23liSMDZneBd3gSyTo` 及 `nan023062/cbim`；用户授权自己的 GitHub 账号后，通过对话加号菜单的两项 Skill 按格式提交。成功继续静默，修复及功能变化通过版本日志查看。

## 验收

- 版本筛选：排除旧内核、草稿、预发布、同版本／降级和缺失安装附件；网络错误保留可用信息并允许手动检查。
- 更新状态：检查不下载；下载不安装；重复点击不并发；失败可重试；下载完成后检查不覆盖待安装版本；只接受可信桌面发布地址与匹配版本。
- 安装：真实 NSIS 安装、启动、正常退出；真实旧版到正式版升级，核对版本与既有数据；报告区分本机验收包和公开正式包。
- 反馈：在正式包中完成真实 Device Flow、重启后连接保存，再经真实产品 Skill 创建唯一测试 Issue。使用确定性模型时明确标注；GitHub 连接／发单不可用 HTTP 替身冒充。
- 同步源码注释、受影响类图、协议、路线图与实际验证报告。未通过的线上步骤不标记完成，不重放未知 Issue 创建。

当前实施进度以[路线图](../tool-architecture-roadmap.md)为准；OAuth 操作见[配置指南](github-feedback-setup.md)。

## 后续发新版的操作

2026-11-09 起正式构建强制签名。证书申请、Windows SDK 配置、同版本重发和故障恢复详见[Windows 签名指南](windows-signing.md)。当前尚无证书，不能生成或发布签名版；下面是配置完成后的操作。

1. 将 `package.json` 的版本号增加为新的稳定三段版本，并创建 `design/releases/desktop-v<版本>.md`，只写本版实际完成的修复、改进和新增功能。
2. 完成类型、依赖／架构和相关测试后，提交并冻结干净源码，再执行 `pnpm make:desktop`。产物单独位于 `build/desktop-release/<版本>/signed-<时间>-<随机标识>/`：安装 EXE、blockmap、`latest.yml`、`SHA256SUMS.txt` 和本机构建回执。同版本产物不会被构建脚本静默覆盖。
3. 核对冻结源码、构建内容和真实安装运行，通过后推送对应源码；给该提交创建独立 `desktop-v<版本>` 标签，不移动既有标签。后续发布／验收记录可单独提交，不替换已验收的源码标签。
4. 执行 `pnpm verify:desktop <候选目录>` 重新核对签名、时间戳、发布者与更新摘要，再执行 `pnpm publish:desktop <候选目录>`。工具创建草稿、上传并核对 EXE、blockmap、`latest.yml` 和 `SHA256SUMS.txt` 后公开，保持旧 Python latest。仅本次明确授权的同版本签名重发使用 `--replace`，按签名指南先备份、暂转草稿再替换；原标签不移动。
5. 从上一桌面版本实际检查、下载并点击「停止任务并重启安装」，确认新版本及既有设置／对话保留；记录真实验收证据。不要以“Release 已创建”代替完整客户端升级验证。

客户端联网运行时在启动后和定时间隔检查新版，也可在账号菜单中「检查更新」。这不是独立推送服务：关闭程序或离线时不会收到即时通知。“最近一次更新”无需检查网络即可查看当前版本的内置日志；存在已知新版时展示新版说明并保留当前版本日志。用户先点击「下载更新」，校验后再点击「停止任务并重启安装」。查看日志或点击提醒均不切换原页面，不清空未保存内容。
