# 正式派发显式选择模块 Workflow

状态：2026-11-07，Step23 已完成，承接 `0fe0be3`。正式派发已支持按任务选择模块实际挂载的流程，保持默认历史行为。最终全仓217文件1284项、13项边界、类型/架构及 Windows EXE `20261107-171643` 正常/停止两场通过，见[验收报告](../verification/dispatch-workflow-selection-20261107.md)。

## 交付范围

目标分配、正式派发输入与任务节点共用可选 `workflowSelections: [{moduleId, workflowId}]`。显式数组为 1–50 项，同模块不得重复，模块必须属于该分配或任务。只接受本模块已挂载的 Workflow ID，不接受任意文件路径、正文、版本、哈希或强制 general；当前 Workflow ID 本身是 `.cbim/.../workflows/...` 路径式逻辑标识，不能误用 UUID 或图节点字符限制。允许只覆盖部分模块，其余仍采用原默认首项；旧缺省字段不补空数组。

任务节点保存显式选择，实际固定流程及内容哈希继续由 `ModuleBinding.workflow` 承担。准备时按原选择重新解析并比较完整原绑定；知识版本、挂载关系或正文变化拒绝，不回退首项。相同命令使用原幂等回执，同命令 ID 换选择拒绝。选择只随新计划、新派发保存，已有任务不能通过图更新改选或把缺省改为显式；改选须重新规划并创建新任务。

显式业务 Workflow 只分配给执行角色。主 Agent 仍可在目标分工中列出需要治理知识的模块，但不能为自己声明这项业务执行选择；它不运行该 Workflow，知识提交证据不能代替流程条件。

目标计划、派发、候选审阅、人工来源、检查点预约及消费、未启动后继前置替换共用纯匹配规则：同模块双方同时缺省，或显式 ID 相同。缺省不是通配。人工继续的业务主体纳入排序后的显式选择，不能跨流程继承旧接受；历史无选择主体保持原形状。检查点和依赖替换不能顺便更换流程。

## 实施边界

- Core：选择契约、目标与任务节点、图变化规则、人工主体、检查点及依赖替换的不变量。
- Scheduler：从真实模块知识解析、持久派发、执行准备及当前计划/候选核验；主工具声明和指引说明先查询再选用。
- Frontend：沿用节点详情的真实 Workflow ID 展示；不在界面推断或补造默认选择。

各处同步中文注释与受影响 CONTRACT/ARCHITECTURE。不扩大成员派发权，不修改静态模块负责人模型，不实现任意 Workflow 编排或跨知识版本恢复。

实施发现的前置问题：通过真实知识事务挂载第二份 Workflow 时，严格 JSON 解析产生的无原型对象触发 Ajv `uniqueItems` 比较器的 `valueOf` 假设。兼容处理限定在 Rules 的 Ajv 输入边界，不修改全局严格解析、不关闭唯一性；畸形自有属性引起校验异常时仍拒绝候选并返回可读问题，不能使整个事务抛非业务 TypeError。真实双流程保存、重复项、重复字段及危险自有字段均须回归。

## 验收

单元覆盖第二项选择、部分模块覆盖、旧缺省、跨模块/重复/未挂载、目标与派发不一致、重规划后旧候选与人工接受/检查点/后继不能误匹配、知识变化、命令幂等和历史重开。

真实 Pi 和最终 Windows EXE 使用本机确定性供应商，在同一模块挂载两份流程，正式主调度选择第二份 JSON 结构流程：真实错误文件拒绝交付，修复重验后完成，计划、任务节点、成员准备和证据均绑定第二份；停止和重开不重复运行。通过后更新路线图、开发记录并独立提交。
