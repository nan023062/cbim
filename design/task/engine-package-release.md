# 官方引擎包开发与发布

引擎只由开发者在代码中登记。实现入口在 `src/logic/execution/engines/<id>/package.ts`，`engineAdapter.version` 是包版本；清单的 nativeVersion/旧 version 字段保留上游依赖版本，protocol 是宿主协议。实现、依赖或默认行为改变都应提高包版本，同版不同摘要禁止覆盖。

支持名单及业务/模型声明在 `logic/engines/catalog`，随 R 更新。增加引擎时更新 R、包构建入口与 E；兼容已有宿主协议不改 C。升级已有引擎且不改静态支持策略时，只发布 E。宿主能力或信任根改变仍须相应冷更。

## 构建可审阅候选

提交并冻结源码，运行受影响的引擎单元、契约与实际 SDK 验证，然后：

```powershell
pnpm make:engines pi
pnpm make:engines memory
pnpm sign:engines <候选目录> <当前runtime-cold.json> <下一发布序号> <说明文件> <上一版latest.json>
```

不传引擎 ID 构建全部官方包；传 Codex 时连同它的固定 Pi 依赖构建。同字节依赖仍使用相同摘要，不要求客户端重下。签名私钥沿用 `CBIM_RUNTIME_SIGNING_KEY`，不生成临时生产密钥。首次建立通道可以省略上一版索引；之后必须提供当前公开的已签名索引，避免丢失其他引擎及历史固定依赖。

memory 是自定义 Loop，包内不含厂商 Agent SDK；nativeVersion 与 adapter.version 同版，原生入口就是 adapter.cjs。它与厂商包共同走归档、签名、独立安装和版本不可变校验，不额外设计用户脚本或 npm 安装入口。

签名命令核查 Git 冻结、归档大小/摘要、展开文件清单、版本不可变、依赖闭包、公钥与发布序号。它只生成候选，不上传或启用公开通道。候选输出包含包版本、上游版本、摘要和 `published:false`。

## 发布顺序与验证

发布前审核候选和现有公开索引，确认没有并发发布抢占序号。不可变 ZIP 先上传到本仓库 `runtime-engines` Release；不得覆盖同名内容。核对公开附件的实际大小和 SHA-256 后，最后更新同一 Release 的 `latest.json`。下载地址由客户端固定为本仓库，不接受用户提供的来源。

发布阶段还须完成干净安装、同包离线复用、依赖锁、升级失败保留旧版、历史绑定以及固定 C/R 的 E 单独升级验收；单元测试不代替真实公开发布。首次部署通用宿主需新 C；旧冷壳不具备此协议。引擎准备和切换不自动恢复或重启业务任务。

当前命令保留完整已签名历史，最多 256 个版本；达到上限时应设计并验证保留历史信任证明的归档迁移，不能手工删记录或复用发布序号。生产发布仍遵循既有签名与制品审核流程，本文不是发布授权。
