## 切片与依赖

1. **Step53 / R12-A（已完成）：平台执行器。** 按官方机制创建临时唯一 LPAC；本机 Node 的 Winsock 初始化需要固定 `registryRead`，零能力探针以 WSAStartup 10107 失败，因此明确保留这项只读系统资源能力，仍不授予任何网络 capability。只给自有暂存文件赋权，不改原工程或用户目录 ACL。冻结真实执行器与参数，运行前验证进程 Token 和 Job，实际越界探针及打包 EXE 证明平台边界。资源清理失败必须保留可查状态，不报告完全成功。
2. **Step54 / R12-B1（已完成）：运行授权与装配。** 冻结范围、全部模块一致、可信读取与 Node、原受控写边界、权限审批、未知写屏障和物理收尾均已接通。相关178/178及最终EXE三场通过，见[报告](../verification/scoped-member-execution-20261108.md)。
3. **Step55 / R12-B2（已完成）：孤儿核实与清理。** 可信持久身份绑定原任务／运行／调用；只读核实后显式清理原资源，拒绝仅凭临时owner/PID猜测或重放。
4. **R09-C：程序验证。** 指定测试／构建能力绑定同一输入、执行器、实际退出和结果；失败、停止、环境不支持均不能满足出口。

## Step53 验收

- 真实普通进程可读写的自有哨兵，在隔离进程中被 OS 拒绝；允许快照读取和暂存输出确实可用，不能只验证“所有访问均失败”。
- 原始业务路径、只读快照、越界链接、外部网络／本机监听、环境变量和启动句柄分别测试；仅受支持平台可返回可用。
- 后代持续运行、主动超时、取消及宿主退出后核实实际进程消失；拒绝未受 Job 管理的启动。
- 类型、依赖、架构和相关回归通过；真实打包的 Windows EXE 调用同一平台实现。中文注释、CONTRACT 和架构类图同步。
- R12 保持部分完成，直到细粒度授权与实际执行链共同验收；本片不宣称任意系统工具、完整 Windows 资源或其它平台已覆盖。

官方依据：[AppContainer 启动及 LPAC](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)、[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[进程创建属性](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute)。Step53实际结果见[验收报告](../verification/execution-isolation-platform-20261108.md)；R12-B1/B2均已有独立验收，R09-C仍仅保留计划。

## Step54 接续

冻结任务与真实执行链已验收，范围及具体限制见[成员执行计划](scoped-member-execution.md)。Step55已补原隔离来源核实／清理；R12仍保留通用资源授权与R13的实际衔接；不以可选范围模式代表历史原生操作也有隔离。
