# 全局运行准入与可见等待

## 行为与范围

- Application 持有唯一 `GlobalRunAdmission`，所有桌面主轮和成员轮共同受限。默认上限 4，可在设置中改为 1～32；先可靠保存再生效。降低额度不停止已有运行，只限制新准入。
- 执行前同步检查全局名额与现有工作区租约，领取成功才占用；等待者不持全局名额、工作区锁、run 或模型请求。原角色/知识版本/任务领取检查继续在事务内执行。
- 已受理的成员任务和主结果回注用稳定请求键、工作区装配代际和 FIFO 票据等待。跳过暂时本地冲突的票据允许其他工作区推进；同工作区更早的写任务阻止后来读任务持续插队。
- 新主聊天尚无持久首轮排队意图，额度不足明确未受理并保留草稿。显式补充/核实/重规划也须在意图提交前取得名额；已受理未知结果不能因配额错误而重新执行。现有普通消息队列在准入失败时暂停并保留条目。
- 释放、配置变化和本地租约释放仅唤醒原协调器重新核实；不直接执行模型。取消、关闭和批次退出撤销等待票据；迟到回调不能重建旧代任务。重启不从进程内票据恢复执行。
- 配额与等待使用独立版本游标，只读界面不扫描日志。设置显示占用与上限，会话显示匹配当前 root 的等待原因；等待状态不冒充持久的用户输入 waiting，也不新增工作时长或用量。

## 模块边界

- Core runtime：可序列化策略、请求、票据、占用和游标契约。
- Scheduler runtime：应用级同步准入器；仅通过注入的本地租约端口检查资格，没有平台、存储或前端依赖。
- Scheduler execution：已有工作区租约、主轮启动、成员领取和自动协作接入；保留原版本与安全结算约束。
- Main：应用单例装配、设置持久化及受控 IPC；Bridge 公开只读快照及设置请求。
- Frontend：设置编辑、实时占用及会话等待提示；配额拒绝保留输入，不推断任务已启动。

## 验收

单元/集成覆盖跨工作区额度、主成员共同计数、FIFO 和写入防饥饿、重复/变参请求、下降不逐出、领取失败不漏槽、取消/关闭/迟到唤醒、设置版本及写盘失败、等待不产生日志或 token、重启不执行。

同一最终 Windows EXE 与真实 Pi 子进程验证：两个工作区共享配额，活动成员占满名额后另一个已受理协作等待，释放后继续；在等待期间停止则不再启动；设置保存并重开保留；新聊天不足保留草稿且无新周期。模型来自本机确定性服务，业务自主质量另验。
