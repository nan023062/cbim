# 原治理与责任命令的保存核实

Step39 / R03-D2，2026-11-08 约定范围已完成；[实际验证](../verification/governance-effect-verification-20261108.md)。承接 Step38（4db3a27）。本片在既有影响面板、处置附录与新周期关联中核实三个原主命令，不引入批准、重放或自动恢复入口。

## 支持矩阵

| 原调用 | 精确依据 | 可说明的事实与限制 |
| --- | --- | --- |
| cbim_governance_observe | 原 canonical 主身份、实际严格参数、稳定 commandId、唯一治理账本的原命令指纹与观察 | 只说明原观察已保存，不说明提案、批准或知识修改 |
| cbim_governance_propose | 同一原主身份、原请求与来源、唯一治理账本的提案记录 | 只说明原提案已保存，不说明已经批准、实施或完成迁移 |
| cbim_module_owner_change_commit | 原 root/scope/run/tool 身份、实际参数、唯一 DispatchStore 中原命令回执与不可变责任事件 | 只说明原责任变更已保存，不说明今日负责人、任务交接或派发切换 |
| 旧日志缺来源、错参数、缺记录、存储未知 | 明确 unsupported / absent / unverifiable | 查无不证明未执行；不以当前相似记录冒领原命令 |

受控文件、旧 knowledge_refresh、任意 shell 及外部副作用仍按 R03 已有支持矩阵分别推进，本片不宣称整个 R03 完成。

## 实施与验收

1. 定义纯公开摘要与后端原请求解析；原身份只从已核对的主 canonical 和唯一周期取得，不接受页面提供 actor/commandId。
2. 治理读取借用同一知识串行队列中的已校验原账本；责任读取原事件及原回执，严格核实例、完整输入、来源、指纹及回执一致。不调用写入口、当前预览或另一份 Store。
3. 两次读取核摘要稳定；原调用结果保持。旧处置不补字段、不改 basis；所有正文、私有路径和授权数据不进入公开报告。
4. 覆盖错误绑定、参数/回执损坏、缺失、停止、读取变化及重开；实际 Pi 保存后丢回包，核实和显式处置不重放。最终 Windows EXE 验证原失败与已保存分开显示、保存处置、重开只读及零新增模型请求。
5. 同步中文注释、CONTRACT、目录类图、roadmap 与实际开发记录；通过类型、依赖、架构和相关回归后独立本地提交，不推送。第 9 组仅保留计划。
