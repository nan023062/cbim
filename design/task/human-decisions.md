# 人工决定与显式接续

状态：2026-11-07 Step15a 已提交 `1ff5fc2`；Step15b 已完成并验证。属于阶段二业务验收剩余项，与阶段五调度协作衔接。Step15a 原验证见[记录](../verification/human-decisions-20261107.md)；本步 921 项全量及定向复测、同一 EXE 四场景结果见[Step15b 验证](../verification/human-continuation-20261107.md)。

## 本步交付

当前安全 waiting 的目标卡中，用户选择人工验收项，查看真实成员候选并明确选择文件基线，按需核实后提交“接受 / 拒绝 / 要求补证”及意见。可信桌面入口保存不可变记录和精确依据；两处目标卡共享草稿、冻结请求及结果，历史通过已有周期增量展示。

Step15a 的保存操作只完成决定持久化，不消费等待、不运行模型、不改写 goal/review/任务结果，不把“已记录接受”显示成整体目标已完成。Step15b 已接独立“按已保存决定继续”、主调度重新审阅及新任务返工，保存与继续保持分离。

## 决定依据与边界

- 只处理当前 waiting 周期中的 human criterion。绑定 wait、原始输入/计划/审阅版本、验收原文、知识版本、图游标、精确成员 task/run/result 及 canonical 指纹；旧无来源或坏日志不能补签。
- preview 读取真实日志和知识，列出候选基线但不默认选择。用户明确选择后才观察文件，记录选定范围、字节及不可核实限制。basis 使用规范化内容指纹，排除读取时间与独立决定序列；决定并发使用 expectedDecisionRevision。
- accept 要求该项全部真实候选均明确选定当前有效基线且文件全部匹配，没有未决或 unknown 工具结果。已成功命令的影响集合不能完整枚举时，作为不可移除限制保存；它不同于工具结果未知，也不把本次接受扩张为整个工作区或所有副作用已验证。
- reject/request_evidence 可不选文件，或针对文件变化/缺失提出意见；仍须可信候选与身份。知识、候选、日志或选定观察在预览后变化使旧 basis 失效，重新核实后再提交。
- 每周期最多 64 条追加记录。相同命令及内容幂等，不同内容冲突；同 criterion、同 basis 的新决定可以显式替代旧决定，历史保留。记录不能被模型构造或通过普通聊天文字签署。
- actor 由可信桌面入口注入 `local_desktop / explicit_submit`，只证明本机明确提交；无登录认证时不冒称已认证用户或组织审批。明确选择和提交即为确认，不叠加没有身份增益的二次弹窗。
- 保存不解除普通队列暂停，不改变权限，也不恢复成员。通信结果未知只查询/重试冻结的原命令；重启恢复记录不自动发送新决定或模型请求。
- 文件仍有界读取（合计最多 16 个、单文件 8 MiB、总计 32 MiB），前后核实不能提供外部进程的原子文件快照。当前只覆盖成员成果；跨轮主 Agent 知识治理证据及通用审批身份需后续独立接通。

## 实施分工

Core tasks 保存严格契约、追加不变量、持久化与 scope 摘要；Scheduler 复用完整成员候选核验和文件基线规则，重建 preview/提交依据。Main 装配受控日志、只读占用与文件端口，IPC 验证桌面来源；不把人工提交注册成模型工具。Bridge 只公开序列化记录；Frontend 使用一个会话级控制器，目标卡及根详情共用，不轮询文件或重复提交。

## 验收与接续

单元覆盖严格请求、模型伪造字段、过期知识/日志/文件、并发 CAS、重复命令、相同依据替代、停止与保存竞争、坏本机记录和通信未知；确认 human satisfied 与完成门禁仍不被绕过。

真实 Pi 生成可核实候选并进入 waiting；最终同一 Windows EXE 实际选择和提交三类决定，检查双视图同步、草稿保留、原图/goal/日志不变、重启历史保留且模型请求不增加。完成后同步注释、CONTRACT、类图、roadmap 和开发记录，独立 Git 提交。

显式继续已保留原输入与计划、绑定真实决定与新运行并复用预算/停止门禁；接受仍由主调度审阅并重新核实，拒绝则派新任务，不篡改旧候选或重播旧业务。返工新等待提供清除旧选择及重新核实新成果，未知提交保持冻结。

## Step15b 当前实施边界

新增独立 `loop.humanContinue / loop.humanContinuation`。请求只携带当前等待、目标/输入/决定版本、最新决定 ID 集合、稳定命令及明确模型/权限，不接自由正文、actor 或客户端证明。界面列出本等待每项最新决定，用户明确点击继续；普通补充或队列不生成此来源。

接续记录与旧文本补充共用有序 `scope.continuations`，新分支标记 `kind:human_decisions`，不伪造 input.message；保存旧等待、决定集合、原业务主体和可信新 run。原始输入及历史保持不变，输入版本递增并清除旧审阅，主调度必须重新规划。系统通过 Pi custom 消息转交已保存意见，公开对话显示系统接续提示。

只消费当前等待中每个验收项跨 basis 的最新记录全集，不能挑旧接受跳过新拒绝。先核候选、知识和决定版本；接受额外核实所选文件。新审阅引用 `human-decision` 必须来自当前输入版本实际消费的意图，并保持对应业务主体、候选及文件有效；审阅和最终完成均复核。普通文本补充、另一次等待或主体改变不自动继承旧批准。

拒绝/补证仍不满足人工项。主调度创建真实新任务；若声明替代被拒候选，必须引用本次消费的精确决定和真实后续结果，旧结果及人工意见不改写。当前没有决定的人工项仍需等待。Step50 / R08已接通[跨等待人工意见核验与重新决定](human-decision-applicability.md)，明确显示来源与产物差异、保留新旧关联；跨等待不自动继承接受，实际验证见[报告](../verification/human-decision-applicability-20261108.md)。

复用运行前原子受理、全局准入、周期软限额和停止屏障。受理前额度不足保留等待；受理后失败保留意图和真实运行，不回滚重放。接续双卡共享冻结请求，通信未知只查询原命令，重开不自动启动。

本轮测试覆盖同命令一次启动、新拒绝使旧请求失效、预算/停止竞争、普通补充不批准、主体变化/过期候选/文件变化拒绝完成、拒绝与补证产生新任务并保留历史；最终打包桌面实测接受继续、返工、过期依据及重开，不以模型文本代替真实结果。同步注释/类图/进度并单独提交。
