# 人工决定与显式接续

状态：2026-11-07 Step15a 已完成，承接成员检查点 `6d1859d`；Step15b 待实施。属于阶段二业务验收剩余项，与阶段五调度协作衔接。全量 159 文件、877 项和同一 Windows EXE 四个场景通过，见[验证记录](../verification/human-decisions-20261107.md)。

## 本步交付

当前安全 waiting 的目标卡中，用户选择人工验收项，查看真实成员候选并明确选择文件基线，按需核实后提交“接受 / 拒绝 / 要求补证”及意见。可信桌面入口保存不可变记录和精确依据；两处目标卡共享草稿、冻结请求及结果，历史通过已有周期增量展示。

Step15a 只完成决定持久化，不消费等待、不运行模型、不改写 goal/review/任务结果，不把“已记录接受”显示成整体目标已完成。Step15b 再接“按已保存决定继续”、主调度重新审阅及新任务返工，单独验证并提交。

## 决定依据与边界

- 只处理当前 waiting 周期中的 human criterion。绑定 wait、原始输入/计划/审阅版本、验收原文、知识版本、图游标、精确成员 task/run/result 及 canonical 指纹；旧无来源或坏日志不能补签。
- preview 读取真实日志和知识，列出候选基线但不默认选择。用户明确选择后才观察文件，记录选定范围、字节及不可核实限制。basis 使用规范化内容指纹，排除读取时间与独立决定序列；决定并发使用 expectedDecisionRevision。
- accept 要求该项全部真实候选均明确选定当前有效基线且文件全部匹配，没有未决或 unknown 工具结果。已成功命令的影响集合不能完整枚举时，作为不可移除限制保存；它不同于工具结果未知，也不把本次接受扩张为整个工作区或所有副作用已验证。
- reject/request_evidence 可不选文件，或针对文件变化/缺失提出意见；仍须可信候选与身份。知识、候选、日志或选定观察在预览后变化使旧 basis 失效，重新核实后再提交。
- 每周期最多 64 条追加记录。相同命令及内容幂等，不同内容冲突；同 criterion、同 basis 的新决定可以显式替代旧决定，历史保留。记录不能被模型构造或通过普通聊天文字签署。
- actor 由可信桌面入口注入 `local_desktop / explicit_submit`，只证明本机明确提交；无登录认证时不冒称已认证用户或组织审批。明确选择和提交即为确认，不叠加没有身份增益的二次弹窗。
- 保存不解除普通队列暂停，不改变权限，也不恢复成员。通信结果未知只查询/重试冻结的原命令；重启恢复记录不自动发送新决定或模型请求。
- 文件仍有界读取（合计最多 16 个、单文件 8 MiB、总计 32 MiB），前后核实不能提供外部进程的原子文件快照。当前只覆盖成员成果；跨轮主 Agent 知识治理证据及通用审批身份需后续独立接通。

## 实施分工

Core tasks 保存严格契约、追加不变量、持久化与 scope 摘要；Scheduler 复用完整成员候选核验和文件基线规则，重建 preview/提交依据。Main 装配受控日志、只读占用与文件端口，IPC 验证桌面来源；不把人工提交注册成模型工具。Bridge 只公开序列化记录；Frontend 使用一个会话级控制器，目标卡及根详情共用，不轮询文件或重复提交。

## 验收与接续

单元覆盖严格请求、模型伪造字段、过期知识/日志/文件、并发 CAS、重复命令、相同依据替代、停止与保存竞争、坏本机记录和通信未知；确认 human satisfied 与完成门禁仍不被绕过。

真实 Pi 生成可核实候选并进入 waiting；最终同一 Windows EXE 实际选择和提交三类决定，检查双视图同步、草稿保留、原图/goal/日志不变、重启历史保留且模型请求不增加。完成后同步注释、CONTRACT、类图、roadmap 和开发记录，独立 Git 提交。
