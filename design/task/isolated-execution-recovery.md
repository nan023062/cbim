# 原隔离执行的核实与清理

日期：2026-11-08。Step55 / R12-B2，承接本地提交 `fada1b6`。实施前计划；实际结果另写验证报告。

## 交付目标

正式范围成员的每次 Node 执行，在创建平台资源和启动脚本之前保存可信私有记录，绑定原任务／运行／调用、可靠授权序号、输入与范围摘要、宿主创建时间、执行身份及原暂存目录身份。记录不含凭据或业务正文，旧运行不补造记录。

桌面在原成员运行中提供显式核实和清理：先验证原 canonical 授权与私有记录，再查询真实宿主及命名 Job。PID 数字相同但创建时间不同不能认作原宿主；访问拒绝、来源缺失或目录身份改变均保留未知。核实不启动模型、不恢复任务、不写日志或自动清理。

清理只处理该记录确定拥有的 profile 与暂存目录。必须确认原宿主已退出、原 Job 无活动进程，并再次核对原报告版本及目录身份；仍存活的宿主交给原停止／收尾链。使用固定 Win32 句柄删除原对象，拒绝链接、目录替换和越界，不按用户或模型传入路径递归删除。清理请求先可靠登记，再操作；中断后可核实原清理，不重放程序、不改变原业务结果。

本次采用独立平台生命周期记录，主任务状态仍以原 Dispatch 日志为准；两者不宣称跨文件原子事务。记录损坏、无来源旧临时目录、不同 Windows 登录会话或物理终止不明时不自动回收。文件系统与账户的信任边界仍为当前本机用户；不宣称防御同用户恶意程序篡改整个私有数据库。

## 实施边界

- Core 只定义授权和公开核实协议；Main 负责实际 Windows 身份、记录及资源操作，Bridge 只导出公开 DTO。
- 私有记录保存准备、启动前、物理收尾与显式清理事实；不可将工具失败或找不到 PID 当成未执行。
- 命名 Job 使用当前 Windows 会话，创建时拒绝已有同名对象；核实前先确认原宿主已退出，避免观察者提前持 Job 句柄改变原 KILL_ON_JOB_CLOSE 行为。
- 正常执行继续原自动收尾，桌面清理针对可靠识别的残留；清理成功不改写旧 failed/interrupted，也不生成验收通过或自动重新派发。
- 未核实物理收尾阻断新副作用和交付，保留原只读核实；关闭重试只收尾原资源。
