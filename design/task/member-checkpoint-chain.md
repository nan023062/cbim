# Step45 / R05-B：同任务多段检查点

状态：本片已完成并验证，承接 Step44（75733ee）。初轮全仓2023/2025，修正两项后相关21文件141/141及最终EXE三个场景通过；未重复全仓。见[验证报告](../verification/member-checkpoint-chain-20261108.md)和[R05支持范围](member-checkpoint-support.md)。

## 本片行为与约束

- 同任务最多16个可靠检查点，每个运行最多提交一个；每个检查点最多预约并消费一次。每次续执行仍创建新 run、提升一次租约，保留原 task/实例/通道、岗位、权限、模型、知识和前置。
- 公开 checkpoints 只追加；保留 resumeRequest 为最新预约，旧预约逐项进入只追加的 resumeHistory，旧单段记录不补造字段。Store 提交与重放均核完整前缀、顺序、唯一信封及真实来源；模型不能提供 run、路径或新权限。
- 每段必须具有自己的完整成功工具日志、文件基线、正常终态及 native 指纹。续执行核全部原 canonical 和最新 native；文件按各段最后一次触及的已核实事实合并，旧段未再触及的文件仍受保护，不能只检查最后一段文件。文件检查不代表全工作区或业务验收。
- 已消费的历史只读；只有最新且尚未消费的检查点可等待、预约或明确放弃。多段后的持久等待仍需完整未领取后继清单，跨重启不自动执行。放弃后可沿已有真实候选替换流程接替，不改原历史。
- 继续、停止、放弃与实际领取竞争保持一次事务裁决；未知/失败/求助/关闭记录不获得恢复资格。达到段数上限不能再暂存检查点，原正常交付仍可按证据完成。

## 实施与验收

1. 分离纯检查点链和预约选择，更新图 Schema、图归并、联合运行/信封/放弃/等待不变量；保持文件依赖单向。
2. 运行时仅对有明确剩余额度的正式成员提供检查点；调度结算与预约、实际领取三处独立核验，原生来源不依靠公开模型字段。
3. 主工具提示和成员历史界面说明逐段状态，按所选运行显示对应检查点及预约，不把已消费的旧段显示为可执行。
4. 真 Store/运行时测试至少覆盖两次检查点、三段同身份运行、预约重发与重复消费、旧证据篡改、累计文件变化、停止/交接/重放及旧记录兼容。真实 Pi 验证第二次持久等待后重启继续、停止、明确放弃。
5. 同步中文注释、CONTRACT 与受影响目录类图；类型、架构、相关回归通过后冻结源码并生成 Windows EXE，做实际桌面操作及重开验证。记录确定性模型来源、失败及修复和指纹。
6. 完成后立即更新 roadmap、开发记录和 R05 支持范围，独立本地提交、不推送。第1–8组继续；第9组仅保留计划。
