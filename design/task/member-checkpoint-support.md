# R05 成员生命周期支持范围

当前实现由 Step14b 的可靠检查点、Step34 的显式交接、Step43 的真实候选替换、Step44 的持久等待和 Step45 的多段检查点共同组成。Step45 的初轮冻结全仓、两项失败修正后的相关回归及最终三场EXE均见[本步报告](../verification/member-checkpoint-chain-20261108.md)，不将初轮失败记为通过。R05约定的可靠生命周期范围已完成；下表保留实际支持与拒绝域。

## 已接通的生命周期

| 对象或动作 | 支持范围 | 真实边界与证据 |
| --- | --- | --- |
| 成员安全停泊 | 正式业务成员每运行最多一个可靠检查点，同任务最多16个 | 全部原工具必须可靠结束，触及文件有完整基线，原生会话有受管指纹；暂存后不得继续执行工具或交付 |
| 同周期继续 | 主调度明确预约最新未消费检查点，创建新 run 并递增租约 | 同一检查点只消费一次，重复命令返回原回执；task、实例、通道、原岗位、权限、模型和冻结前置不变 |
| 持久等待 | 主调度明确列出全部可靠检查点及其未领取后继，进入安全 waiting | 释放运行占用；重启只保留等待，不启动模型、预约或派发；旧等待不补造 memberPause |
| 重启后继续 | 用户通过“补充并继续”明确受理，先重新核实，再启动主轮 | 原知识、岗位配置、权限、canonical、native 和累计文件变化会拒绝；失败不消费等待，主轮仍需明确预约原成员 |
| 多次等待与继续 | 每段有独立检查点、证明、预约与消费记录，可重复持久等待 | 历史记录只追加；最新预约保留在 resumeRequest，先前预约保留在 resumeHistory；旧单段数据不要求补字段 |
| 累计文件保护 | 各段已核实文件按路径合并，最后触及的可靠事实覆盖此前事实 | 早期未再触及的文件仍检查；每批最多16文件/32 MiB，最多16段、累计至多256个路径，所有批次共享15秒期限；超时、缺失或变化明确拒绝 |
| 停止 | 持久等待或继续竞争时通过原停止协议裁决 | 封存最新检查点和未领取意图，原历史保持；停止不是暂停后可复活状态 |
| 显式交接 | 当前主调度明确放弃最新待办或其未领取预约 | 原任务取消、原运行和证明保留；已消费历史仍显示已续执行，不能把旧段改成新放弃对象 |
| 交接后的业务接替 | 当前岗位另建任务，以真实新候选替换尚未启动后继的依赖 | 原身份不转交新权限；不重写旧候选或既有执行事实；复用 R02/R04 的核实与事务协议 |
| 达到检查点上限 | 第17段可按本轮真实证据正常交付 | 不再提供检查点工具，不丢弃前16段记录，也不重新开始计数 |

## 明确不赋予恢复资格的对象

- 已失败、求助、普通取消、interrupted、closed、未知副作用或损坏日志不会因本协议恢复旧运行。已有异常核实与独立重规划沿 R03 处理，原状态不改写成成功。
- 检查点仅覆盖受支持的可靠文件操作与有界文件事实。命令、动态目录查询、额外知识查询、未覆盖外部操作等不能生成本协议的可靠检查点；这不是全工作区快照、完整产物验收或进程快照。
- 原知识、岗位、模型、权限或原生记录变化不能自动迁移旧链。可明确结束旧待办并另建当前任务，不能刷新旧证明后继续。
- 已预约但未消费的最新检查点不能再次停泊为安全等待；必须先按现有领取或放弃协议处理。主调度不能遗漏仍活动或不属于检查点后继的任务来制造安全等待。
- 旧 Workflow、外部网络任务和任意暂停中的进程不因 R05 自动获得恢复能力。Workflow 共享成员机制的接线归 R10，外部通道仍需相应可靠契约。

这些边界保留 R05 的完整约定：等待释放占用、显式交接、逐段一次消费、重启后重新核实及拒绝复活不可靠记录。R03 的通用异常、R06 的逐请求预算及后续工作没有被本表划为已完成；第9组仍仅保留计划。
