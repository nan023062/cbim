# 成员检查点与同周期一次续执行

状态：2026-11-07 Step14b 已完成，承接文件基线 `0d51df6`。本片只覆盖同一活动调度周期内的一次合作式检查点及一次续执行。全量 155 文件、841 项通过；Windows EXE `20261107-095848` 正常、停止、重启三个场景通过，见[验证报告](../verification/member-checkpoint-20261107.md)。

## 可见目标

成员完成一段有明确文件边界的工作后，请求保存检查点并正常结束当前运行。程序核实成功回执、完整日志、原生会话及文件基线后，将任务标为“已保存检查点”，释放模型名额和业务锁，保留 task、角色实例与会话身份。

主 Agent 明确提出续执行，先保存待续请求；主轮结束后，调度器再次核实上下文、权限、知识、文件、额度和准入，创建同任务的新 run。旧运行及检查点不可变，旧步骤证据失效；后续候选必须使用新运行的真实验证。未启动依赖后继重新纳入当前批次。

## 协议和边界

- 执行成员专属 `cbim_task_checkpoint`：显式当前进度版本、已确认基线 ID 和原因。只暂存意图并禁止后续工具；无在途工具或审批才接受。引擎正常完成且 close 成功之后，才可确认为检查点，不能将 abort 当停泊。
- 主调度专属续执行工具：显式目标 task、checkpoint、节点/图/目标版本及原因；可信闭包提供 scope、主 run 和命令身份。新 assignment 保存预约；新 DispatchRun 的 resumeFrom 是唯一消费事实，容量等待不消费。
- 当前片最多一次检查点及一次续执行；goal、模块、角色、验收、计划结构、知识、权限及原生历史不变。保留步骤结构但清除旧证据与候选。普通 startMember 不放宽为通用恢复入口。
- 只支持成功且全部实际路径可枚举的 read/write/edit，以及明确列名的任务 plan/step/inspect/artifact_capture 维护工具；所有文件路径由最新确认基线覆盖。启动时已冻结的团队/模块知识可使用，运行中额外知识查询暂未纳入资格，不能仅凭工具名前缀或 effects 推定固定来源。bash、grep/find/ls 动态集合、未知外部工具、失败或未确认副作用明确拒绝。文件数及字节沿用 Step14a 限制；其 impact 枚举不是恢复授权。
- 原生文件指纹在引擎真正关闭后记录，领取及发模型前再次核实；文件、知识、Workflow、前置候选变化拒绝续执行。模型提供的路径、哈希或判断不能替代程序核实。
- checkpointed 与待续请求都是未完工作，阻止 completed/awaiting_user。停止或关闭封存任务及待续信封，保留历史；重启沿用 active 周期 interrupted 规则，不自动重播或跨重启续执行。
- 旧 help、失败、取消、interrupted、closed、released 均不复活。续执行核实失败不创建 run、不消费检查点；同周期放弃检查点并改派须后续独立协议。本片不签署人工验收，也不将旧“本次全部通过”权限继承到新运行。

## 模块分工

Core tasks 定义检查点、预约、消费事实、纯证据规则与不可变约束；Core brain 在真实运行中暂存和封闭工具，Pi 接入专用续执行。Scheduler 负责正常关闭后的确认、主调度工具、批次与准入、周期门禁及封存。Main 提供受控文件/原生历史端口。Frontend 经 Bridge 展示节点检查点和新旧运行关系；静态团队/业务图不承担动态状态。
