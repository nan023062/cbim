# 成员求助与主调度补做

状态：2026-11-07 已实现，承接正式业务重规划 `7536c09`。本文件界定本轮切片，实际验证与局限见[本步报告](../verification/member-help-20261107.md)。

## 目标与边界

执行者能向自己的主调度结构化报告缺口，结束当前执行并释放占用，由主 Agent 在同一目标周期内判断补做或安全等待用户。只有主 Agent 派工；不把 `ask_user_question` 挂起等待主回复，不重开已有运行，不让成员选择收件人或授予权限。

本轮不实现原成员 checkpoint/resume、对等成员聊天、复杂依赖重连或任务子树取消。有未启动依赖任务时继续保留现有安全等待门禁，不能为展示等待而放宽证据规则。

## 已实现契约

1. 成员专属 `cbim_task_help` 接受有界、严格结构的种类、原因、问题及已尝试工具调用引用。工作区、任务、周期、运行、成员与调用身份由可信运行环境绑定，模型不能指定或伪造。
2. 工具立即返回标准 `jsonToolResult` 的 staged 信息，由统一工具通道生成回执；不等待主 Agent，也不新增第二套授权回执。同一运行只能有一份不可变求助，重复调用 ID 拒绝。请求时有其它在途工具或审批则拒绝；参数/引用在落盘前校验失败可待旧调用结束后用新 ID 修正，开始落盘后不重放。成功暂存后禁止新工具；明确拒绝的新调用不会反过来破坏已有交接。
3. 求助暂存事件只是本轮声明。成员引擎正常完成并关闭后，结算从 canonical 日志重新核对绑定、成功工具回执及输入/结果哈希、无未知操作和后续副作用。只有核验通过才原子保存 `blocked + help`、独立帮助信封、运行终态及清除活动占用。取消、失败、中断、坏日志均不伪造安全交接。
4. 帮助记录与交付 result 互斥且不可改写。帮助信封仅发往原主调度，可靠回注后才能确认收件；回注是成员数据，不是用户指令或授权。旧信封、关闭周期或重启不自动产生新运行。
5. 主调度按真实缺口重新规划；需要补做时派新任务和新实例，用新成功候选替代旧 blocked 任务，再通过原目标完成门禁。没有待执行依赖且确需用户输入时可进入已有安全 waiting；人工验收项仍不可伪造或删减。
6. 界面分别显示“需要主调度协助”和真实的执行终态；本轮结束后成员空闲，帮助记录说明当时已交接事实，不冒称原成员已经实现可恢复停泊。任务节点、详情与主对话成员记录共享事实，不增加恢复或越权按钮。

## 模块分工

- `logic/tasks/rules`：严格请求、帮助记录与信封，图及持久化不变量。
- `logic/execution/rules` 与 Pi：真实调用身份、暂存事件、标准回执、在途与暂存后工具门禁。
- `logic/team/runtime 与 logic/dispatch/runtime`：canonical 结算、可靠信封、释放占用后的主调度回注与补做；不让等待主回复占住成员租约。
- `view/tasks` 与对话：只读事实展示与任务节点状态，保持静态图和动态任务图边界。

## 本轮验收

- 单元/领域：非成员和跨身份拒绝、严格参数、重复调用/结算/确认、并行在途工具与迟到副作用、坏日志/未知回执、停止及关闭竞争；持久重放不能补造 help 或将其变成交付候选。
- 真实 Pi：成员真实写一次后求助，正常终态释放占用，主收到结构化帮助后新派任务，完成真实验证并审阅；逐次权限不因求助而提升。另一流程无待执行依赖时明确等待用户。
- 同一打包 EXE：主对话和任务图显示真实求助，补做使用新节点/实例，停止不生成可消费安全求助，重开不自动重放；保留草稿、队列、原日志及原人工约束。
- 完成后同步注释、CONTRACT、目录类图、路线图和验证报告，单独 Git 提交。本机确定性模型不替代在线业务质量验证。
