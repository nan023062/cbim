状态：2026-11-07，Step21 本片已完成，承接 `a096a95`。覆盖已实际装配的执行计划、步骤、交付和查询四工具，以及正式成员专属的求助、文件基线、检查点三工具。验证与边界见[报告](../verification/member-tool-output-contracts-20261107.md)。

## 本片范围

- 复用既有工具回执、Workflow、求助、基线和检查点协议，补真实 TaskProgress 与查询结果 Schema，不给旧计划补造 workspace/run 或验收身份。
- 普通运行及主运行也能有执行进度，四工具绑定真实 workspace/task/run；只有三个正式成员工具要求完整成员实例、通道、租约和计划版本。
- 领域操作后只序列化一次，核对同一原 wire、可信身份、请求及保存前冻结的依据。输出错误不能被默认值、裁剪字段或二次编码修复成成功。
- 保存成功后的坏回包仍保留已提交版本、事件及求助/检查点交接门闩，不回滚、不重试。文件采集只是临时锁，按既有工具结束事件释放；失败回执不能使暂存基线生效，也不自动重采。保存本身失败沿用原异常语义；旧版本重发不能覆盖新状态。
- 当前运行的有效回执才能进入进度证据；保持副作用代次、迟到读取和 Workflow 指定工具的现有约束。专业验证与人工验收仍不能由工具返回结构代替。
- 对外列出真实输出、副作用及取消/恢复边界，不注册占位能力；求助/检查点暂存后仍必须结束当前轮，不能建议成员继续调用被门闩禁止的工具。

## 实施与验收

Core 叶子契约复用后被工具包装器依赖，运行时只负责注入实际身份；输出模块不反向依赖大脑或包装器，包含类型引用也不能成环。同步文件注释、CONTRACT、目录类图和 roadmap。

单元覆盖合法输出、缺失/额外字段、跨运行回执、Workflow 错配、单次序列化、保存成功后输出损坏及门闩不解除；真实 Pi 沿现有计划/交付、求助与检查点流程回归。最终 Windows EXE 核对任务详情、实际文件操作、停止/重开和无重放，记录确定性供应商的限制后单独提交。

不在本片实现专业验证器、通用链接器、跨重启恢复或硬预算。
