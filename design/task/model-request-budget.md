# Step46 / R06：逐模型请求预算

状态：本片约定范围已完成，冻结全仓2068/2068、最终定向113/113及最终EXE三场通过。承接 Step45 `a2868f6`；承接已有周期软限额，原策略和旧周期不迁移为新的执行保证。实际证据和失败修正见[验证报告](../verification/model-request-budget-20261108.md)。

## 本片结果

用户可为新目标选择逐请求预留。主 Agent、执行成员、模型重试和自动摘要使用同一冻结周期额度；只有可靠保存了本次请求的预留，才能向实际供应商发送。收到完整、可核实的用量后结算并释放未用预留；发送后断流、取消、缺少用量、持久化失败或重启遗留均保留未知，不能当零释放后继续请求。设置变更不影响旧目标，查询不产生模型调用。

本地 Token 和按冻结价格计算的美元额度不是供应商最终账单。请求前以冻结模型容量和本次实际输出上限进行保守预留；不能把字符数估算称为精确 tokenizer 或账单上限。单次请求所需预留超过剩余额度时，在网络发送前拒绝，并显示所需预留与剩余额度。

## 开发前依据

- `ScopeBudgetService` 只在新主/成员运行之间检查 canonical 用量，同一启用额度的周期等待上一运行结算。一次 Pi 运行仍可能发出多个请求，不能在此直接宣称逐请求保证。
- 项目固定 Pi 1.5.0。其 `extensions/runner.js` 的 `emitBeforeProviderRequest` 捕获扩展异常后仍返回请求，因此扩展回调抛错不是可靠网络阻断。此结论来自本项目实际安装代码，不是对其它版本的推断。
- 当前受支持模型协议为 `openai-completions`、`openai-responses`、`anthropic-messages`，运行设置使用 SSE 并关闭供应商 SDK 内部重试，Pi 自己负责重试和自动摘要。须在所有实际 HTTP 尝试共用的传输出口核实预算，不能只统计公开 assistant 消息。
- 2026-11-08 接入预检：隔离真实Pi在启动前安装 fetch 转发，并在 undici 初始化后保持；三种 API 各1次请求经本机门禁后到达确定性供应商，全部正常结束，见本机 `test-results/request-gate-probe.json`。最初 Anthropic 夹具缺 SSE `event` 字段，补正后通过，失败另存。此探针只验证可拦截真实请求，尚未实现或验证预算、持久化、并发、重试/摘要及产品接线。

## 实现边界

1. **冻结策略与兼容。** 保留原运行间软限额；新增显式逐请求模式。缺省字段仍表示旧语义，不给旧周期补字段，不因全局设置变化复活已关闭或超限目标。
2. **可靠请求账本。** 复用同一工作区 DispatchStore 的串行可靠提交，独立预算附录以真实 workspace/root/scope/task/run 绑定每个请求，保存原策略、模型快照指纹、预留和结算事实，不与业务变更混写。落盘后再公开结果，并发请求共同扣减可用余额。请求正文、密钥和私有推理不入账本。恢复只重放事实，未结算记录阻止继续，不重发请求。
3. **传输门禁。** 每运行受管本机代理只允许固定供应商/模型与实际 API 路径，凭据留在可信父进程；SDK/Pi 的每次重试和摘要均重新经过预留。SDK保留原供应商地址用于兼容判断，实际 fetch 经启动时安装的可信转发入口，不能只换 baseUrl 后丢失原供应商兼容选项。须验证 Pi 的 undici 初始化不会覆盖门禁，验证失败则拒绝启动。拒绝不再调用模型解释。禁止重定向、任意目标地址、换模型、无限输出、未知协议或跳过门禁的直连回退。
4. **真实用量。** 严格解析完整 SSE 的协议终态和 usage；输入、输出及缓存分量按协议计算，推理 token 不重复计入输出。缺字段、冲突或损坏不能补零。明确未发送可释放预留；已发送失败不能仅凭 HTTP 错误或断线推断免费。
5. **生命周期。** 启动前、停止及退出均处理代理、请求和账本的所有权；先结束实际 IO 再释放运行资源。预算拒绝、业务验收、目标等待和旧失败分别保留。主/成员运行创建仍遵守原岗位、权限、并发和工作区锁。
6. **界面与审计。** 设置说明新旧模式和保守预留；目标显示冻结策略、已结算/在途/未知及实际拒绝原因，明确读请求记录而非供应商账单。晚到读取不能落入其它目标，读取失败不显示为零消耗。

## 验收矩阵

- Core/Store：版本冻结、并发预留恰好一次、相同请求 ID 冲突、金额边界、缺价格、Token-only、缓存/推理计量、超额报告、损坏日志及写前/写后故障；失败不释放不明消耗。
- 真实传输：三种已支持 API 的普通流式结束与缺失/重复/变化 usage、提前断流、取消、错误响应、重定向和越界路径；证明被阻断请求到达供应商次数为0。
- 真实 Pi：主轮连续请求在同轮内被阻断；成员与主轮共用预算；自动摘要和重试不绕过预留；未知结果后即使引擎尝试重试也不得再次到达供应商。旧软限额场景继续通过。
- 重启与竞争：已保存预留但无终态的原请求不重发；新设置不重置旧预算；并发、停止和落盘竞争不会多发一个请求。
- 桌面：最终 Windows EXE 实际设置逐请求模式，核实正常结算、同轮阻断和未知后重开。使用本机确定性供应商分别记录，不把它称为在线账单或模型自主质量。
- 同步中文文件头/关键接口、受影响 CONTRACT/目录类图、内置说明及实际支持矩阵。按类型→架构/依赖→相关测试验证，必要时冻结全仓；记录失败、修正和产物指纹，完成后独立本地提交、不推送。

R06 不提供外部账户扣费撤销、精确供应商账单对账或任意第三方私有协议保证；无法确认的消耗保留未知。不能因此删减本包普通请求、重试、摘要、缓存和并发预留的验收。第1–8组继续，第9组只保留计划。
