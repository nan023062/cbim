## 可交付行为

主 Agent 先定位静态模块，再通过 `cbim_governance_get` 获取实际保护和历史，`cbim_governance_observe` 保存真实当前依据，`cbim_governance_propose` 提出精确正文方案，`cbim_governance_receipt` 查询原操作。这四项只在本轮真实主运行装配；执行成员和未装配入口没有这些能力。登记保护、批准、驳回、暂缓和实施继续只由桌面明确操作。

观察与提案保存私有治理记录，不修改正式知识或推进业务验收。工具的 scope 为当前工作区 knowledge，effects 分别为 read、maintenance、preview、read；不扩大通用权限分类。受保护对象的普通 CRUD 仍拒绝绕过，聊天中的“同意”或工具权限确认都不代替治理决定。

## 来源、容量与恢复

- 来源由运行闭包绑定工作区、主实例、根会话、run 和 toolCall，模型输入不得指定身份、actor、原命令或写入路径。新桌面记录标明本机操作；旧记录缺少来源时明确显示未记录，不补造来源。
- 原/新正文各限 16 KiB UTF-8，单次序列化结果限 128 KiB，摘要最多返回最近 20 条且说明总数与截断。超长正文返回明确 oversized 信息，转到桌面处理，不发送伪装为完整正文的片段。
- 原命令由真实运行与调用身份稳定派生；持久后回复未知只能查询原记录。取消在进入可靠保存前检查；已经保存的记录不因取消被冒称回滚，不自动换 ID 重试。
- 原回执查询限同工作区、同根会话的可信模型来源。未查到是 unknown，不证明未受理。重新打开只恢复历史，不重放工具或启动模型。
