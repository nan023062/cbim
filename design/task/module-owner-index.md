# 模块负责人索引：实施切片与验收

日期：2026-11-07。状态：设计已整理，功能待实施。本文件是开发计划，不是产品运行 Skill；不启动模型、不修改真实项目岗位。概念与协议的唯一设计入口是[工作区成员与模块负责人索引](../../docs/module-owner-index.md)，实时开发状态只维护在[路线图](../tool-architecture-roadmap.md)。

## 目标与前置

用户明确的模型是：Agent 为与具体业务无关的专业能力；进入工作区形成岗位成员；模块标记负责人成员；主 Agent 先按模块查负责人再派发；更换负责人不改写旧任务事实。每个成员使用自己的模型与专业 Skill。

当前已存在知识快照、真人维护关系、派发事务、实例/运行身份、成员工具授权和有界文件基线；同周期成员检查点仍属于当前开发步骤，验收状态以路线图为准。本计划不覆盖、代交付或自动推进该步骤。

负责人的唯一权威选择同一工作区 DispatchStore 的成员/责任登记，模块详情提供关联字段。避免把关系写入 module.json 后改变全局 knowledgeRevision，也避免双写索引与模块字段。责任关系、派发和领取具备同事务裁决点，知识/文件存储的原有复核边界继续保留。

## A. 登记项目成员并展示模块负责人

交付：工作区拥有独立 `memberId`、岗位适配和配置版本；模块可查询未分配/已分配/失效状态，成员详情可反查负责模块。记录独立于主会话和用户目标，初始化不猜测负责人。

涉及范围：Core team/workspace/tasks 的新契约、Main 派发持久化、查询服务、Bridge、成员及模块页面。旧 AgentInstance 保留运行语义；不把新增成员登记当作持久运行实例已完成。

验收：同一能力可登记两个岗位成员；两个工作区互不串用成员 ID；成员改名不丢模块关系；能力来源代次、已采纳版本与成员 revision 分开；模板变化提示待采纳，不自动更新成员。只读查询不创建成员或启动模型；未分配和悬空引用明确可见；退休成员无法再次被指派。模块正文、authors、真人维护信息保持各自语义。

## B. 设置、更换与解除责任关系

交付：模块详情和主 Agent 工具共用预览/提交服务，保存关系版本、影响摘要、稳定命令、可信操作者和不可变审计。此切片先建立控制面能力，不宣称派发已自动采用新索引。

验收：首次设置 A、替换为 B、解除、再设 A 的版本持续增长；同命令重复不新增事件，不同参数复用命令被拒绝；两个更换请求只有符合当前版本者成功；写入失败不发布新索引；未知提交可查原回执；重启后正反索引从同一日志恢复。批量导入/删除不得留下悄悄生效的悬空关系。

## C. 主 Agent 按负责人分组派发，领取时再次核验

交付：目标计划、cbim_dispatch_task、显式 IPC、实例准备和领取统一绑定 `memberId` 与逐模块责任快照。同一负责人的合适模块可以合并，不同负责人必须拆任务。成员模型配置解析替代自动继承主轮模型，实际 Skill 和模型版本写入运行记录。

验收：按模块找到 A 并实际由 A 的配置执行；两个成员模型不同、专业 Skill 不串用；主模型切换不改变成员选择；未指定自定义岗位由主 Agent 执行，不回退已退役默认执行者；成员模型失效不降级；伪造 assignee/其他工作区成员被拒绝。负责人或成员配置在计划后变化时拒绝旧派发；外部 profile 原位更新即使未改变成员 revision，也按预期修订/无凭据指纹拒绝旧计划。明确采纳能力版本、重新查询规划后可派发；运行工厂只使用已冻结配置，凭据不进入公开指纹。明确权限与现有并发/写锁仍有效。

旧接口迁移：全部新业务派发走同一负责人规则，不能只修模型工具而保留可绕过的 IPC；旧任务在旧协议下安全收束、历史读取不补造责任。运行前的迁移预览与启用状态必须可见。

## D. 更换与排队、领取、暂停恢复的交接闭环

交付：更换预览按实际任务状态列影响；新任务归新负责人，未领取旧任务显示责任变化并阻止领取，在途当前段保持原身份收尾，旧检查点不能交给新成员。明确交接通过新任务与替代关系完成，不原地篡改任务负责人。

必要子协议：按明确任务/检查点/预约版本安全放弃尚未被领取的暂停任务，原子撤销未领取 resume 信封并追加 abandoned_by_handoff 处置和有原因的取消记录；不可变检查点仍保留，依赖后继仍须明确替代和复核。当前检查点尚无该能力，实施时必须补状态不变量、目标审阅及领取竞争验证。在它接通前，换人成功仍保留待交接缺口；只能显式关闭旧周期并开启新目标，不能宣称原周期已闭环。

验收矩阵：

| 场景 | 必须观察到的结果 |
| --- | --- |
| 先更换，再领取 A 的旧待办 | 拒绝旧领取；新派发只给 B |
| 先领取，再预览/提交更换 | 预览显示 A 在途；A 本段仍归原身份，新任务只给 B |
| 预览后有人领取 | 更换提交报告影响已变，重新预览后才能提交 |
| 多模块任务仅一模块换负责人 | 整个旧任务不得按过期绑定开始，重新拆分/规划 |
| A 已保存检查点，模块改为 B | 保留 A 的检查点和身份，B 无法恢复；A 无当前责任也不能开启下一段 |
| 先预约恢复，再换负责人，再实际领取 | 实际领取再次检查并拒绝，不消费旧检查点冒充已执行 |
| 显式放弃暂停任务与恢复领取竞争 | 放弃先提交则旧信封不能启动；领取先提交则放弃拒绝，改走停止核实 |
| 放弃暂停任务后新负责人接替 | 旧 checkpoint 原文不变、旧任务有取消原因；后继不被自动解除，真实替代结果及新审阅满足后才可完成 |
| 旧运行完成后再换人 | 历史仍显示 A 和原证据，模块当前负责人显示 B |
| 更换后崩溃/重开 | 已提交责任和回执一致；不因索引重建自动执行或恢复任务 |
| 跨主会话共享负责人 | 关系一致，任务正文与停止/恢复权仍按原会话范围隔离 |
| 受控能力同路径替换、模块删除/重建 | 来源代次变化使旧引用失效；跨存储变更中途失败保持待核实，不静默给新对象继承原责任 |
| 可观察外部缺失/内容变化，或来源连续性未知 | 阻止旧绑定并要求核实；不承诺检测无事件且字节相同的离线删除重建 |

还须验证更换不修改业务 knowledgeRevision、业务正文变化仍使旧基线按现规则失效；已完成旧结果不因负责人变化被伪造为失败；未解决交接工作不能绕过目标完成条件。

## 文档及验证要求

本次设计已同步概念入口与“能力抽象/工作区岗位/模块责任”边界；现有运行 Skill 和 Schema 尚未切换为新协议。进入各实施切片后按 `cbim-development` 更新当前步骤，修改 src 时同时按 `architecture-maintenance` 维护注释、CONTRACT 和受影响类图，不把未接通接口写成可调用事实。

实施验证按切片运行行为测试、类型和架构检查，功能接通后进行真实桌面操作验证；模型测试分别记录确定性供应商和在线实际配置证据。上表是验收要求，当前没有运行这些新功能测试。

本次文档交付只验证新增示例 JSON 可解析、修改文档相对链接有效、关键概念一致与 diff 无空白错误。不以文档检查替代功能验收，不改变已有成员检查点开发的测试结论。

## 后续独立能力

成员长期原生会话、跨重启恢复、对等邮箱、直接协作任务、允许原负责人完成指定遗留的继续执行许可、多主责策略和完整项目岗位迁移不属于本索引的第一版。接口保留稳定成员身份、责任版本和审计引用，后续能力以此衔接，不靠重写历史实现。
