# 单模块负责人控制面

Step31 / R02-A2/B，承接 `f70a968`。状态：已完成本片验证。完成 Step30 的稳定岗位登记后，为实际模块设置唯一项目岗位负责人；实时进度见[roadmap](../tool-architecture-roadmap.md)。

## 本步结果

桌面业务架构可以查询、预览并设置、更换或解除模块负责人；团队项目岗位可反查当前负责模块。真实主 Agent 使用同一服务查询和治理责任，按已有 read/ask/execute 权限执行。每次操作只改一个模块，保留完整原命令、变更理由、真实来源和回执。

责任属于工作区，不属于某个主会话。它引用稳定 memberId，与静态 Agent、真人维护人和动态执行实例分别保存。不继承父模块责任，不用名称或旧任务 assignee 推导负责人。岗位暂停保留关系并显示问题；仍有责任的岗位不能退休。解除不会删除关系历史，再次设置沿原 bindingId 升版。

本步只完成责任登记控制面；现有派发、领取、模型选择和旧任务身份保持原协议。预览按实际关联任务提供影响计数，但不声称已改派或移交。C 启用实际负责人派发前，必须补受控来源代次、知识变更屏障与旧记录明确采纳；当前观察 hash 不能证明删除重建连续性。

## 模块与接口

- Core workspace 提供纯 DTO、Schema、关系投影及依据计算；Core tasks 在同 DispatchStore 校验单条责任审计、岗位引用和独立 ownershipCursor。禁止混入图/运行变更或直接改关系头；岗位退休与关系设置按同事务裁决。
- Main `ModuleOwnerships` 从真实可见模块注册表观察来源，提供 `workspace.ownerships.list/get/byMember/preview/commit/receipt`。预览只读；提交核原命令、工作区实例、关系/岗位版本、知识和影响摘要。解除不依赖已失效的来源。
- 主工具为 `cbim_module_owner_inspect/change_preview/change_commit/receipt`。inspect 可先分页发现真实岗位摘要，再查指定模块或岗位的责任范围，不要求用户提供内部 UUID。真实运行闭包注入主会话、周期、实例和工具调用身份，模型不能伪造 actor 或命令；成员不安装这些工具。责任提交使用治理写权限，保留副作用时间线，但不冒充业务产物证据，也不把纯责任操作自动判成需要业务验收的任务。
- 前端固定当前工作区和选择，核对原预览与回执；提交前保存原请求，未知只查原命令或明确重送同一请求，重开不提交。列表按责任、岗位与知识三项依据分页，不能拼接过期页；历史展示明确有界。
- 知识与调度仍无跨存储原子锁；观察读取前后复核，来源缺失/变化明确展示，不自动解绑或恢复关系。查询/登记均不启动执行 Agent。

## 验收

1. A→B→解除→A 的关系身份、版本、正反查询一致；改名不重绑，暂停保留，引用未解除时退休拒绝。
2. 模块缺失仍可解除；首次设置须实际存在且可见、目标岗位 active 且版本匹配。过期预览、关系/岗位并发、任务影响变化拒绝；坏审计或混合事务不得重放。
3. 真实主工具 read 拒绝、ask 拒绝/批准、execute、停止和已提交坏回包；回执记录真实主来源而非本机人工，未知只查询，不重试业务副作用。
4. 正常桌面和真实保存后丢回复两场，原任务/知识记录不因责任登记被改写；重开不重复提交或启动模型，草稿保留。
5. 类型、类图与含类型循环检测、边界及相关回归通过；构建最终 EXE 后真实桌面验证，同步中文注释、CONTRACT、roadmap、开发记录和验证报告，独立 Git 提交。
