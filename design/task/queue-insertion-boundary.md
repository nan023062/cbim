# 队列插入的原轮次绑定与停止屏障

状态：2026-11-07，Step26 已完成，承接 `dda55f1`。最终19文件154项、13项边界、类型/架构通过；Windows EXE `20261107-185053` 正常、停止与已受理后丢界面回复三场通过。见[验收报告](../verification/queue-insertion-boundary-20261107.md)。本片修复插入时序缺陷，不扩展任务调度权限。

## 已有能力与问题

普通用户消息在成员工作期间留在队列，安全 waiting 使用独立补充入口；主 Agent 运行时才允许“插入当前任务”。已有真实 Pi 测试证明正常插入不打断当前工具，也不继承队列项的更高权限。

实际 Manager 的确定性端口复现发现：附件读取等待期间点击停止，旧实现仍可能在停止执行之前 steer 并消费队列。当前 IPC 还未带原主 runId，迟到请求可能进入另一主轮。该复现不是在线模型或桌面测试，需本片补齐分层及最终包验证。

## 本片约束

- 两处界面插入口捕获点击时的主 runId，IPC 与 Manager 强制核验；缺失、过期或不是活动主轮时拒绝，不消费原排队消息。
- 插入独立持有停止信号；停止与关闭同步撤销，不等待同一插入串行事务后才停止实际引擎。claim、附件读取和 Pi 状态查询后的发送前边界再次核验。
- 对话与任务根的停止按钮使用独立在途标记，插入等待不能锁住停止；停止未返回时禁止新的发送/插入/继续。迟到停止只释放自己的标记，不清除另一会话状态或发送锁。
- 未发送即停止时保留原消息；已 claim 条目暂停。Pi 明确确认 queued 后保留真实受理事实，不能因随后停止改称未接受；发出后的通信或日志/队列保存失败按未知暂停，不自动重插。
- 使用原活动运行的模型、权限和成员身份，不采纳队列里的提权配置，不把消息插入成员通道，不借普通队列恢复 waiting，不修改持久目标原始输入。
- 插入失败暂停普通消息队列，独立的内存推进屏障在持久化失败时仍防重发；不误用整个协作停止标记阻断正常成员结果回注。停止实际引擎绑定请求开始时的原运行，不能补扫并停止后来明确启动的新轮。
- 旧队列文件无需迁移；旧缺 run 的调用明确失败。停止不能因单个插入失败而漏掉其它运行的资源释放；无跨重启自动恢复。
