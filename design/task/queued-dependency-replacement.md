# 未启动任务的单条前置替换

状态：2026-11-07 待实施。承接 Step12b 运行间软限额；本步补协作中的依赖修订，不恢复已结束的执行者。

## 交付路径

主 Agent 派发 A → B → C。A 可靠求助或明确失败后，主 Agent 在同周期规划并派发 A2。A2 产生当前知识版本下的真实交付候选后，主 Agent 明确以 A2 替换 B 的前置 A；B、C 保留原任务、角色实例和执行通道，首次执行继续通过权限、工作区租约、软限额及全局准入。原 A 保留失败/求助记录；最终完成还须审阅明确 A → A2 的替代关系。

只允许单条原子替换，不支持任意删除依赖、重启旧 Pi、改派已启动任务或刷新过期知识后继续使用旧任务。

## 契约与数据

模型提供旧图游标、目标版本、B 的节点/计划版本、旧边 ID/版本、A2 的节点/计划/run/result 身份及原因。workspace/root/scope/mainRun/command 来自可信运行闭包，不由模型冒充。

`TaskNode.dependencyReplacements` 追加不可变记录：提交前图游标、主运行、目标/计划/知识版本、B 原版本、退役边和原来源、新边和 A2 候选身份、重新纳入跟踪的 B 及全部未启动后继。B 只增加节点 revision，planRevision 不变，因为目标、范围、责任和验收未变。

单次事务禁用旧边，创建固定候选的新边，追加 B 审计并重算全部前置及成员等待状态。原 assignment、成员/会话身份、A/A2、其他任务和已有执行不改写。图增量仍以 `dependency.changed` 的完整原子批次发布。

## 不变量与执行边界

- 周期须 active，当前目标计划有效且没有未重新规划的旧 review。旧来源须真实安全求助或可靠失败；未知/未决操作不能通过换边隐藏。
- A2 同周期且后创建，覆盖 A 原模块，具有完整 canonical 证据及当前知识基线。仅 status=result_ready 不足以放行。
- B 与全部启用依赖后继都未领取、未登记运行、未求助/交付/撤销；原计划仍匹配当前目标的角色/模块安排，配置与知识不能过期。
- 新边不能自引用、重复或成环。新依赖/禁用旧边必须与审计原子提交；退役边不可复活，旧审计不可改删。正常 member claim 仍可固定前置 resultId。
- 回执的 trackedTaskIds 只是待办跟踪集合，不是立即可执行授权。协调器显式加入当前主运行批次，待主运行结束后按真实前置推进，避免旧 B/C 因已退出旧批次而永久等待。
- 重复命令返回原回执；停止/重启不自动执行历史替换，候选或基线变化明确拒绝。
