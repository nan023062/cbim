# 主调度撤销尚未启动的任务

状态：2026-11-07 已实现并通过本地验证，承接成员求助 `eaf588c`。主调度可处理求助后的未启动依赖待办，再按原门禁安全等待用户。具体测试、最终 EXE 和限制见[验证报告](../verification/queued-task-cancel-20261107.md)。

## 范围

- 新主调度工具 `cbim_dispatch_cancel`，输入当前图游标、明确目标列表 `{taskId,expectedRevision}` 和原因。workspace/root/scope/run/command 来自运行闭包，成员无该入口。
- 只接收当前 active scope 的 planned/queued/waiting，且没有 run、claim、活动占用、候选或求助。活动任务继续使用明确停止接口；此工具不发送 abort，不伪造执行日志。
- 检查启用的 dependency DAG 后继。遗漏必要未启动后继则整体拒绝并说明需纳入的任务，绝不静默扩大取消集合；已启动/有运行后继拒绝处理。当前派发都是 root→task，不把依赖下游误称为递归派发子树。
- 单事务保存不可变撤销记录、cancelled 状态、原因、assignment→processed、成员待办列表及图投影。实例空闲但仍属于 scope，关闭时才 released。不删除节点/边/原目标，不造结果或求助。
- 图/目标版本和领取状态在同一存储屏障复查。start/cancel 竞争只有一方可受理；幂等同命令返回原回执，不重复事件。历史重放与读取不启动模型。
- 撤销使旧审阅过期，必须重新审阅才可安全等待。取消任务仍需真实新任务候选替代才能完成目标，既有人工项和证据规则保持不变。
- 主对话、节点及详情显示“已撤销（未启动）”和实际原因；不把普通运行取消或无可信记录的旧节点改成此标签。本轮不新增用户撤销表单。

## 验收

领域与门禁：批量原子性、依赖闭包、过期图/任务版本、跨scope/会话、重复命令/重放、领取竞争、拒绝历史/活动/候选/求助任务；取消不可用作成功证据，停泊仍要求完整主成员日志。

真实 Pi 与同一最终 EXE：A 求助，B→C 尚未启动；主调度明确撤销 B/C 后申请 waiting，重开无执行，普通“同意”留在队列；显式补充后新建 A2/B2/C2 并以真实结果替代旧任务。界面展示原因和保留历史，停止/并发边界另测。确定性模型用于重现，不作为在线质量证明。
