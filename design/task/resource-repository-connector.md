## Step17b1：明确连接与只读 HTTP

已有本地资源仓库、共享 HTTP 服务和远端客户端，仍缺工作区可授权的实际链接器。增加独立 `resource_repository_v1` 静态定义，保存仓库身份，不保存 URL、令牌或运行授权；已有 Cindy plugin 映射保持原静态含义。

用户先在设置中明确开启当前仓库共享，再选择工作区预览并确认连接。静态定义通过现有知识事务保存；实际访问授权由本机可信界面独立登记，绑定工作区、链接器、仓库及版本。定义本身不能给 Agent 授权，撤销无需删除静态知识。

专用只读凭据留在主进程，只允许真实 HTTP GET。查询有范围和响应上限、取消及超时；关闭共享、切换仓库、撤销授权或应用退出使连接代际失效，迟到结果不交付。无本地磁盘回退、自动共享、自动换源或隐式重试。重启只恢复定义/授权记录，不恢复服务、凭据或网络调用。

桌面可核验连接和读取资源，以真实 HTTP 结果证明服务打通；读取正文只是资料，不能自动安装、应用或执行其中的指令。这个切片不装配主 Loop 工具，不把接口预留当成 Agent 已接通。

已实现的桌面核验仅返回前 20 项摘要、数量与内容版本，不返回正文。原请求在本机先保存再发送，授权/撤销和知识登记分别查询真实回执；实例退役后只有明确未受理证明才能解除未确认记录。知识事务日志和完整授权命令链作为事实来源，缓存或缺失历史不能代替成功/未受理证明。

## Step17b2：主调度真实调用

复用同一连接，新增有界摘要查询和带版本的单项读取；严格输入/输出、运行授权和真实回执。可信适配器生成 repository scope，区分工作区文件与仓库资料；外部读取不能冒充文件验证或检查点。仅主调度装配，执行成员的显式授权另行推进；静态 Cindy 映射不因此可执行。

## 验证与边界

- 单元：静态定义联合、错误字段/越权拒绝、只读 HTTP 凭据、版本与代际竞争、撤销/取消/超时、迟到结果、敏感信息不回显。
- 真机：最终 Windows EXE，隔离的真实磁盘仓库和 HTTP 服务；明确选择/预览/确认、读取核验、撤销/停止、重启无自动服务或模型重放，页面及通信错误检查。Step17b1 不调用模型；Step17b2 再使用真实 Pi 和本机确定性模型验证工具回执。
- 同步中文注释、CONTRACT、目录类图、roadmap 和验证记录，每步独立 Git 提交。
- 不接账号、不模拟登录、不输入任意 URL/密钥、不执行资源包脚本；跨物理电脑复用、通用插件、外部写入与正式发布保持待验证。
