## 本轮交付

1. 设置页提供 Token / 估算美元额度，默认关闭，启用时至少明确一个正数。版本化原子保存成功才生效；只影响之后创建的周期。
2. 新周期冻结策略，主运行、成员运行和显式补充共享；旧周期不补造策略。新核实和新业务重规划各冻结当前设置，但不会重放旧目标。
3. 在主运行登记/成员领取的真实事务里核实全部既有归属与 canonical 用量；通过证明与新运行同事务保存。不能用界面缓存或可重建全局统计签发许可。
4. 启用额度的同一周期只在上一运行可靠结算后启动下一运行；其它周期继续按全局并发。可信在途启动与损坏/缺失记录分别处理；等待不占名额，未知消耗不当零。仅配置 Token 时，不因没有价格拒绝。
5. 达到任一额度或不能核实所需用量时，阻止下一轮。活动周期持久记录原因、暂停队列并收口为未完成，不额外调用模型解释；已有运行先正常结算。已满足目标完成门禁或安全 waiting 不因最后一轮超额而被改成失败。
6. waiting 后显式补充的预算拒绝不消费检查点、输入版本或启动意图。调高全局设置不改既有周期、不复活已关闭目标；不绕过原权限和人工验收。
7. 前端显示冻结策略和拒绝原因，区分未应用、关闭、额度达到、用量未知与正常完成；新增设置不会暗示已有周期已生效。

## 实施约束

Core 保存严格契约和提交/重放不变量；Scheduler 在既有串行事务内读取可信日志与准入，避免在事务内再次调用 store.read 造成重入。Main 装配可靠设置和运行端口，Bridge 仅公开 DTO，Frontend 只提交用户设置与展示事实。

不承诺硬账单上限：一次 Pi 运行可包含多个请求、重试及自动摘要，本轮仍可能超过阈值。当前请求前扩展不能可靠阻断所有这些请求，逐请求预算留待专门的请求预留/结算机制。
