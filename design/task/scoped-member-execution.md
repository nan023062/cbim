# 冻结范围的成员隔离执行

日期：2026-11-08。Step54 / R12-B1，承接本地提交 `e1a410c`。全局进度由 roadmap 维护。

## 本片目标

为显式声明 `executionScope` 的模块 Workflow 接通真正可用的受限成员执行。声明是对原 read/ask/execute 权限的收窄，不授予额外权限；旧任务保持历史语义。一个任务的全部模块必须共同采用该模式，不能混入无范围模块后回退原生工具。

- 冻结允许读取和修改的文件/目录以及固定 Node 执行预算。路径不含通配符、跳转、设备名、`.cbim` 或 `.git`。写范围必须包含在读范围内；完整产物和验证要求也必须在读范围内。
- 该模式关闭所有 Pi 原生文件/命令工具，可信运行时也拒绝伪造调用。受控读取使用实际 Win32 目录/文件句柄，拒绝链接、备用路径和超限；原受控写及删除/移动继续核原授权和原阶段，另核冻结范围。
- 隔离命令只读取明确选择的允许文件，复制后使用 LPAC/Job 执行固定 Node；模型不能更改可执行程序、环境、网络能力或资源预算。输出留在私有目录，只返回声明的有界字节，不自动回写工程。执行非零与验证通过分开。
- 产物采集、清单、专业验证和续执行复用同一冻结边界；所有读写仍沿真实任务/运行绑定。取消与收尾等到实际隔离进程树退出。

## 验收

纯协议验证混合模式、范围逃逸及声明冲突；真实 Win32 读取覆盖只读文件、目录替换/链接与范围外文件；真实 Runtime/Pi 覆盖 read/ask/execute、审批停止、伪造 native、未知写后禁止命令、只读核实和原调用不重放。最终 EXE 使用自身运行时验证冻结输入执行、越界拒绝及取消。相关回归、类型与架构检查通过后记录指纹、报告并独立本地提交，不推送。

## 后续边界

本片不把任意 shell、网络、外部资源或不同语言解释器标为已隔离。可靠孤儿来源核实/清理需独立持久身份设计，列为 R12-B2；在该能力接通前，崩溃仍由 Job 收束进程，残留目录保留，不自动重放或盲目删除。R09-C 程序验证随后复用固定快照执行，普通命令退出零仍不充当专业验收。
