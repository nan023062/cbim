# 任务知识基线与恢复

本规则定义任务的知识基线与恢复约束，供调用方使用。基线属于本次任务证据，不给 Agent、Module 新增字段，也不建立第二套权威知识。本地任务进度、版本快照和恢复证据保存在 `<用户主目录>/.cbim/<项目标识>/task-records/`；个人短期线索位于 `<用户主目录>/.cbim/<项目标识>/memory/`，不能替代任务记录。两者均为本地目录，由根忽略规则排除版本管理，不默认共享。跨设备恢复或人员接管须显式传递所需记录，并核验完整性；不能只依赖对话上下文。

## 本地记录命名

- 在 `<用户主目录>/.cbim/<项目标识>/task-records/` 和 `<用户主目录>/.cbim/<项目标识>/memory/` 下新建记录时，顶层记录文件或文件夹统一使用 `YYYY-MM-DD_HH-mm-ss_记录名`，以创建时的本地时间为前缀；各时间字段补零，采用 24 小时制，便于按名称排序。
- 一个任务或主题使用一个带时间前缀的文件夹；内部的 `checkpoint.md`、快照及证据文件保留用途名称，不要求重复添加时间。独立记录文件同样带前缀，并保留扩展名。
- 同一记录后续追加内容不改变前缀；新建独立记录才使用新的当前时间。同秒同名冲突时追加递增序号，不覆盖已有记录。跨时区协作时在记录中注明所用时区。
- 历史记录整理采用整理时的当前时间，明确其为迁移时间而非原始创建时间；保留新旧路径映射。历史快照和版本绑定不改写，恢复旧引用时先按映射定位，再核验原哈希。

## 建立与传递

1. 首次使用知识作出方案、派发或验收判断时，登记实际使用的入口、CBIM AI 助理 Skill、agent.json、工作原则、专业 Skill、module.json、相关 DNA、Workflow，以及该任务唯一 Agent 与全部作业模块声明的完整插件声明集合、注册表映射及实际工具可用范围与调用回执。仅记录实际用到的文件；后续按需加载时增补，不快照整个项目。
2. 每项记录逻辑路径、所属任务及用途、内容版本依据和可重新取得该内容的位置。优先使用实际读取的 Git 提交或 P4 文件修订及内容哈希；不能用仓库最新版本冒充本地已读取内容。未提交修改或无版本库时记录内容哈希，并在可追溯任务记录中保留必要的只读历史快照或可还原差异。快照是审计依据，不能作为当前可编辑的知识真源。
3. 文件自述 version、修改时间和路径只能辅助说明，不能单独证明内容相同。哈希只能识别差异，不能恢复内容；无法取得旧内容时如实标明缺口，不声称精确恢复。
4. 将知识基线与实际代码、资源、配置的产物基线分别记录并关联，决定、派发与验证证据标明依据哪一版。交给执行者时传递记录位置和所需文件版本，要求核实实际读取内容；新增必要引用时补记。
5. 建立或调整 Task 时绑定实际采用的任务抽象、唯一 Agent、完整模块集合及逐模块维护依据、工作范围和验收条件；只读上下文与作业模块分开记录。维护依据来自用户或负责人指定时，保留可追溯的指定内容与适用范围。派发记录关联这份任务版本，恢复时核对执行者实际接收的版本、旧执行实例状态及实际工具访问范围；模块增减、执行者变更或任务拆分保留新旧对应关系，不覆盖原绑定。

## 派发、恢复与验收前复核

1. 对照任务记录，核实已发生操作、当前产物、知识内容和当前有效授权。正在执行的任务发现知识变化也应回报；不能只凭旧完成标记继续。
2. 内容未变且产物及授权仍有效：从未完成步骤继续，不重复已发生的修改或发布。
3. 内容改变：取得新旧内容或可靠差异，判断是否影响本任务的范围、契约、能力、步骤或验收条件。纯排版或无关变化可记录无影响依据后更新绑定；不能只凭文件名或版本号认定无影响。
4. 相关语义改变：暂停依赖该依据的任务，明确受影响的决定、产物与验证。根据新事实调整方案，核实已有授权是否仍覆盖，需要额外决定时向调用方返回待决事项；更新基线后重新派发或重验受影响部分，独立工作可继续。保留旧依据与新旧对应关系，不覆盖历史记录。
5. 旧内容丢失、引用失效或影响无法判断：先重建当前必要事实；能重新验证的部分重新验证，仍有关键缺口的部分保持受阻。不得靠猜测恢复，也不要求无关任务全部重做。

当前任务依据被更新时也执行同样的差异判断。绑定旧版本用于追溯，不允许借此绕过已生效的约束或继续使用失效授权。记录完验证所对应的最终基线后再交付；所需本地记录缺失或未传递到接管环境时，明确恢复能力尚未落实。清理临时目录前核实在途任务仍需的恢复证据。
