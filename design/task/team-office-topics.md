# 主会话办公室、任务话题与团队对话

来源：2026-11-14 用户直接要求，明确授权分步实施、逐步测试与独立提交。基线：`8f743f51`，工作区初始干净；当时唯一开放工单 #65 是另一项报错，不属于本设计。本文保存设计和迁移边界，实际完成与验证写入开发记录，不另设实时待办。

## 产品规则

- 一个主 Session 是一个办公室；多个主 Session 独立并行。
- 所有 Agent 使用同一模型。每个办公室中每个 Agent 只有一个长期逻辑对话；子会话由主 Agent 首次登记/派发创建。
- 侧栏按主 Session → 子 Agent Session 展示。主会话常驻一级，子会话可折叠。用户从任意窗口发送的指令都交给所属主 Agent。
- 用户需求成为任务话题。普通新消息排队；主动向指定话题提交补充才暂停该话题的全部参与者。只浏览不暂停。
- 一个办公室默认只执行一个话题，话题内不同 Agent 并行；同一 Agent 的多任务串行。话题暂停不启动下一项。
- 主 Agent 派发、子 Agent 回传和执行流归原话题。回传不能进入主会话根流水，也不能按当前选择或最新话题路由。
- 所有记录按主 Session → 话题 → 内容组织；正文只保留权威记录，通过引用提供不同 Agent 的视图。保留实际发送者、任务/运行身份与输入版本，Agent 消息不冒充用户授权。
- 主 Agent 可使用本主 Session 中所有用户输入、话题与回传。子 Agent 只获得当前话题上下文；历史可浏览但不能混入其他话题的提示词或原生线程。
- 已完成、已撤销任务默认折叠到历史任务。结束任务不删除 Agent 对话或办公室。
- 办公室用人物、模块工位、派发/汇报往返表现真实活动；动画由已提交事件驱动，不阻塞执行、不把移动结束当作任务完成。人物对话图标返回对应对话。

## 状态与职责

Logic 拥有话题、逻辑对话、队列及调度状态；原调度日志保持唯一事务来源。Bridge 只提供受限查询/操作，View 负责导航、折叠和动画。Core 不承载办公室业务。

长期逻辑对话与执行租约区分：`TeamSession` 按工作区、主 Session、Agent 唯一登记；已有 `AgentInstance` / `AgentSessionBinding` 仍记录执行任务的冻结权限与原生通道。执行租约不是额外的团队人物或用户会话。这样保留既有检查点、未知工具结果、原子结算和旧日志的校验，不通过 UI 合并偷偷复用原生历史。

话题使用已有 `DispatchScope` 作为执行归属；待执行输入需要在入队时取得稳定话题身份。主运行由已保存的 `runTracking` 归属，成员运行经原任务的 `scopeId` 归属，缺失的旧记录明确显示未分类历史，不能靠时间猜测。上下文装配须分别约束主会话和子话题，有限模型窗口不等于删除完整归档。

插入采取“提交补充 → 冻结原调度 → 请求参与者停止 → 等待真实退出/结算 → 主 Agent 分析新输入 → 新版本派发”。未确认退出或副作用未知时保留待核实，不能显示已暂停或继续派工。已完成话题的新增要求创建关联后续话题，不复活旧运行。

## 可独立审阅的迁移切片

1. 长期逻辑对话身份：与主根、成员登记/派发同事务保存，跨任务/话题复用；验证重复、跨办公室隔离、重放和旧日志兼容。
2. 话题及上下文：队列身份、原话题回传归档、同角色串行与严格话题上下文；验证迟到结果、跨话题污染及不同引擎启动输入。
3. 群聊与团队导航：侧栏主子层级、话题队列、成员真实流和统一主 Agent 输入入口；验证导航不发消息、不暂停以及跨办公室选择。
4. 明确话题插入：暂停全部参与者、可靠收尾、新输入版本与重新调度；验证并发输入、失败、重启与未知结果。
5. 办公室场景：人物/模块工位、真实派发汇报事件和对话双向导航；保留历史折叠、键盘访问、窄屏与减少动画设置。

每片迁移真实消费者，更新契约/类图和实际验证记录后单独提交。遇失败修正本片，不改写已提交历史或全盘回退。模型执行/任务事实继续以原日志为准；新投影不可成为第二个执行状态源。

## 影响与维护导航

本轮为已授权的跨模块产品演进，按 C3 / L3 准备设计与取消、事务、恢复边界的 review 证据。

- Q1：保护执行租约、权限、原生绑定、业务验收与未知结果语义，以及四层单向依赖。
- Q2：长期对话归 Team 规则；话题归现有任务周期；输入调度归 Conversation/Dispatch；场景只归 View。
- Q3：每片依据实际调用链选择单元及消费者契约；不因跨模块自动运行全仓测试，后续集成/发布另记。
- Q4：首先阅读 `logic/team/rules/team-session.ts`、`dispatch/rules/dispatch-storage.ts`，再沿各片的消费者及测试阅读。
- Q5：暂无需要晋升的通用规则；本设计仅约束此次产品行为。

本方案不表示全部功能已经实现；实现、验证、人工 review、合并和发布分别记录。
