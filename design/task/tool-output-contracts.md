# 内部知识工具的业务输出契约

状态：2026-11-07 Step17a 已完成，承接已验证并独立提交的 Step16a `df60966`。26 个既有知识工具及 2 个新增目录/契约查询入口均具备严格业务输出契约。验证见[报告](../verification/tool-output-contracts-20261107.md)。只覆盖真实知识工具，不把尚无传输的链接器算作已接通。

## 交付范围

为现有知识工具的真实返回值补严格业务 Schema，覆盖身份、快照与诊断、内置规范、团队/模块查询、知识预览/提交、对象事务和维护任务。自然语言正文、无效知识诊断、继承冲突、缺失正文、内置默认角色和 not_found 都是正常可表达的结果，不因增加协议检查而吞掉这些状态。

领域调用只执行一次。返回后产生唯一 JSON 传输快照，按业务 Schema 核验，再封装为已有文本 JSON ToolResult；实际发出的仍是该快照，不依赖第二次 toJSON、不用 Schema 默认值补造成功，也不丢掉多余字段悄悄放行。异常使用 `TOOL_OUTPUT_INVALID`，只说明协议位置和错误类别，不回显正文或凭据。

输出核验不属于事务回滚：即使提交已经发生，返回协议仍可能损坏。错误必须提醒核实已有操作，不能通用自动重试。原知识 requestId、对象 planId、版本与实例校验保持实际语义；维护任务的取消只表达请求，不等于已经停止或回滚。

## 元数据与实际能力

注册表持有真实工具名、版本、副作用、输入/输出 Schema，以及取消与恢复说明。读取可重新读但版本可能变化；预览可能形成新计划；知识提交只允许同 ID 同内容取得原回执；对象提交的目录清理警告可能变化；刷新并非调用级幂等；维护启动丢失结果时需查询已有记录，不能盲目再启动。

按需描述仅返回本注册表实际装配的知识工具，不声称覆盖原生、派发、人工决定或外部插件。元数据不授予任何权限，不返回密钥，不改变主 Agent 禁止直接执行业务的边界。没有真实传输端口的 Cindy 插件保持静态定义，不构造虚假可用工具。

## 模块安排

- Core tools：输出快照校验及工具元数据，保持依赖 Core；注册表不执行授权、事务或网络。
- Core knowledge：真实知识业务输出 Schema，与现有返回类型对照；知识结构不合格仍可作为合法诊断返回。
- Scheduler tools：知识服务装配与按需契约说明，复用既有一次调用授权和真实运行回执。
- 测试：真实工作区 CRUD/查询、错误字段拒绝、提交后协议失败不重放、旧实例与幂等回归；Pi 和最终打包 EXE 验证真实工具调用、界面结果、停止及重开无重放。
