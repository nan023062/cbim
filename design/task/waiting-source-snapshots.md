## 本步目标

原目标安全等待时，用户可显式添加目录清单、链接、网页摘录及已授权资源仓库静态资料，再补充并继续。复用现有文件/图片、冻结请求、一次受理、预算和停止门禁；普通聊天草稿不受影响。导入资料不是安装链接器，也不是批准业务执行。

| 来源 | 保存的实际内容与边界 |
| --- | --- |
| 文件、图片 | 保持当前私有快照和 manifest v1；图片仍按真实模型视觉能力发送 |
| 目录 | 首层最多 200 项的有界清单；不递归、不读文件正文，注明截断 |
| 链接 | HTTP(S) URL 指针，明确没有抓取网页 |
| 网页 | 显式 HTTP 读取；不跟随重定向、不执行脚本；原始响应最多 1 MiB，保存最多 64 KiB UTF-8 摘录，注明截取 |
| 仓库资料 | 现有 `resource_repository_v1` 的 connector/team/agent/skill/architecture/module/workflow 正文，经真实授权和共享代际复验；仅作为静态资料 |

## 实施边界

- Core 增加严格 manifest v2，保留 v1 原结构和旧回执。来源证明由 Main 产生，不接受界面或模型自报。没有证明的旧非文件快照要求重导。
- Main 负责有界实际读取、取消、保存与授权前后核实。受理继续时只读保存的快照，不重新联网或重读原目录；重复原命令先查原回执。
- Bridge 只暴露公开元数据和显式选择接口，凭证不入 renderer 或模型。Frontend 共享控制器冻结原等待身份与选择代次；迟到导入、会话切换、取消不能污染新草稿。
- 保留既有总附件、图片、文本及展开消息限制；导入失败不消费等待。新材料不自动满足旧目标或业务验收。
- 本片不实现登录/服务器建设、真实浏览器渲染、目录完整产物索引或外部插件执行。组 9 仍仅保留计划。

## 验收

真实目录和 HTTP 服务覆盖所有来源、超限、取消、重定向、授权撤销及代际变化；v1 兼容、v2 严格联合、来源篡改、顺序及哈希受检。实际 Pi 验证混合资料进入续跑、输入升版、快照不随原来源变化、同命令不重导。最终同一 Windows EXE 验证选择/预览、继续、草稿隔离、迟到结果和重开无重放。类型、架构、边界、行为测试完成后更新记录并独立提交。
