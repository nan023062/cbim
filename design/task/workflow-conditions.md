## 本轮结果

在模块自己的 `workflow.md` 中允许一个明确命名的 `cbim-workflow` JSON 代码块。未声明时保持现有自然语言流程；声明后严格校验版本、字段及重复块，不能把坏配置当成没有约束。约定随 Workflow 正文和知识指纹冻结，不复制到另一模块或隐式继承父模块。

首版只支持两类稳定条件：业务写入/命令前必须有执行计划；交付时必须引用指定原生业务工具的真实成功回执。首版工具限当前内置 read/write/edit/grep/find/ls/bash，不接任意脚本、表达式或模型自报通过。`bash` 的影响范围仍为 unknown；名称匹配只能证明工具调用事实，不能证明命令是有效测试或专业语义正确。

```json
{
  "version": 1,
  "beforeEffects": { "requirePlan": true },
  "delivery": {
    "requiredToolEvidence": [
      { "id": "inspect-result", "toolName": "read" }
    ]
  }
}
```

两部分可分别省略，但至少有一项条件。每份契约的证据要求有界且 ID 唯一。所有绑定模块的条件都检查，任务工具不能充当业务证据；首版不根据 workspace 级回执推断逐模块/逐文件覆盖。

## 执行与职责

- Core workspace 定义纯解析/校验；知识预览/保存与完整架构包复用该规则，错误声明不能绕过治理入口进入新执行。
- 执行知识准备保存正文、解析结果及同一知识版本；成员启动前核对实际工具集合及权限，缺能力明确拒绝。普通无约定的旧任务兼容。
- 工具先按真实注册信息分类，再检查 Workflow 条件，再进入既有权限、平台路径和审批；主 Agent 仍不能执行业务。审批期间计划变更须拒绝旧调用，不能借新计划放行旧批准。
- 交付要求绑定当前运行、计划和最后一次副作用后的真实成功回执。持久化候选及主 Agent 审阅从 canonical 重新核验，不能只相信内存状态或模型给出的 pass。
- 知识变化继续使旧执行基线失效；业务执行后的知识沉淀由主治理安排，不能在本片放宽版本门禁。通用暂停/恢复、人工批准、专业验证器和跨重启续跑后续独立推进。
