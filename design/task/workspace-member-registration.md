## 交付与边界

静态 Agent 表示可复用的专业能力。工作区显式登记稳定 `memberId`，保存岗位名称、职责、适配说明、采纳的工作原则与继承 Skill，以及明确选择的供应商/模型配置。相同能力可以登记为两个岗位；稳定岗位不创建运行实例、主会话、任务或模型请求。

成员支持版本化编辑、明确采纳能力或模型新版本、暂停与退休。退休为不可复活终态，保留历史身份。改名不换 ID，编辑其他字段不暗中采纳外部变化；换另一静态 Agent 必须新建岗位。缺失来源不妨碍暂停/退休，也不抹去已采纳的历史内容。

团队页面新增独立的“项目岗位”入口，与静态树和执行历史分开；列表分页、详情展示原采纳和当前差异，编辑先预览再明确提交。每次提交固定原命令、岗位版本、登记游标和预览依据；未知结果只查原命令或明确重送同一请求，不能新建命令重复登记。重开只查询未知，不自动提交。

本片**不改变现有任务派发**，独立模型仅登记、尚未用于实际执行。后续再接模块责任设置、所有派发/领取入口及存量任务交接；现有默认执行者和旧任务身份保持原规则。

## 模块与协议

- Core team 维护严格岗位 DTO、公开模型快照和有界内容；Core tasks 校验单条不可变审计、版本、状态和事务隔离。纯类型不反向导入大脑或调度。
- 同一工作区 `DispatchStore` 追加岗位变更事件、派生当前岗位及独立 registry cursor；不另建权威登记文件，不改变知识 revision、图游标、运行实例或任务。
- Main 从真实知识读取能力、从现有模型配置读取公开选型。模型读取与运行选型共用逻辑，但登记不解密密钥、不发网络请求。能力来源 captureId 仅标记采纳，不冒充删除/重建代次。
- 公开 IPC 为 `workspace.members.list/get/preview/commit/receipt`，Bridge 只重导数据协议，前端不提供 actor、采纳正文或凭据。Main 先查原命令，再验证新提交的实例、版本、依据和当前来源。
- 预览/提交包含能力及模型公开配置指纹；跨知识、profile、调度存储仍是前后复核边界，不声称跨存储原子锁。详情每次显式查询当前差异，不因 registry 游标不变而缓存外部配置仍一致。
- 累计岗位 256、审计 4096 条/32 MiB；单能力 1 MiB、单事件 2 MiB。超限拒绝新写入，不裁剪原则/Skill、不删除历史。列表默认 20、最大 100；后续页必须固定原游标。

## 验收

1. 同一能力登记两个岗位，修改/暂停/退休不改变原身份；退休不可再次启用，跨工作区身份拒绝。
2. 能力与继承 Skill/profile 原位变化显示待采纳，编辑名称不自动采纳，显式采纳只变更选定一侧；凭据、默认选择不进入指纹。
3. 同命令幂等、异参冲突、版本/CAS 竞争、坏审计/重算日志校验、容量上限、保存失败与真实受理后丢回包；重开只查询原回执。
4. 旧 Store 无登记时零迁移写入；登记前后知识、图、周期、成员实例、任务及模型请求均不变。读取缺失来源仍保留原历史。
5. 类型、含类型依赖的架构检查、领域及服务/界面回归；同一最终 Windows EXE 真实登记、编辑、暂停、查询与重开，证明实际持久化且零模型请求。
