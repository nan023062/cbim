### 阶段一当前进展：内部 Loop 统一授权与回执

应用级运行监管现已接通：所有打开工作区的动态成员、派发任务、真实调度周期、旧 Loop 轮次及对话队列进入统一索引，按真实运行去重统计 token/费用，公开快照和无变化游标读取。桌面只读运行管理分别展示目标与模型轮次，支持筛选、异常说明及按原身份定位会话节点；自动协作只消费本轮登记任务的结果，故障进入监管诊断。监管不替代执行权限；独立全局准入处理公平等待，周期 token/费用软限额在真实运行之间核实。逐请求硬预算与通用历史邮箱消费尚未接通；详见[全局动态实例与任务监管](../docs/global-runtime-management.md)。

- 已接入统一 `authorizeRunTool`：read 同时拒绝业务写、知识写和命令；ask 对两类写入使用相同运行内审批；execute 仍经过平台边界、知识实例、版本与事务检查。
- 内部知识写入使用临时桥的一次调用授权，与业务工具共用当前运行权限。索引刷新在内部 Loop 中属于知识写入，不能借只读模式触发。
- 知识工具清单返回版本及副作用分类，gate 前校验 Schema 与工作区实例。预览可保存本地计划缓存，但不修改正式知识；维护检查和结构化问题不等同于正式知识写入。
- 已生成绑定 workspaceId/taskId/runId/toolCallId 的运行回执，包含输入和结果哈希、副作用及范围，区分 succeeded/failed/denied/unknown。回执随事件持久化并通过运行摘要返回；旧日志不补造回执。
- 审批等待期间停止会拒绝迟到批准；未知结果沿用显式核实后恢复，不自动重放。“本次全部通过”仍不跨运行继承。
- 验证覆盖真实 Pi 子进程（使用本机确定性模型服务，并非在线 LLM）的 read/ask/execute 知识提交、伪造授权字段、版本冲突、停止竞争及回执恢复。

主调度 Goal 三工具与 Dispatch 五工具已接严格业务输出：公开 scope 去除私有原生上下文，目标和图一次读取，输出核对可信运行、原请求和实际回执。坏回包不回滚或重放已提交记录，维护回执仍不能作为业务验收。单节点与完整图共用状态不变量。

执行计划/查询/步骤/交付四工具与求助/基线/检查点三工具也已接严格原 wire 校验。前者只绑定实际运行、不向旧计划补造身份；后者核完整成员绑定、调用与知识版本。保存成功后的坏回包不回滚、不自动重发，求助/检查点仍结束本轮。历史报告兼容缺哈希旧回执，但它们不能成为新运行证据。

上述运行能力与限制见[成员执行与结果回传](../docs/member-execution.md)。模型派发、查询、未启动撤销/单条前置替换、只读报告及可再次核实的新周期已接通，`cbim_dispatch_wait/result/message/revise` 仍是[待实现工具契约](../src/backend/scheduler-engine/tools/CONTRACT.md)。成员专属 `cbim_task_help` 正常终态后形成独立帮助信封；主调度可另派新任务，用真实新候选接续原未启动后继，或明确撤销后重新审阅并安全等待。取消不能替代成功，成员仍无递归派发权。原执行者的可恢复停泊、通用历史邮箱唤醒、成员启动表单及通用依赖修订待补齐。正式业务重规划不表示任意异常通道都能修复或续接。

**外层目标循环已接入：** `scope.goal` 冻结原始输入，保存图谱匹配计划及结构化审阅。正式派发先匹配计划，主轮结束后再次核验完成申请、当前知识/图版本、真实回执和本周期全部任务终态。失败或过期候选必须有真实后续任务替代；主知识提交同样经过审阅，人工项不能由模型批准或重规划删掉。没有新派工不能替代完成证明。重规划清除旧审阅，原始输入不变。

当前最多 32 次主调度运行、64 次目标变更。安全结算的 `awaiting_user` 保存 waiting 检查点，释放计算占用并暂停用户队列；正常退出或崩溃重启不执行，可取消，显式正文与文件/图片补充可沿原周期续跑，保留旧检查点并强制重规划；稳定请求只消费一次，普通队列仍暂停。`blocked`、缺审阅或不安全等待保存原因后失败关闭。完成门禁复核已登记的有界产物基线及必验文件，不能覆盖整个工作区，也不是跨知识/调度日志的原子事务；不将证据引用解释为人工验收。

### 已具备的静态架构与资源复用

- 团队架构与业务架构各是工作区唯一的静态定义图，已支持 Agent/Module/Skill/Workflow 表单维护、预览与提交，模块维护真人与确认记录同事务保存。
- 人才市场支持完整团队、单 Agent、单 Skill 的发布与应用；业务模板按完整业务架构发布与应用。三类资源入口共用仓库设置，本地仓库跨项目复用已验证；静态包不迁移运行记录、执行授权或原项目人员/源码绑定。
- 多个主会话同时拥有各自的动态任务图，节点关联成员实例、任务目标与模块列表。静态编辑/导入不创建成员或任务，不改写既有图；已派发任务的知识基线变化会要求重新准备。

本文旧概念 `conversationId` 对应 `rootSessionId`。当前桌面接入中，`rootSessionId` 取所属主对话的 `TaskSpec.taskId` 值，与派发节点的 taskId 语义不同。新主对话按 `conversationBinding` 归属真实实例，旧无绑定日志保留 role-only；只有显式续聊的新轮保存绑定，不改写历史。普通聊天轮次不伪造派发任务，下文宏观生命周期是目标模型，不是当前 TaskStatus 枚举；执行状态和业务验收始终分开。

## 1. 目标与设计依据

CBIM 是面向 AI 原生团队的生产与治理体系。工具架构应同时支持广泛参与者自主创造，以及核心治理者维持系统健康、理解和接管能力。

依据：

- [CBIM 架构设计理论](../docs/02-CBIM架构设计理论.md)：能力与业务独立，通过具体任务组合；知识、事实和授权分别表达。

## 3. 分层与依赖

保持 `main → scheduler-engine → core`。调度引擎与 Core 平级，单向依赖 Core；大脑通过注入的接口获得服务，不反向导入调度实现。

| 边界 | 职责 |
| --- | --- |
| 应用层 main | 装配工作区、真实身份、凭证、进程、文件系统和界面；实现平台适配 |
| 调度引擎 scheduler-engine | 组织目标、绑定能力与模块、管理依赖冲突、执行实例、验证和恢复 |
| Core 大脑 brain | 封装模型与 Loop，发起工具调用、报告执行事件，不自行签发权限或业务验收 |
| Core 领域服务 | Team、Workspace、Connector、知识及后续权限、证据、治理领域规则 |
| 工具适配 | 将领域接口描述为 `cbim_` 工具，完成参数和结果转换，不复制领域规则 |

桌面 UI 与内置 Loop 共用领域服务，执行权限由本轮可信上下文与工具网关核验。Team 不硬编码业务路径，Workspace 不永久绑定执行 Agent；二者通过任务绑定。

具体新增目录在实施阶段对照源码确定，本文不先行批量搬动现有文件。

| 工具组 | 入口与当前状态 | 输出与边界 |

## 5. 统一执行通道与权限

每次调用经过：识别工具 → 参数校验 → 任务与作用域校验 → 授权 → 执行 → 持久化回执 → 通知调度引擎。

原生 `bash/write/edit` 和内部知识提交必须进入同一策略入口；只读模式应同时限制两类写入。路径检查仍保留，但任意 shell 的隔离保证必须由实际执行环境提供，不能仅靠字符串匹配宣称已隔离。

### 工具注册信息

| 字段 | 含义 |
| --- | --- |
| id/version/inputSchema/outputSchema | 稳定身份、协议版本、输入输出校验 |
| effects | 读取、修改、删除、发布等副作用分类 |
| scopeResolver | 根据参数和可信环境解析实际影响对象；未知范围明确返回未知 |
| authorization | 所需授权及不可豁免的领域规则 |
| idempotency/recovery | 是否支持幂等、如何查询结果、能否安全重试或补偿 |
| evidence | 回执中应包含的产物与验证事实 |
| cancellation | 可取消阶段、取消后可能已经发生的影响 |

身份、授权和执行关联由可信运行时注入，不接受模型提供 `approved: true` 作为依据。权限按主体、工作区、任务范围、动作和有效期表达。

“本次任务全部通过”只免除明确范围内的重复操作询问，不扩大读写范围，不替代正式架构审批。沿用现有当前运行授权语义；续聊或队列下一轮不静默继承。未来若扩展授权生命周期，必须显式说明并版本化。

## 6. 任务、事件和恢复契约

以下描述目标契约。现有计划修订、派发任务和运行身份按各自实际协议使用；尚未实现完整业务验收状态和产物版本检测。

| 标识 | 区分 |
| --- | --- |
| rootSessionId（原 conversationId） | 用户与主 Agent 的会话，可包含多个派发任务；当前取主对话 taskId 值 |
| taskId/taskRevision | 可验收目标及其版本，跨重试保持目标身份 |
| runId | 某次执行尝试；恢复或重试的关联必须明确 |
| toolCallId | 单次操作及结果关联 |
| knowledgeBaseline | 本次使用的知识、Skill、Workflow 版本集合 |
| artifact/evidence/decisionId | 产物、验证依据与人工决定，不能混用 |

任务主状态：待定位 → 已绑定 → 可执行 → 执行中 → 待验证 → 已验收；另有等待输入、受阻、失败、取消。检查点与交付状态分开，执行完成事件不能直接推进到已验收。

模型提出计划和调整理由，调度引擎校验后持久化状态。普通问答不强制创建复杂任务；空项目允许有边界的探索，不伪造模块或 Agent 归属。

Loop 事件自动记录工具启停、实际操作回执、验证结果和取消事实；模型补充意图、专业判断与未知范围。回执绑定输入版本和产物版本，文件随后变化时，相关验证必须重新判断有效性。

恢复先核对在途实例及外部结果，再决定续跑。未知结果保留为“待核实”，不能当成未执行自动重放。外部非幂等操作在没有可靠去重或结果查询时禁止盲目重试。停止不等于回滚；补偿操作单独记录。

持久化优先使用现有本地工作区运行存储，不要求建设服务器。团队长期知识与运行证据分开保存，通过引用关联；跨设备接管需要显式传递完整所需记录。

### 依赖与并行

- 模块层级和静态引用帮助理解架构，不直接决定执行顺序。
- 产物前置边必须说明所需产物、版本和放行条件。
- 共享文件、资源和环境形成冲突约束；无业务依赖也可能必须串行。
- 当前已具备成员串行、只读并行及工作区写入互斥；扩大并行范围前继续验证唯一写入责任与租约释放，补齐公平调度、等待让槽和异常恢复。
- 范围调整只重新核验受影响任务；更改在途任务前停止相关旧范围写入并交接。

## 7. Skill 与 Workflow 的执行方式

Skill 表达专业方法；Workflow 表达模块操作的步骤、条件和出口。保留 Team/组/Agent 的 Skill 父链继承，保留 Module 仅使用自身挂载 Workflow 的规则。跨模块共享通过显式引用，不隐式继承父模块 Workflow，也不复制共享正文。

内容拆成两个互补部分：

- 自然语言方法：分析、判断、示例和专业取舍，由模型运用。
- 结构化契约：稳定且可验证的前置条件、工具需求、证据要求、出口和人工决定，由程序检查。

不将整篇自然语言强行转换为固定步骤。先程序化已有稳定约束，探索步骤可调整但留下理由。Task 绑定实际使用版本；恢复时比较相关变化，不能默默换入新规则。

例如 Workflow 要求真实浏览器验证，语法检查不能替代该出口。对美术、策划、QA 等产物采用对应专业验证，不统一要求编译或单元测试。

## 8. 渐进式治理与正式知识保护

治理主线：业务产物 → 模式观察 → 方案评估 → 人工决定 → 实施与验证 → 正式规则生效。

观察保存证据、相似点与差异、反例、影响范围、处理建议和复查条件。继续观察、暂缓、驳回均为有效决定；相似度和重复次数只触发调查，不自动触发抽象或重构。没有新证据时避免重复提案。

正式变更方案包含目标契约、不变量、替代方案、使用方、迁移顺序、验证与回退条件。批准绑定方案版本、范围和真实负责人；范围改变后检查批准是否仍适用。批准、实施、验证、迁移完成和正式生效分别记录。

通用知识 CRUD 同样检查正式契约、已登记稳定层和公共规则的变更，不能通过直接修改 Markdown 绕过审批。只保护项目实际确认的对象，不根据名称或复用次数自行建立冻结清单。

区分两种图：实现现状图随代码更新；正式约束图承载经确认的设计决定。现状与约束不一致时记录偏差，不能自动用现状覆盖正式约束。

业务验收与治理待办分开：非阻塞观察可以在业务交付后继续处理；必要契约或验收条件未满足时不得用待办替代通过。

## 9. 人工认知保障

| 变更影响 | 交付内容 |
| --- | --- |
| 普通局部修改 | 产物差异、验证、已知风险和未知范围 |
| 跨模块变化 | 关键数据流、职责变化、使用方与联动验证 |
| 公共契约或稳定层 | 方案取舍、不变量、失败路径、迁移、排查与恢复办法 |

评审展示具体差异、原始证据与待决问题，允许要求补证、提出异议或确认方案。以负责人实际反馈和必要接管演练记录认知状态；已读标记、发送文档及 AI 自评都不等于已经理解。

没有账户认证时，记录“本机用户确认”及具体反馈，不声称已核验团队负责人身份。正式身份核验属于后续账户能力；当前不能伪造其保证。

局部任务可在同一交付说明中表达，不强制产生多份文档。高影响任务再安排必要复查，不能擅自创建周期任务或承诺固定复盘期限。

## 10. 分阶段实施与验收

保留原五阶段的范围与行为验收；以下“当前状态”说明已落地部分，“剩余”说明距离阶段目标的缺口。成员基础提前实施不取消前序验收与治理要求。

### 阶段一：统一工具、权限和回执

范围：工具注册契约、原生与知识操作共同授权入口、执行身份、事件回执；迁移现有工具，不先扩张工具数量。

当前状态：内部授权、输入与标准返回协议、知识工具严格业务输出、真实取消/恢复元数据、按需目录及运行回执已接通。剩余为其他工具业务输出 Schema、精确作用域、取消/幂等/恢复声明、回执审阅及真实隔离；链接器接入时也须复用这些边界。

验收：只读模式同时拒绝业务写与知识写；伪造授权字段不能放行；任务内放行不跨运行泄漏；所有副作用关联真实调用回执；停止和未知结果可区分；已有知识版本冲突与事务测试继续通过。

### 阶段二：单 Agent 任务闭环

范围：自然语言目标、候选定位、上下文绑定、任务版本、执行、验证及交付，优先串行运行。

当前状态：执行计划、步骤、候选及上下文绑定已接通；主调度已保存图谱匹配、逐项证据审阅及真实完成门禁。有界选定文件指纹和外部变化复核已实现，持久人工接受/拒绝/补证、独立按决定继续、最终依据复核及新任务返工已完成；完整产物覆盖与跨等待决定适用性仍待完善。成员候选与主模型的完成申请都不等于人工验收。

验收：普通问答不被繁重流程阻塞；执行结束仍进入待验证；缺证据不能自动验收；修改产物后旧证据不会无条件沿用；重启不重复执行未知结果操作；范围调整保留历史。

### 阶段三：Workflow 检查点

范围：结构化前置、证据与出口，运行恢复、任务依赖、必要人工决定。

当前状态：Skill/Workflow 正文、继承/挂载规则、成员版本基线和派发前置校验已接通。Step16a 新增可选严格约定，按实际工具能力、业务操作前计划、审批后版本、真实成功回执及副作用完成边界核验交付，结算与审阅从 canonical 重算。Step22 首种有界 JSON 验证使用冻结规则与真实文件字节；rejected 不满足出口，交付/审阅及人工接受核实全部必验文件当前状态，负面决定保留历史依据。Step23 显式流程选择贯穿计划、派发、准备及证据匹配，改选需新任务，主角色不执行业务Workflow。剩余为更多专业验证器、细粒度产物/模块出口、通用推进/暂停/恢复；结构合法不能替代业务判断，已有任务检查点不能代表全部 Workflow 能力。

验收：执行前置未满足不能启动或放行对应步骤，允许登记等待依赖的任务；指定的专业验证不能被其他检查替代；Workflow 变化能触发基线核验；无专属 Workflow 时仍可按已授权的通用流程执行；取消不宣称回滚。

### 阶段四：治理与认知交付

范围：观察、提案、版本化人工决定、实施与正式生效、分级理解材料。

当前状态：已接通 Module 绑定正文的窄闭环：明确登记保护、真实观察、精确提案、本机批准/驳回/暂缓及复查条件、独立实施与原知识事务核实。统一知识入口保护已登记定义、正文绑定与模块可见性；新提案/知识版本不能沿用旧批准。主 Agent 四工具已接通有界获取、真实观察、精确提案及原回执，来源可追溯；本机可明确补证/异议，新方案冻结原意见引用并由本机逐项评价回应，来源替代不改旧历史但拒绝新的批准和实施。其余为通用稳定层/公共契约与业务迁移、持久解释和实际接管验证。桌面批准不是认证负责人签署，回应评价不等于理解认证，知识提交不等于业务迁移验收。

验收：重复信号不自动重构；暂缓/驳回保留理由和复查条件；通用 CRUD 不能绕过正式规则门禁；旧方案批准不能无条件用于新方案；本机确认不冒充认证身份；业务验收与后续复查状态分别展示。

### 阶段五：链接器与多 Agent

范围：成员实例与显式执行基础已前置实施，后续优先接通模型驱动的派发与结果续跑，再完善主调度组织的多阶段协作；以一个真实链接器单独验证外部操作契约。Step17b1/17b2 资源仓库已完成桌面授权、HTTP、撤销/原命令核实及主 Loop 两项只读工具，固定原连接并保存精确范围回执。

当前状态：独立成员、主实例、默认执行者、调度周期、结果回注、占用互斥、全局统计及角色履历已接通；周期目标、图谱计划、证据审阅、完成门禁、独立增量状态、安全等待、显式补充、只读核实、正式业务重规划、成员求助安全交接及未启动任务撤销/单条前置替换已实施。全局并发准入、稳定等待票据、设置和会话提示也已接通。周期计量、token/费用软限额和同周期一次有界文件检查点续执行已完成；资源仓库桌面授权、HTTP 核验及主 Loop 只读工具已通过；其余为逐请求硬预算、通用停泊/跨重启恢复、依赖修订、成员资源授权及通用链接器。只读核实保持旧结果与日志；新业务按独立目标与明确权限启动，不能据此认定旧业务已验收。

验收：凭证不进入模型上下文；外部非幂等调用不会盲目重放；并发写冲突可阻止；下游只消费有效产物；子任务失败只阻塞真实依赖部分；实际执行身份、权限及交接可追溯。


各阶段先通过自己的行为验收再扩大范围。阶段顺序不是上线日期承诺，也不授权自动发布、建立远端服务器或改变现有项目规则。

3. **补协作等待和压力控制（阶段五，已部分完成）。** 结构化求助、安全终态交接、主调度补做、未启动依赖撤销/单条前置替换已接通。独立并发准入、FIFO 等待及同工作区写入防饥饿已完成；等待不持运行名额或业务锁。可信周期运行归属、计量、用户明确配置的 token/费用软限额和超限收口均已接通；逐请求硬预算须另有覆盖重试/摘要的可靠请求门禁。有界文件基线及同周期一次检查点续执行已完成；通用成员等待、跨重启和异常通道修复后续完善。派发权仍只属于主 Agent，已有停止、互斥、中断记录与用量统计继续复用。

## 11. 成效评估与非目标

关注真实任务的自主完成率、返工、证据有效性、接管成本、知识一致性和治理成本。工具数量、Agent 数量、扫描频率、抽象数量与去重率不能单独证明成熟度。

本计划不要求立即重写 Pi、一次性程序化全部 Skill、为每个小任务增加审批或建设自有云端。第一阶段的可见目标是：能够解释执行依据、允许范围、实际副作用、完成证据及仍需人承担的决定。
