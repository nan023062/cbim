## 只读场景走查

下表为基于现有实现与历史回执的人工决策走查，不是重新运行 GitHub 或安装测试。

| 场景输入 | Skill 应给出的处理，已逐项核对 |
| --- | --- |
| 无证书，用户已选择个人未签名发行 | 复用选择，三个入口显式 unsigned；不重复购买询问或自动降级 |
| 用户要求签名，但当前只有 SignTool | 区分工具和证书；继续独立准备，明确签名条件缺口，不伪造已签名 |
| 后续从当前桌面版升级、或切换签名／1.x | 先修正现有固定旧版／模式／版本约束并验证，不仅更换 workflow 输入 |
| 草稿 create 回包丢失，列表暂时为空 | 查原 ID／有权限的分页实态，不重新 create |
| 只读 token 看不到草稿 | 核实草稿读取权限，不把空结果当作不存在 |
| 四附件只上传两项／同名摘要不同 | 只补确认缺失项；不一致停止调查，不 clobber、不 replace |
| 公开 PATCH 返回 404 | 按 ID 查实态，再核身份、目标和权限；不假定缺失、不重复建 Release |
| 公开请求超时但已公开 | 核验原 ID、tag、四附件和旧 latest 后继续在线验收，不重复发布 |
| 注解 tag SHA 不同／已有日志 | 比较 peeled commit，按日志恢复；不强推标签或删除日志 |
| 定向诊断绿色／旧 head 绿色 | 核对当前 PR head 与完整四片，不把诊断冒充合并门槛 |
| Windows 换行、8.3 TEMP、下载 504、缓存 nlink=2 | 按证据修正环境，保留产品路径／硬链接保护；只依赖安装有界重试 |
| LPAC 退出、终端超时、检查点持久化未完成 | 查真实宿主／输出／状态与测试前提，不弱化隔离或无依据宣称根因 |
| 本机已有用户安装，希望用 /D 验收 | 转隔离 runner，不卸载真实客户端、不伪造 CI 环境 |
| 升级已安装但末尾签名读取／窗口定位失败 | 查已安装实态，修正 pwsh／DOM 或等待就绪；不无条件重装 |
| 候选与验证 head 不同，产品或构建输入变化 | 新候选和受影响制品验收；仅外部文档／CI 差异需记录依据 |
| 官网仍旧版本、Pages 未部署、分支分叉 | 依据公开回执同步，核实 master 部署和匿名字节；有界只读复核，不强推或删除未知工作 |
| 仅请求评估发布方案／创建 Skill | 不执行发布、安装或 CI 派发；只做本次适用验证 |
