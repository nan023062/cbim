## 正式 0.1.0 到 0.1.1 的线上升级

1. 在本次独立安装目录安装已公开的 0.1.0；旧包 SHA-256 `1c3183f6e394357d56f870258e2284ce67cf3c9ad053a5ed3e0b9867498a6be3` 与 GitHub 原附件一致。保留本次验收的工作区、已完成对话、模型配置、本地存储及用户目录标记。
2. 正式 0.1.0 自动检查公开桌面通道并发现 0.1.1，显示新版日志；点击下载后，缓存安装包的 SHA-256 与本版发布附件一致。
3. 下载完成后正常退出、重新打开，实际安装版本仍为 0.1.0，原标记保留，证明普通退出和下次启动未自动安装。
4. 再次明确下载使用已校验缓存，点击“停止任务并重启安装”。只发起一次在线安装；检测到安装目录内的新进程，带有 `--updated` 和原 `--cbim-user-data-root`，渲染进程也使用原 `user/desktop`。
5. 后续只读／界面补验确认实际版本 0.1.1、正式更新启用、账号菜单可查看本版日志；手动检查返回 current，未提供更高版本。工作区、原 task/run、模型配置、本地存储和用户目录标记均保留；仍只有原一条 completed 运行，没有重放。

首次验收脚本检测到新进程与窗口句柄后即请求正常关闭，没有等待渲染页面就绪；随后出现加载 `index.html` 的 `ERR_FAILED (-2)` 启动提示，关闭等待超时。保留 `online-upgrade-failure.json` 和重启回执，没有把首次流程记为全程通过。经精确进程／窗口核对后关闭该提示，原进程退出；未再下载安装或修改产品代码，使用相同更新启动参数重新打开已安装的 0.1.1，等待真实页面就绪后完成上面的数据与界面验证，正常退出通过。上述证据支持验收关闭时机干扰加载；未将这次被提前关闭的自动重启窗口写成已经完成界面验收。
