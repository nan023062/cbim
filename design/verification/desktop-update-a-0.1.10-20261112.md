## 先准备 A 和测试环境

1. 使用没有 CBIM 用户安装的独立 Windows x64 测试机或虚拟机，保留快照。仅另选安装目录不能隔离 NSIS 的注册安装信息。
2. 在测试机运行本次 A 安装包，启动后打开左下角用户菜单 → **版本与更新**，确认“当前版本 0.1.10”。不要用 `pnpm start` 或便携包替代。
3. 创建测试工作区，保存一条可识别的记录或文件，记下已有设置和历史。后面用这些内容确认升级保留数据；点击重启前保存所有未提交编辑。
4. 在 B 可被发现前，确认 `%LOCALAPPDATA%\cbim-desktop-updater\installer.exe` 存在，并与上面的 A 安装包 SHA-256 一致。正常 NSIS 安装会缓存自身；不要清理这个目录。下载 B 后缓存可能更新，不再要求它始终等于 A。

可在测试机只读检查旧安装包缓存：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath "$env:LOCALAPPDATA\cbim-desktop-updater\installer.exe"
```

## B 如何让 A 发现

建议 B 使用 `0.1.11`，实际准备时再次确认大于 A 和届时的公开稳定版。B 可先只提高版本并增加测试用更新日志，保持引擎和依赖不变，便于观察小改动的差分量；具体节省比例必须实测。

现有应用固定读取 `nan023062/cbim` 的公开稳定 `desktop-v<版本>` Releases，**不读取草稿、预发布、本地文件夹或任意测试地址**。目前最新公开版仍为 0.1.9，所以本地装好 A 后显示“没有更高版本”是正常的。

后续由发布者按既有流程准备 B：更新 package.json 和 `design/releases/desktop-v0.1.11.md`、冻结干净提交，执行 `pnpm make:desktop --unsigned`，核验同一候选并完成发布所需检查。正式通道必须提供匹配的四个附件：

- `CBIM-Setup-0.1.11-x64.exe`
- `CBIM-Setup-0.1.11-x64.exe.blockmap`
- `latest.yml`
- `SHA256SUMS.txt`

为测正常冷缓存差分，A 也应按原流程公开其准确的 `desktop-v0.1.10` 附件，尤其是与本次 A 安装器匹配的 blockmap。首次手动安装 A 通常没有旧 blockmap 缓存，更新器会从 A 标签下载；A 的 blockmap 不可取得时会正常回退全量。不要另造同版本 A 包后覆盖旧附件。

**公开 B 会让所有符合条件的稳定通道用户看到它，并非只给测试机。** A 原生没有独立测试通道；要本地私测需要额外的测试入口。后续已通过[外部本地网络测试启动器](desktop-update-b-local-20261112.md)提供该入口，不改 A 或公开源。直接双击 B 安装器只能测试覆盖安装，不能验证 A 的后台下载或差分。

现有 `desktop-acceptance` 自动化输入仅列出旧交互版本，尚未接受本次 A 作为 previous_version；后续若用它验收 A → B，须先适配预下载/显式安装交互，不能只把输入改为 0.1.10 就声称已覆盖。

## B 可见后，按这个顺序体验

1. **后台下载：** 保持 A 运行，不点下载。启动约 10 秒后的检查或下一分钟检查应发现 B；也可点击“检查更新”。看到“正在后台下载并校验”，完成后看到“重启安装”。下载很快时可能直接看到已就绪。
2. **不中断工作：** 下载期间关闭更新弹窗、继续操作工作区，确认窗口与任务没有因下载退出，当前页面未提交编辑仍在。即使下载完成，不点重启也不应自行安装。
3. **普通退出不安装：** 保存编辑，正常退出并再开 A，确认仍是 0.1.10。联网检查和缓存重验后应再次就绪，不重新传输整个 B 安装包。
4. **明确安装：** 保存编辑后点击“重启安装”。等待任务正常关闭、原 NSIS 安装器执行和应用重启。在新进程确认版本是 B，并核对工作区、设置、历史和业务文件。

可以分别记录“发现 B → 已就绪”和“点击重启 → B 可用”两段时间。本次优化主要减少等待下载的时间与流量；NSIS 的解压、写盘和安装方式没有改变，不能期待这一段必然变成即时完成。

## 如何确认确实走了增量

安装版界面没有“实际差分字节数”字段。快慢、进度百分比、已就绪状态或最终缓存 EXE 大小都不能单独证明走了差分；最终缓存必须是完整安装包。

完整验收需另外记录 A 下载 B 时安装包的 Range 请求、206/Content-Range、实际传输字节以及是否又回退整包，比较 B 的完整包大小，并最终确认 SHA-512 校验和安装成功。可以先用上述步骤验收安装体验，再由专项网络记录量化差分收益。本轮只已有真实下载器 HTTP 样例的差分证据，尚无 A → B 制品的实际流量数据。

回退场景应在另一个隔离快照测试，保留正常缓存的基线环境。缺旧安装器、缺 blockmap 或不支持 Range 时，全量下载并校验后仍可升级是正确结果；下载/校验失败必须显示错误并允许重试，不能安装半包。
