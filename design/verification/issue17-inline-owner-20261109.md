日期：2026-11-09。范围：[Issue #17](https://github.com/nan023062/cbim/issues/17)。

模块卡片直接提供负责人下拉框，包含自定义 Agent 与内置执行 Agent，不含主 Agent；选中即经原服务校验并保存，无说明表单或二级页面。已登记岗位保留原能力和模型，同一 Agent 多岗位在同级区分；首次选择无岗位的 Agent 时采用设置中的已选默认模型，先登记真实岗位，再保存模块责任。没有默认模型或岗位停用/退休时明确提示，不造配置或隐式重建。

卡片新增「+ / 编辑笔 / 删除桶」操作，打开原知识编辑器；删除仍先预览影响再确认。完整岗位/责任维护入口保留用于来源采纳与历史核实，普通设置无需进入。

## 维护与恢复边界

快捷编排在 `frontend/workspace/inline-module-ownership.ts`；共享读取、界面代次和选择器在 `InlineModuleOwner.tsx`；卡片在 `WorkspaceView.tsx`。两类命令池分别从原 state 模块导出，完整表单与卡片共享同工作区未决记录；`submit` 返回自己的命令记录，避免误取别的页面最后一条。

两个写入不是跨服务原子事务：岗位已登记但负责人失败时保留真实部分成功。任一步未知停止后续；核实和重开只查询，不自动完成剩余绑定。用户再次明确选择时复用已登记岗位。前端便利入口不改后端岗位模型采纳、权限、来源、责任版本、任务影响或派发规则，不启动模型。
