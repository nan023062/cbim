## 已实现范围

同一个工作区 DispatchStore 保存唯一模块责任关系、独立 ownershipCursor 和不可变审计。设置、更换、解除保留稳定 bindingId 并升版；成员反查只返回当前负责关系。岗位暂停保留关系，有引用时退休在同一事务队列拒绝。模块来源失效仍能读取历史并明确解除；来源观察不冒充删除重建代次。

Main 六项 `workspace.ownerships.*` 共用预览、串行核实和原命令回执。主 Agent 四项工具先发现岗位摘要，再核实际模块；身份与命令来自真实本轮闭包，严格输出核同一实例，旧回执查询保留原实例。read/ask/execute 使用原有治理写权限。责任提交仅在准确工具/效果/范围匹配时不单独构成业务工作，已有目标、派工、副作用时间线和完成证据门禁不被清除；四项回执不能充当业务验收。

桌面业务架构和项目岗位共用责任面板。读取/编辑切换隔离迟到响应，三项依据固定分页；先预览、明确保存、查询原命令，未知不换ID重做。近20条审计以中文条目展示，真实主运行与本机提交来源分别显示；原命令可展开核实。岗位退休引用拒绝直接可见，仍可回到编辑；本机不一致状态不会把已有未知事实伪装成未受理。
