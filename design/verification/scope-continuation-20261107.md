> 历史快照：正文中的目录、完成状态与验证数字保留记录日期的事实，不是当前实现清单。四层迁移后的现状请看 [源码契约](../../src/CONTRACT.md) 和 [Logic 边界](../../src/logic/BOUNDARIES.md)。

日期：2026-11-07。承接安全等待提交 `9670604`。

## 已实现

- 当前等待目标可“补充并继续”：冻结纯文本、明确模型及权限，以稳定命令 ID 保存一次性启动意图，再恢复原主会话和原 scope。原始输入不改写，补充及旧检查点追加归档。
- 新输入版本使旧计划失效，必须重新规划；原有 human 验收项保留，任何补充文字都不签署人工验收。主运行 32 次与目标变更 64 次上限跨等待和补充累计。
- 请求重试只查询原意图；同 ID 改参、旧 wait、跨身份或已关闭目标拒绝。重启不自动重放已消费但未完成的意图。
- 取得租约并核实旧运行日志后才消费等待；停止覆盖工厂、提交、日志初始化和引擎准备。日志初始化期间停止仍保存完整取消记录，不留下空日志破坏会话读取。提交后读取失败只收束本次可信 runId，不能关闭较早回执对应的运行。
- 对话卡与任务根共享表单和冻结请求。先保存再发送；未知结果仅查询或同 ID 原请求重试，重开只查。窗口切换时复用仍在途的控制器，防止迟到回执覆盖新草稿。
- 聊天草稿、附件及普通队列独立。续跑后队列仍暂停并显示已接收补充，目标结束后可显式继续队列启动下一独立目标。
