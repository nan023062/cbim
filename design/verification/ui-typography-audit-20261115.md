# CBIM 字体、图标与状态样式审查

日期：2026-11-15  
基线：160a703c（release/agent-0.1.21 工作树）  
性质：设计审查与建议，未修改产品源码，未完成真实客户端逐页视觉验收。

## 用户要求

普通文字应使用相同字号，整体视觉与对话流程保持一致；参考 Cindy 的界面语言。字体大小、粗细和状态均纳入审查，图标大小与描边一并核对。本报告不恢复旧 Team/频道工作流。

## 范围与方法

主审与独立设计审查 Agent 只读核对用户截图、View 页面与共用组件、全部 View CSS、样式入口及外观设置。源码声明不等于最终 computed style：加载顺序、选择器优先级、浏览器默认字重及用户字体设置会改变实际显示；本次不是全部页面的截图验收。

参考 [Cindy Design System §3、聊天展示](https://github.com/makecindy/cindy/blob/main/docs/design-rules/DESIGN.md)：沿用克制的字重、共享排版入口和轻量工具过程。Cindy 自身区分 UI 与正文档位；本报告按用户要求为 CBIM 进一步收敛普通文字，不声称 Cindy 全部文字同字号。

## 直接发现

1. 截图中同一用户目标被赋予不同语义。conversation-topics.css 的 .conversation-topic-title 是 15px/600；.conversation-topic-thread h3 是 18px，默认粗体未显式收敛。长目标不是真正的短标题，整段加粗造成视觉噪音。
2. 新对话也未统一：主正文后置规则为 15px，工具概要、状态和原调用详情仍存在 12/13/14px。外观设置只命中 .chat-message 和部分代码块，未覆盖所有调用详情与普通 UI。
3. shell.css 与 interface.css 都声明根字体和字号；业务页继续用固定 px。最后加载 interface.css 不能覆盖所有更具体的选择器，因此不是单一排版来源。
4. 设置中的说明、标签、输入、按钮为 12px，页标题却可达 27px/600；其它设置导航、辅助说明仍有 10/11px。多级缩小令需要阅读的内容难以辨识。
5. Icon.tsx 已有统一 24-unit viewBox、1.75 描边和圆端点，基础可复用；调用者却各自传 size，部分下拉箭头用字符“⌄”。不能把进度环、品牌图标与普通操作图标机械视为同一图形。
6. 普通短标题存在 600 或默认 b/strong/h 标签粗体，另有 550/700 样式。状态需要颜色与明确文案，而不是到处加粗。
7. 窄屏调整 root 到 15px，但固定 px 子元素不随之统一；手机触控目标变大也不等于图标或文字必须随之放大。

## 建议采用的 CBIM 排版规范

这是待实施设计，不是当前已生效值。所有普通阅读文字共享一个可整体调整的 token，禁止页面自行再缩小。

| 内容角色 | 默认字号 | 字重 | 约束 |
| --- | ---: | ---: | --- |
| 普通正文、用户/Agent 消息、输入、工具摘要和结果、表单标签/说明、按钮/菜单、状态、Tooltip | 15px | 400 | 同一普通字号；正文行高 1.6，紧凑单行控件按统一高度 |
| 短分区/卡片/对话面板标题、选中项 | 15px | 500 | 与正文同字号，靠间距与适量字重区分 |
| 真正的弹窗标题 | 18px | 500 | 只放短标题，正文不搬入 h2/h3 |
| 真正的页面标题 | 20px | 500 | 不在每张卡片重复 |
| 时间、字节数等纯元信息 | 12px | 400 | 明确例外；错误解释、状态说明、帮助文案不属于元信息 |
| 代码与结构化日志 | 14px 等宽 | 400 | 复用用户代码字号设置，长行受控滚动 |

- 主界面字体族只有一个入口，保证中文回退和标点一致；Inter 未实际装载时不能假定已生效。
- 普通 UI 不用 550/700；选中/展开可用 500，但不得改变字号、容器尺寸或导致换行跳动。
- Markdown 的用户内容语义独立：保留真正标题、列表、代码和局部 strong，不通过全局 b/strong 重置摧毁内容语义。
- 用户主动调整字体时，全套普通文字同步调整；代码独立配置。设置预览必须对应真实展示，不只覆盖聊天气泡。

## 图标与状态规范

- 复用现有 Icon 字形与统一描边。建议内联/普通控件 16px，独立工具栏 20px；24px 以上只用于明确的空态/说明图。不得因成功、失败、禁用而临时换尺寸。
- 保留 24-unit viewBox 与统一 1.75 描边参数，显示尺寸和描边的比例须在 100%/125%/150% 缩放下光学校验；不得把 viewBox 数值误写成实际像素线宽。
- 文字下拉箭头改用统一 chevron；同动作跨页面使用同一图形。进度环仍按真实进度展示，其尺寸/线宽单独登记。
- 普通/悬停：字号与字重稳定，轻量背景反馈。
- 选中/展开：短标签最多 500，配选择标记或边界；禁止整段任务目标加粗。
- 运行中：同一状态行，图标和明确动作文字；仅运行图标需要旋转，减少动效时仍可辨识。
- 等待用户：明确“等待选择/等待批准/等待补充”，同字号呈现缺口及操作。
- 成功/失败/警告：语义图标、颜色和文案共同表达，不只靠颜色，不用大粗段落；详情按需展开。
- 禁用：不变小、不变细，保留原因提示及可访问名称；颜色/对比单独验证。
- 停止与结果未知必须保留不同文字和事实，不为视觉统一合并业务状态。

## 对话流的明确设计

用户消息与 Agent 正文采用同一排版基线。执行过程使用可展开的紧凑工具行；调用其他 Agent 也是该工具行，展开后复用同一消息流。递归只反映调用关系，不额外放大标题或缩小子 Agent 正文。结果与错误回到原工具调用；不复制长目标成为列表标题和右侧巨型标题。对话、历史和调用详情共享排版组件，保留现有消息身份和运行行为。

## 后续真实视觉验收边界

实施后在每一页面族检查实际 computed font-size/font-weight/line-height，而非只搜索源码。至少覆盖亮/暗、桌面 100%/125%/150%、320/390px 窄屏、长中文目标、错误/等待/运行/停止/禁用/选中、2–3 层递归，以及键盘焦点和减少动效。记录可读性、截断、换行跳动和滚动，区分真实页面截图与设计示意。不得宣称本报告已完成这些验收。

本轮未修改产品源码、未运行产品测试、未改变 CI/发布状态。

## 独立设计审查补充

设计审查 Agent 确认覆盖 55 份 View CSS。另定位两类状态漂移：member-activity.css 将 result_ready / interrupted 分别设为 success / danger，interface.css 又覆盖为 warning；同一状态不应由加载顺序决定颜色。公共禁用按钮 opacity .55、发送按钮 .35、部分引擎选项保持 opacity 1，应统一禁用可读性规则，并区分不可选择但可安装的项目。team tree 的 hover/selected 不应只有相同背景而没有选择标记。

这些是样式来源冲突的静态证据，最终可见色彩、对比及字号仍须浏览器计算样式和真实页面验收。统一设计时不能把 result_ready 误标为已验收成功，也不能把 interrupted 的未知执行事实简化成普通失败。
