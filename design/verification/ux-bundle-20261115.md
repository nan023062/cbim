## 实际验证

- `pnpm typecheck`：通过。初次发现延迟入口参数推断为 never，已用目标组件参数的显式类型消除，未使用 any 放宽入口。
- `pnpm exec vitest run tests/deferred-view.test.ts`：3 个单元通过。选择原因是新增装配机制改变首次加载与 Suspense 输出；覆盖声明不加载、等待提示、解析后传递 props，未加载完整 Application。
- `pnpm check:test-modules`：501 文件，unit=150、contract=155、integration=196，测试归属和边界通过。
- `pnpm check:architecture`：128 个目录、758 个源码/样式文件、架构文档无差异；1525 文件、7430 依赖、0 循环和违规。
- 实际生产构建产物浏览器检查：欢迎页和设置显示正常；设置首次打开才请求对应代码；资源目录草稿在分组切换后保留；取消离开仍留在设置并只询问一次；确认离开请求运行管理模块。8 个动态入口全部导入成功，无全局页面错误。
- 独立 DeferredView 浏览器夹具：未挂载不加载、首次失败显示局部提示、显式重试成功、旁侧输入保留、页面自身输入在父层重绘和隐藏再显示后保留，5 项通过。

浏览器使用隔离内存 IPC，没有真实账号、模型或项目写入。为了注入夹具并读取浏览器断言，仅隔离测试 HTTP 服务移除了响应中的 CSP meta；生产 `index.html` CSP 未改。因此不将此检查称为生产 CSP 验收。运行管理模块成功加载，但后台页签会暂停轮询，不将其当作真实运行数据验收。重试夹具采用首次拒绝、随后成功的 loader，不证明浏览器缓存的失败导入一定可恢复。
