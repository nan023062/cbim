## 一、总体目标

让持续交付与项目长期健康同时成立：AI 完成当前目标，团队获得可验证的产物、可复用的知识和可理解的结构，使下一次开发更容易定位、判断和接管。

要同时处理四种张力：单次交付与长期维护、快速试错与结构稳定、自动产能与人工理解、丰富知识与有限上下文。没有一项工具或一次架构设计能单独解决它们，需要明确的知识组织、执行约束和持续反馈。

本体系面向完整游戏研发：程序、美术、策划、Quality Assurance（QA，质量保证） 都可以拥有业务模块和产物。模块按专业职责与业务边界组织，不以“是否包含代码”作为成立条件；任务根据目标、产物类型及工具要求绑定合适的能力 Agent。

## 二、思想体系及其分工

| 部分 | 核心问题 | 专项文档 |
|---|---|---|
| CBIM | 专业能力、项目知识与个人工作记忆怎样组织，如何独立演化并在任务中组合？ | [CBIM 专项设计理论](02-CBIM架构设计理论.md) |
| 渐进式架构演进 | 如何允许探索与短期重复，又保留有依据的收敛能力？ | [演进与认知专项理论](03-渐进式架构演进与人工认知保障体系.md) |
| 人工认知保障 | 当产出由 AI 加速时，人如何仍能理解、决策、排障和接管？ | 同上，与架构演进协同论述 |
| 全流程设计 | 谁在何时做什么，留下什么证据，如何审批、恢复与验收？ | [全流程设计方案](04-AI-Native开发全流程设计方案.md) |

CBIM 的组织对偶是 **Agent + Skill（能力侧）与 Module + Workflow（业务侧）**，分别由 team/ 与 workspace/ 承载；完整定义见 [CBIM 专项设计理论](02-CBIM架构设计理论.md)。

CBIM 提供知识与能力的组织基础；架构演进决定业务结构如何成长；认知保障让结构变化始终有理解它的人；执行方案把这些要求转成具体工作安排。

Feature / Refactor 表示 CBIM AI 助理在本次任务中组织的业务交付或架构评估职责，不是由循环固定绑定的 Agent 类型。CBIM AI 助理负责选择流程、拆分与协调；每个执行任务绑定一个 Agent 与一个或多个由该 Agent 维护的模块，执行者在已确定的工作区内完成分配的分析、实现或验证工作。任务内跨模块结论由AI 成员 提供，跨任务结论由 CBIM AI 助理汇总。

执行职责分为两层：**Feature Agent 对应业务人员**，负责在现有约定内完成具体任务；**Refactor Agent 对应架构师**，负责跨任务、跨模块的结构观察、抽象判断与演进方案。两者都覆盖程序、QA、美术、策划等工作，按需组合专业能力；正式架构变更仍由人类负责人批准。

## 三、贯穿全体系的取舍

| 设计取向 | 取舍依据 |
|---|---|
| 能力与业务独立 | 方法和项目事实分别维护，通过任务绑定 |
| 结构外化与按需理解 | 保存可定位、可核实的知识，不要求每轮理解整个项目 |
| 自然语言入口 | 业务发起者表达目标，系统和负责人承担技术定位 |
| 增量灵活、收敛受控 | 允许试错，公共契约和架构变化不静默发生 |
| 证据驱动 | 信号引导调查，实际产物与验证支持结论 |
| 人保留决策与理解 | 审批需要理解支撑，不能退化为确认 AI 自评 |
| 单一知识来源 | 正文各有维护位置，索引和其他资产通过引用关联 |
| 治理强度匹配影响 | 不以文档、审批或抽象数量衡量成熟度 |

这些取向的定义和边界由专项文档展开，具体落地由执行方案规定。

## 四、三个相连的闭环

| 闭环 | 结果 | 对下一轮工作的贡献 |
|---|---|---|
| 交付 | 受控实现、验证与业务验收 | 留下实际产物和事实证据 |
| 知识 | 核实、修正、沉淀共享知识 | 改善定位、复用与判断 |
| 演进 | 观察、决策、必要重构与正式抽象 | 改善长期结构和维护成本 |

人工认知贯穿三个闭环。CBIM 中可选的个人 M 可以辅助工作，但团队闭环依靠共享 C、B 和工程记录，不能依赖个人本地记忆。

闭环不要求每次任务产生新抽象。保留观察、暂缓或拒绝抽象也是有效结果，只要依据可以支持后续判断。

## 五、文档边界与阅读顺序

先读本总纲了解关系，再按问题阅读专项理论；制定任务、组织 review 或实施系统时阅读全流程方案。

- `02-CBIM架构设计理论.md` 维护 CBIM 理论，不保存完整任务包和操作流程。
- `03-渐进式架构演进与人工认知保障体系.md` 维护架构演进及认知保障理论，不重复审批表和执行参数。
- `04-AI-Native开发全流程设计方案.md` 维护职责、模板、资产、流程、恢复和验收，通过引用使用理论。

理论不因逻辑完整就等于实践成立，方案不因写入文件就等于能力部署成功。有效性以真实任务的定位质量、返工、知识失配、维护成本和人工接管表现检验。
