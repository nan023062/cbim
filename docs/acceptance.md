# 验收证据与交付边界

CBIM 是面向 AI 原生团队的生产与治理体系，CBIM Assistant 是其桌面入口（见 [产品说明](product-positioning.md)）。本文区分当前实现范围与历史验证记录；历史测试不能代替代码变更后的回归。

## 程序与启动

- 便携目录：`build/<北京时间 YYYYMMDD-HHmmss>/CBIM Assistant-win32-x64/`。
- 双击目录中的 `CBIM.exe`；不能只复制 EXE，须保留完整目录。
- 分发 ZIP 位于构建目录的 `make/zip/win32/x64/`，名称包含构建时间与版本。
- `build/latest-build.json` 记录最近成功构建的目录、EXE 与 ZIP 路径；时间目录内的 `build-info.json` 用 `stage` 区分 package 和 make。
- 首次打开业务工程时初始化缺失的 `.cbim/`，不覆盖已有团队知识，不修改项目的 AI 工具配置。
- 运行记录默认位于用户主目录 `.cbim/`，不放入业务工程；应用启动加载所有已登记工作区，关闭页面不停止运行。

## 验证命令与证据

```powershell
pnpm typecheck
pnpm check:architecture
pnpm test
pnpm make
pnpm test:desktop
pnpm test:portable
pnpm test:loop
```

测试结果与截图保存在本机 `test-results/`，不纳入版本控制。各脚本验证范围以当前代码为准；真实 Pi 测试使用隔离的本机确定性模型服务时，不能据此声称实际供应商模型质量已验证。

[2026-11-06 构建测试报告](build-test-20261106-181923.md) 记录该次构建、测试数量和实际产物。该报告属于历史证据，不保证之后的代码修改已经通过同一检查。

此前 Windows x64 测试已实际覆盖知识初始化、Schema 加载、路径别名、跨进程锁、登记并发、缓存损坏、同名工程隔离、知识版本冲突、幂等提交、引用移动、删除保护、事务回滚与恢复。崩溃测试在第一份文件写入后终止真实子进程，再次打开时检查恢复、锁接管与新运行实例身份。

便携测试复制产物到工程之外，以隔离用户数据运行，PATH 中不含 Node/Python。这不是全新 Windows 虚拟机安装测试。桌面脚本通过 preload 初始化隔离项目，再通过真实页面验证相应交互；没有自动操作系统文件夹选择对话框。

## 当前实现范围

- Electron/React 桌面、多工作区独立知识库与运行生命周期、资源仓库、模型供应商配置。
- 主 Agent 普通对话、真实 Pi 执行、原生文件与命令工具、附件、模型选择、运行内审批与排队消息。
- 内置 Skill 与规范查询、Module/Agent/Skill/Workflow 对象查询与受控 CRUD、结构校验、预览、版本检查、多文件事务及恢复。
- 当前会话任务内计划、步骤、实际工具证据与待审阅交付候选；运行完成不等于业务验收通过。
- 动态成员实例登记、业务任务派发记录、可靠待处理消息、增量事件和持久化恢复，见 [派发契约](agent-dispatch-contract.md)。
- 主 session 的真实实例与图根统一。主 Agent 负责团队和技术管理、任务调度、受控知识治理，并按本轮权限直接执行未配置自定义岗位的模块。已配置自定义岗位的执行者按任务独立实例化；周期结束释放执行者并保留历史。知识写入和主会话业务写都验证 read/ask/execute，只读时拒绝写入与命令，见[成员执行](member-execution.md)。
- 应用级成员、任务压力与用量聚合的后端及 IPC，见 [全局运行管理](global-runtime-management.md)。

## 尚未实现或未验证

- 通用历史邮箱自动消费、执行者主动求助与可恢复等待、异常通道核实及重试/改派、全局运行监控界面。成员递归派发不属于现设计目标。
- 自动业务验收、完整治理待办与人工责任路由、自动限流或预算控制。
- 架构语义、自然语言 scope、业务运行正确性仍需团队 review；结构校验通过不能替代这些判断。
- 旧 Python 专用工具并非全部迁移，见 [规则迁移](rule-migration.md)。应用运行时不调用 Python，历史脚本保留作对照。
- 跨物理磁盘写入、不同 Windows 账户竞争同一工程、全新系统安装尚未完整实测；macOS/Linux 构建、安装器、自动更新和代码签名未交付。
- 工作区共享 Electron 主进程；主进程崩溃影响所有工作区，不具备进程级故障隔离。
- 多文件写入不是操作系统级原子事务；外部程序可能看到中间状态，且不遵守工程锁的外部编辑仍存在极短竞争窗口。
- 当前用户目录权限和工具路径检查不是操作系统沙箱；同用户恶意进程不在隔离保证之内。
- `.cbim.local/` 只检测并提示迁移，不自动迁移或删除历史；未完成大规模性能基准和完整无障碍回归。

架构、初始化、权限与存储详见 [实现架构](assistant-architecture.md) 和 [内部 Loop](loop-engine.md)。
