# 工作区界面

参考 Cindy 的中性背景、紧凑侧栏、细分隔线、轻量图标与底部对话输入区。默认深色，侧栏底部可切换浅色。此界面承载面向 AI 原生团队的生产与治理体系，左侧对象为项目工作区；核心定位见 [产品说明](product-positioning.md)。

## 界面目标与责任

界面应让任何职业的参与者从业务目标进入工作，借助 AI 完成方案、实现、验证和迭代，并让结果判断与人的责任保持清晰。**开放实现能力，守住系统底线**，意味着创作入口要易用，执行约束、验证结果与需要判断的问题也要能够被理解和追踪。

核心治理者与创作执行者使用同一工作区，可在不同任务中承担不同责任。界面不按程序、策划、美术、QA 划分互不相通的执行入口，也不把两类责任解释为已经实现的账户角色或权限等级。

| 使用场景 | 界面设计应支持的工作 |
|---|---|
| 创作与执行 | 表达目标，理解约束，调用所需能力，查看成果与验证依据，判断是否达成目标 |
| 核心治理 | 查看有证据的系统问题与例外，判断影响，维护框架、专业规则和流程，并让治理结果支持后续任务 |

这些是产品设计目标。当前界面已接入主 Agent 调度对话、成员独立执行及结果回传；主动发起成员聊天、完整业务验收与治理闭环仍未接通，不能把过程展示当作这些能力已经完成。

## 导航与页签

左侧上方固定「新建工作区」「链接器」「人才市场」「业务模版」，下方列出所有登记工作区，提供名称/路径搜索与运行状态。新建工作区选择已有项目目录，沿用人工打开和知识初始化流程。

CBIM 启动后加载全部登记工作区的知识与执行上下文，无须先选择页面。点击已有工作区直接进入；重复打开不更换实例。路径失效或启动失败单独显示并可重试。关闭工作区页面仅取消选择，不停止运行；再次选择立即进入。移除登记会停止对应运行，退出应用统一释放所有工作区。

CBIM 管理的团队是由多工种组成的复合大型团队。自动化属于工作区内的团队操作，只读取所选工作区的 Workflow，不提供跨工作区自动化。切换视图保留本机草稿和扩展页签布局。

侧栏工作区下列出各个主 Agent 会话，工作区右侧提供新建对话与更多操作。中间完整保留给当前会话，包含「对话」「任务视图」两个主区域。任务视图只读取本会话的任务与进度，不混入其他会话或整个项目的维护任务。

右侧扩展区域可展开和收起，默认没有页签。新建空页签可选择浏览器、终端、团队架构或业务架构；这些视图属于工作区，不包含当前会话的任务视图。扩展列表、顺序、名称、选择和草稿按工作区身份保存在本机界面存储，运行消息与证据则从后端日志恢复；界面状态不写入正式知识，也不自动同步其他电脑。

## 四类视图在生产与治理中的作用

| 页签 | 产品职责与后续设计方向 |
|---|---|
| 对话 | 以自然语言表达目标，逐步明确约束、成果负责人和验证方式，承载方案、实现与反馈交流 |
| 任务流程 | 预览当前任务流程实时图，让人理解执行进度、验证依据、阻塞原因和需要决策的环节；自动化程度由任务条件决定 |
| 团队组织架构 | 预览团队能力架构，帮助理解成员及可调用能力，支持按责任与能力组织任务；不能将能力归属直接解释为行政汇报关系 |
| 团队知识图 | 预览项目业务架构，帮助理解模块、契约与依赖，为发现重复实现、职责冲突及依赖恶化提供依据；自动问题识别仍待建设 |

### 当前实现

| 页签 | 当前实现 |
|---|---|
| 对话 | 默认内置主 Agent 普通对话、模型选择、真实发送、文本增量与工具证据、停止与继续，以及按工作区恢复历史；无需选择模块、Agent、Workflow 或填写验收表单 |
| 任务视图 | 默认显示当前主会话的节点流程图；按周期突出相关成员/模块/目标节点，保留全部历史关系。节点详情展示成员执行，根详情展示本轮目标、验收条件、分工、审阅与主会话记录 |
| 团队组织架构 | 工作区共享的静态 Team/分组/Agent 定义图；自定义 Agent 和 Skill 增删改查、父链 Skill 展示；发布或使用完整团队、单个 Agent、单个 Skill；主/默认/自定义 Agent 节点可只读查看独立 Session 历史 |
| 团队知识图 | 工作区共享的静态领域工程/模块定义图；模块及自身 Workflow 增删改查，维护真人和源目录；发布或使用完整业务架构 |

知识管理提供正文查看、编辑、预览提交、移动/删除影响和规则检查。工作区诊断展示知识问题、位置与数量；结构错误不等同于运行实例失活。工作区操作提供关闭页面、重新定位和移除登记，不提供服务重启入口。

工作区内自动化页展示本工作区的 Workflow 定义，尚无定时执行。视图只接收当前工作区身份及其知识快照，不接收全部工作区集合。全局资源入口共用随账号状态选择的本地或服务器仓库。架构图表示包含和能力归属，不自动推断业务依赖、汇报关系或调度职责。

## 生产与治理循环中的交互（设计方向）

界面应贯通 **创作与实现 → 验证与反馈 → 发现系统问题 → 核心治理 → 更新框架与规则 → 支撑下一轮创作**，让任务成果与长期治理相互衔接。

执行者需要看清本次目标、执行范围、结果与验证证据。核心治理者需要从证据进入系统问题，处理规则覆盖不到的例外与高影响决定。确认后的治理成果应能回溯到相应问题，并成为后续任务的约束或可复用能力，而不是只停留在一次对话中。

程序确定性校验、业务结果判断和架构判断应清楚区分：结构校验通过不代表业务目标达成，图谱可展示不代表依赖健康，任务结束也不代表治理完成。当前知识检查、工具任务记录和预览提交只覆盖其中部分环节，完整问题汇集、责任路由和治理反馈交互尚未实现。

自动化入口始终在工作区内部。后续执行交互需要说明任务是否具备明确目标、充分约束与可验证结果，并清楚呈现何时需要人的判断；当前页面仅展示 Workflow 定义，不能将其描述为已经可以自主运行。

## 全局可复用资源

链接器、人才市场、业务模板是同一个资源仓库的分类视图，共用唯一的本地目录或远端服务器配置。「设置」放在左下角用户栏的弹出菜单中，不放在侧栏上方导航。点击用户栏向上展开菜单，选择「设置」进入统一设置页；点击外部、按 Escape 或焦点离开可收起菜单，支持方向键选择。用户栏目前显示「本地用户 / 本地模式」，账号登录尚未接入。

设置页按登录状态展示仓库来源：未登录时可保存本地目录，并显式启停本地共享服务；服务器区域显示「登录后自动连接」占位，不再提供本地/远端选择按钮、服务器地址或连接令牌输入框。账号接入后由登录状态统一切换三类资源的来源，已登录时不提供本地目录编辑；服务器不可用时不能显示为本地模式。三个资源页只显示当前来源、资源列表与「前往设置」入口。当前账号登录尚未接入，用户栏显示「本地用户 / 未登录」，退出登录仍为禁用占位。

用户菜单底部保留禁用的「退出登录」，不执行退出、清理本地数据或关闭应用；键盘导航跳过此占位。用户栏及菜单尺寸参考 Cindy 公开源码的 [UserInfoSection](https://github.com/makecindy/cindy/blob/main/apps/desktop/src/frontend/components/sidebar/UserInfoSection.tsx) 与 [dropdown-menu](https://github.com/makecindy/cindy/blob/main/apps/desktop/src/frontend/components/ui/dropdown-menu.tsx)：用户栏高 40px、头像 27px、内容间距 10px；菜单与用户触发按钮左对齐，向上间隔 8px，最小宽度 190px，面板内边距 4px，行内边距为纵向 6px、横向 8px。公开源码版本不保证与用户安装版本逐像素相同。

| 入口 | 可定制类型 | 定位 |
|---|---|---|
| 链接器 | 链接器定义 | 与外部工具打通的桥梁 |
| 人才市场 | 完整 Team、专项 Agent、单个 Skill | 与业务项目解耦的静态角色和方法 |
| 业务模版 | 完整业务架构（含全部模块与 Workflow） | 作为一个整体发布、预览和应用；不单独应用模块或 Workflow |

第一版由运行 CBIM 的电脑管理手选文件夹，支持资源定义的创建、编辑、复制、搜索和删除，并可手动开启本地共享服务。账号服务未来接入后自动连接对应服务器仓库，仓库之间不自动搬迁或合并数据。操作与接口说明见 [资源仓库](resource-repositories.md)。

这些入口用于将专业经验沉淀为可复用工具连接、能力和业务方法，供具体工作区采用。CBIM 没有自有中心服务器，不能把全局入口呈现为已有官方云端资源市场；共享资源也不意味着可以跨工作区执行自动化。

旧版若已创建 `<用户主目录>/.cbim/resource-library.json`，本版不会自动读取、迁移或删除该文件。已接通静态资源包的发布、预览和应用；在线账号市场、插件安装执行仍未接入。旧自由文本和单模块/Workflow 资源保留浏览编辑，不作为可应用的完整业务模板。

## 静态架构编辑与复用

团队图从 Team 根创建自定义 Agent、共享 Skill，也可在已有分组或 Agent 上维护能力。Agent 是叶子，Skill 沿父链累积；查看继承 Skill 时跳到原归属节点编辑。内置主 Agent 由应用维护，不可删除。业务图可创建领域工程、子模块和本模块专属 Workflow；模块编辑须选择真人维护人并明确确认，需要新增花名册条目时与模块一起提交。

所有编辑先校验并预览，确认后才写正式知识。编辑期间冻结知识版本，后台更新不覆盖草稿；过期预览或实例变更会拒绝提交。级联删除必须勾选，范围仅为知识定义和正文，业务源码保留。

人才资源可将完整团队作为子组加入，或明确整体替换当前 Team；单 Agent/Skill 采用新增，不覆盖同名定义。业务模板始终包含完整业务树，目标已有架构时须明确选择整体替换。预览显示新增、修改、删除及结构检查，确认后通过知识事务更新索引。发布时清除源项目真人、维护关系、连接器与源码定位；目标项目需重新绑定维护人和源目录。正文仍需人工 review，结构检查不代替跨项目适用性判断。

一个工作区只有一份静态团队和业务架构；多个主会话共用它们。每个主会话自己的任务图则由调度管理器生成，节点关联成员实例、任务目标与目标模块。编辑或导入静态定义不创建实例、不改写其他会话任务；执行上下文和知识版本复核由调度层负责。

选择团队中的 Agent 节点后点击「执行历史」，依次选择 Session 和运行轮次即可查看公开记录；团队页顶部「历史角色」可找到已删除定义的角色，不将其恢复为树节点。历史页只在打开、手动刷新或加载更多时读取，不实时轮询；它不包含聊天发送、成员启动、恢复或审批操作。主角色的多个 Session、默认与自定义角色的多个任务通道各自保留，不合并上下文；执行实例释放后仍可查询。详见 [Agent 的 Session 执行历史](agent-session-history.md)。

## 产品体验的成功标准

以更多人能够自主创造、更多成果能够持续交付，同时项目复杂度和治理成本可控为目标。后续体验评估应关注参与者能否理解目标与约束、完成成果判断，治理者能否依据证据处理例外，以及治理成果是否减少后续返工和人工负担。以下桌面测试验证当前交互行为，不代表上述长期产品目标已获验证。

## 当前交互验证

桌面测试使用打包后的 EXE、临时项目及隔离用户数据目录。`pnpm test:desktop` 验证扩展视图，其他 `scripts/*-smoke.mjs` 分别覆盖对话、队列、权限、侧栏与任务记录；各脚本范围以代码为准。截图及结果保存在 `test-results/`；历史运行记录见 [构建测试报告](build-test-20261106-181923.md)，不代表后续变更已经重新验证。

`pnpm test:architecture-ui` 验证真实表单创建、预览取消、四类静态包发布/跨项目导入、全局资源选择目标、窄侧栏暗/亮布局，以及源会话任务图和目标运行状态隔离。该测试不调用付费模型，不把静态资源应用当作一次成员执行验证。

自动化作用域测试在两个工程内写入不同的 Workflow，分别进入工作区内「自动化」，检查只显示自身定义；全局侧栏以及未选择工作区时均没有自动化入口。

默认构建输出到 `build/YYYYMMDD-HHmmss/`，使用北京时间命名，最新路径记录在 `build/latest-build.json`。可以用 `CBIM_BUILD_OUT` 覆盖输出位置，或用 `CBIM_TEST_EXE` 指定测试程序。新构建不覆盖其他时间目录中正在运行的实例。


## 对话与工作区状态

侧栏显示工作区运行状态及知识问题提示。知识诊断按当前位置和错误内容帮助维护者处理正式知识，不以网络连接、流量或调用日志代替知识健康状况。全局成员与任务监控目前仅有后端与 IPC，尚未提供独立界面。

对话顶部状态区分主大脑活动与总体任务：主运行期间显示生成、思考、工具执行和等待确认；主轮结束但周期仍活动时显示等待成员或审阅，不能直接显示整体完成。旁边保留用时和平均输出速度。输入区运行时仍可调整附件、权限和模型，提示下次发送生效；等待成员期间新消息继续排队，停止入口仍作用于当前整个周期。只有主大脑正在运行时可插入当前大脑，否则只调整待执行队列。底部显示消费与上下文占用，缺失价格或容量时明确未知。

对话输入布局参考 Cindy：居中内容列、右侧用户气泡、左侧助手正文，工作过程折叠；一体式圆角输入框左下为上下文加号与权限，右下为模型及发送/停止。审批中的“本次任务全部通过”仅对当前运行生效，不改变后续运行或其他成员的权限。附件与移植范围详见 [移植说明](cindy-chat-port.md)。

主对话在主 Agent 原有流式回复之外，用独立署名卡片展示最近三项成员任务的公开输出与工具状态；“查看任务详情”定位任务图节点。图只消费当前主对话 `taskId` 对应的派发记录，图与成员事件按游标增量读取，后台页签降频。详情中的审批、选项回答和停止只作用于该成员任务，打开节点不自动授权。切换图与对话保留输入草稿、队列和节点选择。交付候选尚未业务验收；查看成员结果不等于已让主 Agent 自动消费或派发后续工作。

对话目标摘要和任务图根共用同一份只读投影。可选择历史周期查看原始需求、计划版本、角色/模块分配、验收项、证据引用、缺口及关闭结果；历史选择不会改变当前运行或消息目的地。任务图保留整个会话，选中周期只突出相关节点。旧记录无目标时明确说明，不从首轮会话标题猜填。

目标变化采用独立于任务图的增量游标，摘要无变化时不重传，完整原文和计划仅在选中目标详情版本改变时返回。保存审阅不推进任务图游标；阻塞或关闭即使目标版本未变也会刷新详情。主模型的 `complete` 审阅显示“完成申请待复核”，可靠关闭后才显示“目标已完成”；人工验收仍未接通，不把查看或模型自评当作真人接受。

只有后端提交安全 `waiting` 检查点后，界面才显示“等待补充，执行已暂停”；模型的 `awaiting_user` 审阅尚不代表已经停泊。等待没有生成动画，不累计模型工作时间；停止入口仍可用，普通输入只进入后续任务队列，不能插入大脑或通过继续队列解除等待。退出和重启保留目标及等待原因，历史选择不改变当前开放目标。

当前等待目标卡提供“补充并继续”，对话卡和任务根共享同一草稿及提交锁；只接受文本，模型与权限按提交时的明确选择冻结，聊天草稿和附件不动。本地先保存稳定请求再发送。通信结果未知时保留原请求，只能查询或同 ID 重试；重开查询不自动发送，历史周期只读。受理不等于正在执行或业务验收，补充后要求主 Agent 重新规划；正式人工验收入口尚未接入。原队列仍暂停，目标结束后可显式继续。
## 成员执行记录核实

任务视图仍默认显示当前主会话的任务节点图。点击成员节点，在执行轮次选择下方使用“核实执行记录”；此操作重新读取派发事实、指定轮次的持久日志和工具回执，不调用模型、不确认结果信封、不恢复执行。

报告分别显示未领取、在途、已结算或结果未知，以及证据基线和读取时间。日志缺失、损坏或未完整尾行均保留为问题；失败和取消不代表回滚，工具失败也可能已修改文件。工具记录按同一核实基线分页，基线改变则重新显示第一页。候选只属于所选轮次，始终注明尚未验收。

核实仅由点击或手动刷新触发，节点常规流式刷新不反复读取报告。图或目标周期变化时提示旧报告已过期；切换节点/轮次后忽略旧请求的迟到结果。该入口不提供自动重放、改派或旧实例复活，后续恢复使用独立流程。

报告对应已关闭周期、没有新的开放目标且版本仍有效时，可明确“新建只读核实任务”。表单分别填写用户观察和新的核实目标，模型按当前选择冻结，权限固定只读。仅查看、展开或刷新不会执行；提交会创建同一主会话下的新周期和新执行实例，旧节点保留。未选已有运行不能绕过日志核实；从未登记运行的任务可明确不带 runId。

表单先保存完整稳定请求再发送；通信结果未知只查询原回执或按原 ID 重试。重新打开页面不自动发送，切换节点不会串用草稿或迟到回执。接受后可查看新目标，但受理不等于模型已启动或业务验收；原对话草稿、附件及排队消息不被清空，原队列仍暂停。

主对话将无法核实的历史日志显示为只读问题，不造一条“执行失败”摘要。可续聊轮次由后端核实当前上下文，不能过滤坏记录后选一条较早正常日志。旧记录可以继续展示，新核实周期自己的记录有缺口时仍禁止续跑。
