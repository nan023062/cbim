# 工作区界面

参考 Cindy 的中性背景、紧凑侧栏、细分隔线、轻量图标与底部对话输入区。默认深色，侧栏底部可切换浅色。此界面承载面向 AI 原生团队的生产与治理体系，左侧对象为项目工作区；核心定位见 [产品说明](product-positioning.md)。

## 界面目标与责任

界面应让任何职业的参与者从业务目标进入工作，借助 AI 完成方案、实现、验证和迭代，并让结果判断与人的责任保持清晰。**开放实现能力，守住系统底线**，意味着创作入口要易用，执行约束、验证结果与需要判断的问题也要能够被理解和追踪。

核心治理者与创作执行者使用同一工作区，可在不同任务中承担不同责任。界面不按程序、策划、美术、QA 划分互不相通的执行入口，也不把两类责任解释为已经实现的账户角色或权限等级。

| 使用场景 | 界面设计应支持的工作 |
|---|---|
| 创作与执行 | 表达目标，理解约束，调用所需能力，查看成果与验证依据，判断是否达成目标 |
| 核心治理 | 查看有证据的系统问题与例外，判断影响，维护框架、专业规则和流程，并让治理结果支持后续任务 |

这些是产品设计目标。当前界面已实现的内容在下文单独列出；尚未接入的模型、自动执行和治理功能不展示为已完成能力。

## 导航与页签

左侧上方固定「新建工作区」「链接器」「人才市场」「业务模版」，下方列出所有登记工作区，提供名称/路径搜索与运行状态。新建工作区选择已有项目目录，沿用人工打开和知识初始化流程。

点击已有工作区即发起打开，不需要二次点击「打开工作区」。已运行的工作区只切换视图；打开中显示加载状态并合并重复点击。路径失效时提供重新定位，打开失败时提供重试。主动关闭后不会因为仍处于选中状态而自动重开，再点击左侧项目才重新打开。

CBIM 管理的团队是由多工种组成的复合大型团队。自动化属于工作区内的团队操作，不提供跨工作区自动化。选中工作区后，内部功能栏提供「协作视图」「自动化」；自动化只读取所选工作区的 Workflow，未打开工作区时提示先打开。切换内部功能保留页签和未提交编辑。

每个工作区首次进入时有一个对话页签。顶部加号可以添加对话、任务流程、团队组织架构、团队知识图，同类视图可添加多次。拖动页签调整顺序，双击重命名，右侧叉号关闭。键盘左右方向键切换、Home/End 定位首尾、Alt + 左右方向键排序。

页签列表、顺序、名称、活动页签和对话草稿按工作区身份存入 Electron 的本机 localStorage，重启可恢复，实际位于用户级 `desktop/` 数据目录。它们是本机界面状态，不写入正式知识，不同步其他电脑。关闭页签会删除该页签草稿；移除工作区登记不自动清除此本机布局记录。知识编辑仍通过已有版本校验与事务预览提交，切换工作区或关闭有编辑的页签时提示未提交内容。

## 四类视图在生产与治理中的作用

| 页签 | 产品职责与后续设计方向 |
|---|---|
| 对话 | 以自然语言表达目标，逐步明确约束、成果负责人和验证方式，承载方案、实现与反馈交流 |
| 任务流程 | 预览当前任务流程实时图，让人理解执行进度、验证依据、阻塞原因和需要决策的环节；自动化程度由任务条件决定 |
| 团队组织架构 | 预览团队能力架构，帮助理解成员及可调用能力，支持按责任与能力组织任务；不能将能力归属直接解释为行政汇报关系 |
| 团队知识图 | 预览项目业务架构，帮助理解模块、契约与依赖，为发现重复实现、职责冲突及依赖恶化提供依据；自动问题识别仍待建设 |

### 当前实现

| 页签 | 当前实现 |
|---|---|
| 对话 | 工作区上下文、独立草稿和架构视图快捷入口。模型未接入，发送按钮不可用，不生成模拟回复 |
| 任务流程 | 每 1.2 秒读取真实工具任务状态，显示提交、执行及人工 review 阶段，支持知识检查与取消。没有虚构内部步骤或 AI 调度流程 |
| 团队组织架构 | 按正式 Team 路径组织 AI 成员，显示能力及由规则层计算的 Skill 继承；支持搜索、折叠、文字缩放与成员详情 |
| 团队知识图 | 根据正式 children 构造模块关系，支持折叠、搜索定位、文字缩放和虚拟直属内容切换；展示 source、scope 和模块正文 |

知识图右上「知识管理」保留原有知识编辑、预览提交、移动/删除预览、校验、任务记录及 Agent 连接管理。工作区顶栏设置入口管理打开/关闭、重新定位、移除登记及启动恢复。

工作区内自动化页展示本工作区的 Workflow 定义，尚无定时执行。视图只接收当前工作区身份及其知识快照，不接收全部工作区集合。全局资源入口共用可切换的本地/远端仓库。未运行工作区不会为展示内容而自动打开。架构图表示包含和能力归属，不自动推断业务依赖、汇报关系或调度职责。

## 生产与治理循环中的交互（设计方向）

界面应贯通 **创作与实现 → 验证与反馈 → 发现系统问题 → 核心治理 → 更新框架与规则 → 支撑下一轮创作**，让任务成果与长期治理相互衔接。

执行者需要看清本次目标、执行范围、结果与验证证据。核心治理者需要从证据进入系统问题，处理规则覆盖不到的例外与高影响决定。确认后的治理成果应能回溯到相应问题，并成为后续任务的约束或可复用能力，而不是只停留在一次对话中。

程序确定性校验、业务结果判断和架构判断应清楚区分：结构校验通过不代表业务目标达成，图谱可展示不代表依赖健康，任务结束也不代表治理完成。当前知识检查、工具任务记录和预览提交只覆盖其中部分环节，完整问题汇集、责任路由和治理反馈交互尚未实现。

自动化入口始终在工作区内部。后续执行交互需要说明任务是否具备明确目标、充分约束与可验证结果，并清楚呈现何时需要人的判断；当前页面仅展示 Workflow 定义，不能将其描述为已经可以自主运行。

## 全局可复用资源

| 入口 | 可定制类型 | 定位 |
|---|---|---|
| 链接器 | 链接器定义 | 与外部工具打通的桥梁 |
| 人才市场 | 专项 Agent、能力 Skill | 多工种团队可复用的专业成员与方法 |
| 业务模版 | 业务架构、单一业务模块、Workflow | 可复用并进一步适配的业务结构与流程 |

第一版由运行 CBIM 的电脑管理手选文件夹，支持资源定义的创建、编辑、复制、搜索和删除。可手动开启本地仓库共享服务，也可在设置中切换到兼容的远端服务器。连接成功后才切换，仓库之间不自动搬迁或合并数据。操作与接口说明见 [资源仓库](resource-repositories.md)。

这些入口用于将专业经验沉淀为可复用工具连接、能力和业务方法，供具体工作区采用。CBIM 没有自有中心服务器，不能把全局入口呈现为已有官方云端资源市场；共享资源也不意味着可以跨工作区执行自动化。

旧版若已创建 `<用户主目录>/.cbim/resource-library.json`，本版不会自动读取、迁移或删除该文件。资源库中的内容仍是定义；在线市场、插件安装执行和模版一键应用尚未接入。工作区已有正式知识及其编辑功能按原流程使用；自动化仍局限在各工作区内部。

## 产品体验的成功标准

以更多人能够自主创造、更多成果能够持续交付，同时项目复杂度和治理成本可控为目标。后续体验评估应关注参与者能否理解目标与约束、完成成果判断，治理者能否依据证据处理例外，以及治理成果是否减少后续返工和人工负担。以下桌面测试验证当前交互行为，不代表上述长期产品目标已获验证。

## 当前交互验证

`pnpm test:desktop` 使用打包后的 EXE、两个临时项目及隔离用户数据目录。验证鼠标拖放、键盘排序、同类页签、工作区切换、重启布局与草稿恢复、真实团队/模块文件展示、任务完成状态、全局入口、主题切换以及关闭隔离。截图及结果保存在 `test-results/`。

自动化作用域测试在两个工程内写入不同的 Workflow，分别进入工作区内「自动化」，检查只显示自身定义；全局侧栏以及未选择工作区时均没有自动化入口。

默认构建输出到 `build/YYYYMMDD-HHmmss/`，使用北京时间命名，最新路径记录在 `build/latest-build.json`。可以用 `CBIM_BUILD_OUT` 覆盖输出位置，或用 `CBIM_TEST_EXE` 指定测试程序。新构建不覆盖其他时间目录中正在运行的实例。
