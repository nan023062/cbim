# 项目实例的生命周期

1. **登记目录。** `Catalog.Add` 识别项目路径，保存本机登记和项目身份。此时还没有运行中的 Office；侧栏可以通过 `Cache(id).history` 读取本机记录。
2. **首次打开。** `ProjectList.Open(id)` 查找登记项，加载组织树、业务树和共享包引用，再建立 `ProjectInstance`。同一列表内，并发打开同一项目共用一次加载。加载失败不会发布半初始化的实例，修复数据后可再次打开。
3. **恢复项目知识。** 两棵树分别优先读取项目根下的 `.cbim/cability/organization.json` 和 `.cbim/bussinss/business.json`。缺哪份就为哪份查找旧项目缓存；再缺才从旧项目定义初始化。首次导入组织时也恢复岗位设置。快照损坏会报错，不以旧值覆盖；迁入后只写项目目录。
4. **创建或恢复 Office。** `CreateOfficeRecord()` 先建立持久的主会话 ID；`OpenOffice(session)` 以此 ID 查找或创建运行实例。打开中的同一会话复用 Office。不同 Office 共享项目组织和业务定义，各自持有成员实例和任务。`ListOfficeRecords()` 列磁盘记录，`ListOffices()` 只列运行实例。
5. **关闭与重开。** 关闭 Office 后，它从活动列表移除，磁盘记录保留。项目实例关闭时拒绝再打开 Office，并等待已有 Office 关闭。应用关闭项目列表时，也会等待进行中的加载结束。下次启动重新加载项目，可用原主会话 ID 打开历史；不要把临时 Office ID 保存为恢复依据。

**存储边界。** 项目根的 `.cbim/` 随项目携带。会话历史、队列、工作记录、引擎运行目录和工作树属于本机项目缓存，调用方从 `ProjectCache` 取得。引擎和连接器的安装资产由本机资源管理器共享，不随 Office 关闭或随项目复制。新增旧版缓存兼容逻辑时，在 [ProjectCache](../../logic/projects/project-cache.ts) 定义路径，在对应加载器决定何时导入。

**任务授权。** 每次引擎运行由宿主签发绑定项目、Office、Agent 和运行 ID 的内存授权。普通文件限本任务工作目录（排除 .cbim），只读任务没有写目录。只有主 Agent 可使用项目资源工具，ask 模式仍须逐次批准。没有隔离执行器时，主 Agent 和岗位都不开放通用命令。取消或关闭运行后，工具入口失效。此机制约束受管工具，不构成对子进程的操作系统沙箱。
