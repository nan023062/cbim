### 去除重复项目根

业务架构去掉树上方工作区名加“项目根”的重复按钮，业务模块为唯一可见根，空项目的新建/模板等入口仍在根行菜单。内置projectRootModuleId语义、默认执行和数据结构不变。

### 文件树操作入口

业务模块菜单绑定本行真实模块：子模块、编辑/删除、治理、负责人记录和新建Workflow；业务根菜单负责新建工程模块、工作区责任记录与架构发布/模板导入。删除仍进入原ArchitectureEditor预览/确认。详情保留负责人选择、正文/源目录与Workflow编辑；打开菜单动作先保护未提交草稿。图标配title/aria-label，不用另一套提交或选中对象推断目标。

### 模块卡片一级负责人选择

`InlineModuleOwner` 在原模块卡片上选择即保存；列表由静态自定义 Agent、内置执行者与真实岗位组成，不含主 Agent。同一 Agent 多岗位在同一级区分，不猜选模型。已有岗位保留原配置；无岗位时使用模型设置中已选默认供应商/模型，自动生成登记说明，经原预览与提交登记后以真实 memberId 绑定。不填写额外描述，不进入二级页面；默认模型缺失明确报错，不伪造配置。

`inline-module-ownership.ts` 只编排既有命令，不提供新后端写通道。岗位与责任分别保存原请求和回执；任一步未知则停止后续，原地核实或重开只查询，不重放或自动继续绑定。读取失败不假报空列表；停用/退休岗位不隐式重建；源/实例变化仍由原门禁拒绝。可能部分成功的岗位保留，用户再次明确选择后可复用。模块行尾菜单打开原知识编辑器，删除仍经过影响预览与确认，不直接删文件。

### 项目根与渐进架构

业务架构仅显示业务模块树根，真实工程模块显示在它之下。空项目可以直接开发，创建模块是按需入口；根不打开真实模块编辑/删除或负责人表单，不生成虚假维护人。主会话 Auto/Team 的实际能力由后端决定，页面文案不授予执行权限。

# 工作区静态业务图

## 责任来源的明确采纳

负责人详情分别显示原定义观察和受控来源状态；旧缺省、退役、待核实不从同路径或同hash猜成当前有效。新增“预览采纳当前来源”使用原原因输入和独立 `adopt_source` 命令，要求保持原负责人；预览展示实际来源，确认后保留 bindingId/owner并增加责任版本。更换负责人仍使用原协议，不能借来源采纳夹带换人。原命令保存、未知查询和晚到响应隔离与责任变更共用。

`WorkspaceView` 展示唯一业务定义树，根为 Workspace，第一层为领域工程节点，下层为模块。模块详情显示自身正文、源目录、岗位负责人和自身 Workflow，不继承父模块 Workflow。

增删改操作委托共享 `ArchitectureEditor`，通过预览、校验和人工提交更新工作区知识，并显式刷新快照。资源发布/使用委托 `WorkspaceResourceTransfer`；业务模板始终是整套业务架构，不提供单独应用模块或 Workflow 的入口。

业务图不显示动态任务节点。多个主会话共用此静态定义；每个主会话自己的任务派发图由 tasks 目录展示，已派发的运行上下文仍由后端知识版本规则管理。

模块详情的“知识治理”打开独立 `ModuleGovernancePanel`，固定模块及工作区实例。登记保护、记录观察、精确提案、本机决定和独立实施都委托治理服务；普通编辑入口不能绕过后端知识事务门禁。知识提交后显式刷新静态图，不创建或改变会话任务图。

## 单模块负责人控制面

旧完整责任面板的岗位列表为空时，下拉框展示“从 Agent 登记新岗位”：选项取同工作区的静态团队快照，包含自定义 Agent 与内置执行者，不包含主 Agent。`BusinessArchitecture` 组合现有 `WorkspaceMembers`，传递真实工作区运行状态与所选 Agent；岗位与模型仍由用户明确填写、预览并保存。登记受理后返回原模块，重新读取岗位列表，只有新 memberId 仍存在且 active 才预选；不使用 Agent ID 代替岗位，不自动保存责任。取消返回原模块且不登记；登记结果未知时保留原命令核实界面，不自动返回或创建另一岗位。

空列表与读取失败分开呈现：只有完整列表成功读完才提示尚无／没有启用岗位，并开放 Agent 登记选项；读取失败保留核实错误与重试入口。再次选择模块或刷新不重复套用初始新岗位选择。负责人面板只调用上层注入的登记回调，不反向导入岗位管理视图；责任与岗位写入继续使用各自原控制器及后端版本门禁。

`ModuleOwnershipPanel` 由项目根的记录图标或所选模块的负责人记录进入，也供项目岗位反查当前负责的模块。负责人使用稳定 memberId，不关联真人花名册；一个模块只有一个关系头，解除保留关系和历史，重新设置沿原 bindingId 升版。正式派发和领取由调度系统核实，此界面不移交旧任务或创建执行。预览的关联任务统计包含该模块的真实新旧节点，不再笼统称为旧协议任务；它是影响范围而不是可以移交的资格。来源通过独立明确采纳更新，active 岗位不等于可执行。

列表按 ownershipCursor、岗位 registryCursor、knowledgeRevision 三项依据分页；来源无法读取不假报空架构。详情展示当前岗位、真实来源观察和近20条明确有界历史；main_agent 与 local_desktop 来源分开，不把主工具审批伪造成人工责任决定。元信息、当前来源差异每次显式核实，不周期回读。

`module-ownership-state` 严格核对原模块、前后岗位、版本、游标、预览依据和不可变回执。每工作区共享本机128条/2MiB命令记录；发送前保存，双击或另一个页面不能重复提交，未知冻结原请求。重开只查原命令，明确重送仍保持原ID和实例；结果已受理后本机保存失败保留事实、可查询修复，不当作回滚。读取记录损坏或达到容量上限时停止新写，不丢弃旧记录。

业务架构选择与岗位反查均固定工作区实例；异步代次隔离迟到列表/详情，表单编辑立即废弃旧预览。缺失模块仍可解除已有关系。关系修改与岗位退休的冲突由同一个后端 Store 裁决，前端不主动解除或替用户退休。

负责人表单将 OWNERSHIP_ALREADY_EXISTS 视为明确未受理，和 NO_CHANGE、BINDING_STALE 保持可恢复区分；其他未知错误仍保留原命令核实入口。

### 负责人快速登记选型

WorkspaceView 传递 Agent 本机 runtime。inline-module-ownership 新登记优先采用明确 Agent 引擎/模型，失效时拒绝；未设置才读取本机默认。复用已有 memberId 不重新采纳模型，不迁移原任务。

### 模块新岗位的引擎引用

inline-module-ownership 在新登记时同时传递 Agent runtime 的 engine、profileId、modelId，并通过 providerSupportsEngine 核实供应商接口及适用型号；未指定 runtime 时采用 Pi 与默认模型。已有岗位保留原采纳，不跟随静态 Agent 或主 Agent 的设置变更。

模块卡片岗位编排的 IPC action 限定为真实使用的模型列表及岗位/责任读取、预览和原命令操作；models.list 不转发任意参数，原两阶段提交和未知回执处理不变。

业务架构按实际知识目录/文件显示，可选择模块详情或文件预览编辑；移除高级知识管理和直属内容开关。未显式配置显示自动解析（父级、模型匹配、主 Agent），不伪装成已保存的主 Agent 责任；原显式预览/保存、岗位登记和历史入口仍保留。一键治理通过共享启动器发起真实工作流会话。


责任列表的普通入口只传工作区及分页字段；指定岗位反查时才附 memberId。回包核验沿原请求进行，不将可选字段混入另一个严格协议。
