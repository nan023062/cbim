# CBIM V1 架构

## 目标

CBIM（Capability–Business Independence + Memory）验证一个直接的假设：将可复用能力与项目业务知识分开，是否让 AI 编码工作更顺畅。上下文选择和知识组织可以提供帮助，但不保证上下文大小与项目规模无关，也不预设必须多 Agent 才能提效。

V1 使用 Claude Code 默认会话行为。Claude Code 可以根据明确的 Skill 描述自动命中 CBIM Skill，用户也可以显式调用；没有命中时走默认行为。CBIM 不提供额外分类器、不强制派发、不拦截普通请求。没有行为树、后台治理、生命周期回调或 MCP 服务。

## 三类基础机制

| 维度 | 内容 | 边界 |
|---|---|---|
| 能力 | Agent 定义、私有 Skill、资源文件、可移植专业方法 | 不写入项目专有事实；专业角色不是必经门禁 |
| 业务 | 模块 `.dna/module.md`、可选 contract、notes、workflows、模块注册表和知识图 | 描述当前业务结构与约束，不绑定某个 Agent 的执行协议 |
| 记忆 | 用户明确保存的事实、决策与经验，手动查询和整理 | 不主动捕获会话、召回、蒸馏、晋升或删除来源 |

`.dna/workflows/<name>/workflow.md` 是业务流程文档，不是自动运行的 Python 流程。创建和编辑文档不会自动执行其中的步骤。

## 调用结构

```text
用户
 ├─ 普通对话 → Claude Code 默认行为
 └─ 显式 CBIM Skill → 主会话执行方法
                       ├─ 按需读取源码、能力和业务知识
                       └─ 经授权的本地 CLI
                            → services / resources
                            → 数据原语、schema、路径校验、原子写
                            → 注册表、检索索引与业务图同步
```

CLI 是基础操作入口，不是调度器。主会话不必先调用架构师；用户也可以按需要选择专业 Agent。不存在固定 HR 分配链、强制机器回执、收敛重试或后台状态机。

## 代码分层

| 目录或文件（相对 `v1/kernel/`） | 职责 |
|---|---|
| `engine/cli/` | 显式命令、参数验证、结果和退出码 |
| `services/` | Agent、Skill、业务知识、记忆等公共操作与约束 |
| `cbi/resources/` | 资源对象；直接保存不等于经过所有 service 策略 |
| `cbi/_primitives/` | 文件和模块操作、注册表、元数据、业务图 |
| `memory/` | 记忆文件、后端、查询、统计和显式维护 |
| `engine/retrieval/` | 文本检索、可选向量接口、索引持久化和图查询 |
| `engine/audit/` | 用户主动检查；不承担强制验收 |
| `project/` | 显式初始化、同步、专业能力及原生 Skill 源资产 |
| `context.py`、`atomic_io.py` | 项目定位、共享原子写入 |

保留 service 的路径、名称、schema 和可执行资源校验。不应为了少一层调用，让 Skill 直接改写受控文件并遗漏注册表或索引更新。

## 三种 Skill 内容

1. **主会话入口**：`.claude/skills/<name>/SKILL.md`。设置 `user-invocable: true`，允许清晰匹配时自动命中，也允许用户显式调用；不设置 `disable-model-invocation` 或 `context: fork`。
2. **Agent 私有能力**：Agent 目录内的技能文件和 assets，可移植到其他项目。
3. **内置方法库**：Python 包中的 `SKILL` 文本，供显式查看与复用；本身不等于原生 slash Skill。

当前入口包括知识查询、代码查询、架构、开发和记忆治理。知识查询不隐含记忆召回；架构与开发不隐含保存记忆。

## 记忆和一致性

当前可写记忆 tier 为 `medium`。候选区、健康检查、重建工具和可选后端保留为显式维护能力；它们没有定时调用者。历史 `short` 数据不自动迁移或删除。

用户主动写入后更新注册表、索引与知识图，是该次操作的一致性维护，不是自动捕获。数据保存成功但衍生索引更新失败时，必须向调用者说明，不能静默等待后台修复。用户可以显式重建。

BM25 文本检索是已实现能力。retrieval 的 Local/OpenAI embedding 提供器目前为不可用占位实现；独立 Chroma 记忆后端不等于这两个提供器。保留可选接口不代表已经接通外部模型。

## 权限与安装

Skill 的调用不改变宿主权限。旧安装若拒绝本地命令，必须提示用户处理，不能修改 deny 或绕路执行。安装不应强制权限模式、修改全局 Claude 设置或启动服务。

显式升级可以清理明确归属 CBIM 的旧项目注册，但不能删除其他工具的 hooks/MCP 配置、用户权限、历史数据或系统任务。源码开发不自动升级宿主项目。

## 验证重点

- 普通会话没有 CBIM 自动触发入口。
- 原生 Skill 仅由用户调用并在主会话执行。
- 数据格式、路径和可执行资源检查仍有效。
- 业务与能力读取完整，记忆操作只在明确请求后进行。
- 安装与同步在隔离临时目录验证，保护用户配置和数据。
- 对比实验观察完成质量、耗时、用户介入和上下文开销，不再以旧调度树是否跑完作为成功指标。
