# V1 显式记忆

本文替代旧的自动捕获与后台治理蓝图。旧设计由 Git 历史保留，不再作为实现或运行指令。

## 使用边界

- 用户明确要求保存时才写入记忆。
- 用户明确要求查记忆时才读取相应范围；普通知识查询不隐含读取记忆或原始会话。
- 用户明确要求整理时才比较、去重或提出知识提取建议。
- 整理不自动授权删除来源、扫描全部宿主会话、修改 Agent 或发布业务知识。涉及覆盖、删除和跨资源变更时明确范围并遵守用户授权。
- 不记录普通 turn、工具调用或子 Agent 回执，不执行定时维护，不使用捕获队列驱动后台工作。

## 数据与接口

| 数据 | 用途 |
|---|---|
| `memory/medium/*.md` | 用户主动保存的条目 |
| `memory/candidates/` | 保留的显式整理候选工作区，不自动填充或消费 |
| `.dna/` | 业务知识，不是记忆日志 |
| `.claude/agents/` | 可复用能力，不是项目事实仓库 |

以上 memory 路径相对于项目 `.cbim/`。已有 short、incoming、processed、索引及治理记录不因升级被删除。

底层模块继续提供查询、枚举、读取、统计、受控写入、健康检查与重建。有效写入 tier 为 `medium`；V1 内部 schema 的版本号 2 不表示仓库 V2。

使用 `/cbim-memory` 指明保存、查询或整理及其范围。该 Skill 在主会话执行，使用本地基础操作而非后台服务。宿主权限拒绝操作时报告限制，不改变权限或采用另一条路径访问相同受限数据。

## 索引与后端

显式写入会维护相应后端与外部检索索引，这是用户操作的一致性要求。文件已保存但索引失败时需明确警告，让用户决定是否重建，不等待后台自动修复。

默认文件后端历史上按修改时间返回条目，不应把该排序宣传为语义相关性。需要文本相关性时使用实际文本查询能力或保留的 BM25 检索。独立 Chroma backend 是可选实现；retrieval 中 Local/OpenAI embedding 提供器是尚未接通的占位接口。

搜索不会自动抓取未索引的宿主会话。保留 transcript source 的数据结构不意味着允许主动读入会话。

## 手动整理

1. 确认用户选定的条目或目录范围，先读取原文。
2. 区分事实、决策、经验和过时内容，保留来源，不臆造缺失结论。
3. 给出合并或提取方案，明确将修改哪些文件。
4. 按已授权范围执行受控操作，分别报告保存、删除和索引结果。
5. 不因完成任务、重复犯错或容量阈值而自行开启下一轮整理。

`identifier` 的旧自动识别占位入口已不需要。保留的 compactor 不应被称为已经实现的 medium 自动合并器；候选管理、健康检查和重建是独立能力。

## 回归保障

测试应覆盖：无效参数不留下文件、读写删除不越界、显式查询不捕获新数据、索引失败有反馈、旧数据不会被初始化或同步删除。涉及真实 Claude 会话或可选后端的集成测试必须单独说明是否执行。
