从安装到第一轮协作

  1. 安装桌面应用

    下载 Windows x64 安装包，核对来源后按安装向导完成安装。在开始菜单搜索「CBIM Assistant」即可启动。

  2. 配置你的模型服务

    在设置中配置可用的模型服务与相应凭据。首次使用所选 Agent 引擎时自动下载独立运行包，请保持联网；模型用量与费用取决于服务商。

  3. 建立本地工作区

    选择一个项目目录，整理团队角色和项目知识；在对话中提出明确目标、约束和验收要求。

  4. 准备好后，点击更新图标

    悬停侧栏底部图标查看当前版本、可更新版本和准备进度。圆环满格并呼吸闪烁后，点击才升级。旧版迁移到本版仍需一次安装；后续兼容业务更新只替换资源并短重启。

Before you begin

开始使用前，你可能想了解

这个版本包含官网上的新图标吗？

已经包含。当前 v{{version}} 继续在窗口、欢迎页、应用程序和安装器使用统一品牌图标；侧栏用“团队空间”文字标题，已完成真实安装与升级验收。

软件会自动下载安装更新吗？

当前版本每分钟检查，后台下载并校验兼容的资源包或更高冷版本。图标显示就绪后由你点击，程序才停止任务并升级；资源更新短重启，冷更运行安装器。普通退出不会升级。旧客户端迁移到本版仍按各自旧流程执行；检查更新不需要 GitHub 登录。

关闭应用后自动化还会执行吗？

当前自动化依赖 CBIM 正在运行且对应工作区打开。错过的时刻不补跑，同一项任务不重叠执行。需要审批或补充时，请从运行历史打开对应会话处理；执行结束仍需按业务标准验收。

怎样选择 Claude Code 或 Codex？

三种引擎可选，首次使用时按需下载独立运行包，无需在供应商中配置引擎。供应商只维护连接和模型；Pi 支持现有三种协议，Claude Code 支持 Anthropic Messages，Codex 支持 OpenAI Responses，模型菜单按协议兼容性筛选。对话栏设置的就是主 Agent，与团队页面的主 Agent 配置同步。模型用量按所选服务商计费，不读取其他客户端的账号。

在哪里反馈 BUG 或提出需求？

在软件对话窗的「+」菜单选择「BUG 反馈」或「需求许愿」，用一句话描述问题或愿望，其余信息自愿补充。首次需在设置中连接自己的 GitHub 账号，随后直接创建 Issue；后续修复与功能变化统一查看更新日志。提交到公开仓库的内容公开可见，请勿填写密钥或私人资料。

我的项目与对话数据会放在哪里？

工作区以本地项目目录组织。使用模型服务、插件或 GitHub 反馈时，相关上下文会按所选服务的调用发送；这不是完全离线的应用。本站不要求登录、不收集反馈内容，也没有嵌入统计脚本。下载文件与项目文档由 GitHub 提供。

旧的 v1.x 也是这个桌面应用吗？

不是。GitHub 仓库中的旧 v1.x 属于早期 Python 内核通道。请使用本页链接或名称以 desktop-v 开头的桌面发布，避免误下载旧产物。

为什么 Windows 会提示未知发布者？

当前公开安装包没有可信代码签名。签名发布流程已经接入，实际签名版仍等待证书配置与验证。本页不会把未签名的现有文件标成签名版，也不建议关闭系统安全功能。
